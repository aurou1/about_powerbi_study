# ch01 复杂度分析与开场

> 学习目标：搞懂「大 O」到底在说什么；会用 `timeit` 实测算法快慢；背下一张复杂度速查表，以后看任何算法先问「它是几阶的」。

## 为什么要先学复杂度

前两套教程里你已经见过：一个 SQL 忘了 `status` 过滤，销售额虚高 47%；一个 JOIN 把客单价放大 3 倍。**数据结构和算法解决的是另一类问题：当数据量从 100 行涨到 1000 万行，你的程序会不会慢到不能用。**

复杂度就是回答这个问题的一把尺：**输入变大 N 倍时，耗时/内存大约变大多少。**

## 一、大 O 是什么

大 O 记号 `O(f(n))` 表示：当数据规模 `n` 很大时，算法的**最坏情况耗时**和 `f(n)` 成正比（忽略常数倍和低阶项）。

```python
# O(1)：无论 n 多大，都只做固定几步
def get_first(a):
    return a[0]          # 1 步

# O(n)：n 多大就走 n 步
def find_max(a):
    m = a[0]
    for x in a:         # 走 n 步
        if x > m: m = x
    return m

# O(n^2)：两层循环
def bubble_hint(a):
    n = len(a)
    for i in range(n):       # 外层 n
        for j in range(n):   # 内层 n  -> 共 n*n 步
            pass
```

**关键认知**：
- 大 O 砍掉常数。O(2n) 写成 O(n)，O(100n) 也写成 O(n)。因为 n 足够大时，常数不重要。
- 大 O 看**最坏**和**主导项**。`O(n² + n)` 直接写 `O(n²)`——平方项碾压线性项。
- `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`，从快到慢。

## 二、亲手实测：别只听我说

理论容易懵，直接跑。下面测同一件事的两种写法：**在列表尾部加元素 vs 在列表头部加元素**。

```python
import timeit

def tail_insert(n):
    a = []
    for i in range(n):
        a.append(i)          # O(1) 尾插

def head_insert(n):
    a = []
    for i in range(n):
        a.insert(0, i)       # O(n) 头插（后面元素全要后移）

for n in [1000, 4000, 16000, 64000]:
    t1 = timeit.timeit(lambda: tail_insert(n), number=200)
    t2 = timeit.timeit(lambda: head_insert(n), number=50)
    print(f"n={n:6d}  尾插x200={t1:.4f}s  头插x50={t2:.4f}s")
```

**预期输出：**

```text
n=  1000  尾插x200=0.0099s  头插x50=0.0116s
n=  4000  尾插x200=0.0297s  头插x50=0.1857s
n= 16000  尾插x200=0.1050s  头插x50=2.6414s
n= 64000  尾插x200=0.4983s  头插x50=40.7331s
```

> 看倍数：n 从 1000 涨到 64000（64 倍），尾插只慢了约 50 倍（接近线性），头插却慢了约 3500 倍（接近平方）。**这就是 O(n) 和 O(1) 的差别，跑出来比画图直观。**
> 不同机器秒数不同，但「倍数关系」一致，看倍数别看绝对值。

## 三、各阶随 n 增长长什么样

```python
for n in [10, 100, 1000]:
    print(f"n={n:4d}: O(1)={1}  O(log n)={int(n.bit_length())}  "
          f"O(n)={n}  O(n log n)={int(n*n.bit_length())}  O(n^2)={n*n}")
```

**预期输出：**

```text
n=  10: O(1)=1  O(log n)=4  O(n)=10  O(n log n)=40  O(n^2)=100
n= 100: O(1)=1  O(log n)=7  O(n)=100  O(n log n)=700  O(n^2)=10000
n=1000: O(1)=1  O(log n)=10  O(n)=1000  O(n log n)=10000  O(n^2)=1000000
```

> `O(log n)` 的 `log` 是「以 2 为底」的近似（这里用 `n.bit_length()` 表示「n 是几个二进制位」）。1000 个元素，二分只要约 10 步——这就是后面 ch08 二分查找快的秘密。

## 四、实测 O(n) 与 O(n²) 的差距

```python
def linear(n):
    s = 0
    for i in range(n): s += i
    return s

def quadratic(n):
    s = 0
    for i in range(n):
        for j in range(n): s += i*j
    return s

for n in [1000, 2000, 4000]:
    t1 = timeit.timeit(lambda: linear(n), number=200)
    t2 = timeit.timeit(lambda: quadratic(n), number=5)
    print(f"n={n:4d}: O(n)x200={t1:.4f}s  O(n^2)x5={t2:.4f}s  比值≈{t2/t1:.1f}")
```

**预期输出：**

```text
n=1000: O(n)x200=0.0073s  O(n^2)x5=0.2609s  比值≈35.8
n=2000: O(n)x200=0.0131s  O(n^2)x5=1.0783s  比值≈82.1
n=4000: O(n)x200=0.0263s  O(n^2)x5=4.3538s  比值≈165.3
```

> n 翻倍，O(n²) 耗时大约翻 **4 倍**（2²），比值从 35.8 → 165.3。**数据量一大，平方级算法会先死。**

## 五、空间复杂度

除了时间，还要看**额外占多少内存**：

- `O(1)`：只用几个变量（反转字符串原地交换）
- `O(n)`：开了一个和输入等长的辅助数组（前缀和、归并排序的临时数组）
- `O(n²)`：开了二维表（某些 DP）

```python
def make_matrix(n):
    return [[0]*n for _ in range(n)]   # O(n^2) 空间
```

## 复杂度速查表（建议背下来）

| 复杂度 | 名字 | 典型操作 | n=1000 大致步数 |
|---|---|---|---|
| O(1) | 常数 | 数组按下标取、哈希查表 | 1 |
| O(log n) | 对数 | 二分查找、平衡树 | ~10 |
| O(n) | 线性 | 遍历一遍 | 1000 |
| O(n log n) | 线性对数 | 快排/归并/堆排 | ~10000 |
| O(n²) | 平方 | 双层循环、冒泡 | 1000000 |
| O(2ⁿ) | 指数 | 朴素背包、全子集 | 10³⁰（不可接受） |

## 小结

- 大 O 看「规模变大时耗时怎么放大」，砍常数、留主导项、取最坏。
- 衡量算法快慢，最好自己 `timeit` 跑一下，看**倍数**不看绝对值。
- 面试/工程里：能 O(n) 别 O(n²)，能 O(n log n) 别 O(n²)。

## 练习

1. **（判断）** 下面函数复杂度是？
   ```python
   def f(a):
       return [x*2 for x in a if x % 2 == 0]
   ```
2. **（判断）** 下面函数复杂度是？
   ```python
   def g(a):
       total = 0
       for i in range(len(a)):
           for j in range(i+1, len(a)):
               total += a[i] * a[j]
       return total
   ```
3. **（理解）** 为什么说 O(100n) 和 O(n) 一样？什么时候常数又不能忽略？
4. **（实测）** 用 `timeit` 测：对长度 10000 的列表，算 `sum(a)`（内置，近似 O(n)）和手写一个双重循环求和，哪个快？快多少倍？（跑一下把数字贴出来）
5. **（空间）** 反转一个链表（ch03 会学），需要额外开等长数组吗？它的空间复杂度是 O(1) 还是 O(n)？先猜，ch03 验证。

**答案与解析**

1. 遍历一遍 + 过滤，**O(n)**。列表推导每元素一次判断。
2. 两层循环，外层 n 次、内层平均 n/2 次，约 n²/2 步 → **O(n²)**。
3. 大 O 忽略常数倍，所以 O(100n)=O(n)。但**实际工程中常数很要命**：当 n 不大（比如 n=50）时，100 倍常数可能让 O(n) 比 O(n²) 还慢；或者常数来自昂贵的 I/O/网络，不能只看阶。大 O 是「规模足够大时」的渐近结论。
4. 预期：`sum(a)` 快很多（内置用 C 实现且单趟）。手跑脚本大致：
   ```python
   import timeit, random
   a = [random.random() for _ in range(10000)]
   t1 = timeit.timeit(lambda: sum(a), number=1000)
   def my_sum(a):
       s = 0
       for x in a: s += x
       return s
   t2 = timeit.timeit(lambda: my_sum(a), number=1000)
   print(f"sum内置 x1000={t1:.4f}s  手写 x1000={t2:.4f}s  比值≈{t2/t1:.1f}")
   ```
   预期 `比值≈1.x~3`（两者都是 O(n)，差距来自 Python 字节码 vs C 实现，不是阶的差距）。
5. 反转链表**原地**改指针，不新开等长数组 → 空间 O(1)。如果你用「先转成列表、反转、再建链表」就是 O(n) 额外空间，能原地就别绕路。
