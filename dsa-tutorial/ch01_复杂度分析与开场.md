# ch01 复杂度分析与开场

> 学习目标：拿到一段代码/一个算法，**不运行也能说出它"随数据量变大会怎么变"**。这是算法课的第一把尺子，后面所有章都靠它说话。

---

## 一、为什么先学复杂度

假设老板扔给你 100 万行订单，让你统计每个省的销售额。两种写法：

```
写法 A：两重循环，每行跟其他所有行比一遍（O(n²)）
写法 B：按省份分组，一趟加完（O(n)）
```

数据只有 100 行时，A 秒回；100 万行时，A 可能要几分钟到几小时，B 依然秒回。

> 复杂度衡量的不是"这台机器跑多快"，而是**算法本身随输入规模 n 增长的"工作量趋势"**——这是硬件无关的、算法天生的属性。

---

## 二、手推图示：O(1) / O(n) / O(n²) 到底差在哪

先记住一句话：**大 O 数的是"关键步骤执行了多少次"，而且只关心 n 变大时它怎么涨**。

### 2.1 O(1)：常数时间——做一次就完

```
数组按下标取值 a[5]

内存:  ┌─────────────────────────────────────┐
       │ a[0] │ a[1] │ a[2] │ a[3] │ a[4] │ a[5] │
       └─────────────────────────────────────┘
       CPU 算出地址 = 起点 + 5×每个元素大小
       直接跳过去拿 → 永远只要 1 步
```
n 从 1 变到 1 亿，都是 1 步。

### 2.2 O(n)：线性时间——n 个元素就看 n 次

```
找最大值：必须把每个元素都看一遍

步骤:   1     2     3     4     5     6     7
       ┌─┬─┬─┬─┬─┬─┬─┐
数组   │3│1│4│1│5│9│2│
       └─┴─┴─┴─┴─┴─┴─┘
        ↑   ↑   ↑   ↑   ↑   ↑   ↑    共 7 次比较 → O(7)=O(n)
```
n 涨 10 倍 → 步数也涨 10 倍。这是一条 45° 斜线。

### 2.3 O(n²)：平方时间——两两都比较

```
两重循环的例子：判断数组里有没有重复元素（最笨写法）

i=0 时: 3 vs [1,4,1,5,9,2]   → 6 次
i=1 时: 1 vs [4,1,5,9,2]     → 5 次
i=2 时: 4 vs [1,5,9,2]       → 4 次
...
总共 ≈ 6+5+4+3+2+1 = 21 次 ≈ n²/2 → O(n²)

    i 走 n 格
   ┌───────────────────
   │ ◉ ◉ ◉ ◉ ◉ ◉ ◉ ◉   ← j 也要走 n 格
   │ ◉ ◉ ◉ ◉ ◉ ◉ ◉
j  │ ◉ ◉ ◉ ◉ ◉ ◉
走 │ ◉ ◉ ◉ ◉ ◉
n  │ ◉ ◉ ◉ ◉
格 │ ◉ ◉ ◉
   │ ◉ ◉
   │ ◉
   └────────── 填满一个 n×n 的三角形 → 面积 ≈ n²/2
```
n 涨 10 倍 → 步数涨 100 倍。**这是"数据一多就卡死"的头号元凶。**

### 2.4 三种放一起对比（n 从小到大）

```
n         O(1)     O(n)      O(n²)
1          1        1          1
10         1       10        100
100        1      100     10,000
1,000      1    1,000  1,000,000      ← O(n²) 开始吃力
10,000     1   10,000  100,000,000    ← O(n²) 明显卡顿
100,000    1  100,000  10,000,000,000 ← O(n²) 要几分钟
```
> 一句话记忆：**O(1) 恒为 1，O(n) 加一个零就乘 10，O(n²) 加一个零就乘 100。**

## 三、手推图示：O(log n) 为什么是"砍半狂魔"

```
从 100 万个有序号里找一个数（二分，ch08 细讲）

第 1 步: 100 万 → 50 万     （比中间，砍掉一半）
第 2 步: 50 万 → 25 万
第 3 步: 25 万 → 12.5 万
 ...
第 k 步后剩: n / 2^k

问：砍多少次能剩 1 个？
解：n / 2^k = 1  ⇒  2^k = n  ⇒  k = log₂(n)

n = 100 万  ⇒  log₂(100万) ≈ 20 步
n = 10 亿   ⇒  log₂(10亿)  ≈ 30 步
```
```
线性找 10 亿个里的目标：最多 10 亿 步
二分找 10 亿个里的目标：只要   30   步
差距：3000 万倍
```
> O(log n) 的直觉：**每次丢掉一半**。凡是"每次规模减半"的算法都是 O(log n)。

## 四、手推图示：递归展开 = O(2ⁿ) 灾难

递归代码的复杂度要**展开成树**来数（ch06 系统讲）。以朴素斐波那契为例：

```
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)

fib(5) 的调用树：
                    fib(5)                    ← 第 1 层：1 个节点
              ┌───────┴───────┐
           fib(4)             fib(3)          ← 第 2 层：2 个
        ┌────┴────┐        ┌────┴────┐
      fib(3)     fib(2)   fib(2)   fib(1)     ← 第 3 层：4 个
     ┌──┴──┐   ┌──┴──┐  ┌──┴──┐
  fib(2) fib(1) fib(1) fib(0) ...
   ...
每层节点数翻倍：1, 2, 4, 8, ...
总节点数 ≈ 2^n 个 → O(2ⁿ)
```
fib(40) 就要调约 20 亿次——现代 CPU 也要几十秒。所以**递归里有重复子问题必须缓存或改动态规划（ch12）**。

## 五、手推图示：为什么复杂度只留"最高次项"

```
f(n) = 3n² + 5n + 7

n=100:    3×10000 + 5×100 + 7 = 30507
n=1000:   3×1000000 + 5000 + 7 = 3005007

看 n 从 100 → 1000（×10）：
  3n² 项:  30000 → 3000000   ×100   ← 主宰
  5n  项:    500 →    5000    ×10    ← 越来越不重要
  7   项:      7 →       7    ×1     ← 忽略

结论: n 很大时，低次项和常数项占比趋近 0
      ⇒ 只写最高次: O(n²)
```
> 所以 `O(2n)`、`O(n+100)`、`O(n²+n)` 一律写成 `O(n)`、`O(n)`、`O(n²)`。**系数、低次项、常数全扔。**

## 六、时间 vs 空间复杂度——鱼与熊掌

```
时间 O(n) 但空间 O(n) 的写法：
def double_list(arr):
    out = []
    for x in arr:
        out.append(x*2)     # 新开一个同样大的数组 → 空间 O(n)
    return out

时间 O(n) 且空间 O(1) 的写法：
def double_inplace(arr):
    for i in range(len(arr)):
        arr[i] *= 2         # 原地改，不开新数组 → 空间 O(1)
```
> 很多经典题就是**拿空间换时间**（如哈希表，ch05），或**拿时间省空间**。面试常说"时间 O(n)、空间 O(n)"就是在报这两笔账。

---

## 七、复杂度的"最坏 / 平均 / 最好"

```
在数组里找 target=5:  [1, 3, 5, 7, 9, ...]

最好: 第一个就是 5 → O(1)      （别拿这个吹牛）
平均: 在中间 → O(n/2) = O(n)
最坏: 最后一个才是/根本没有 → O(n)   ← 我们报这个
```
> 业界默认说复杂度 = **最坏情况**，因为你得保证最差场景也不崩。

## 八、常见复杂度实战速查（配图记忆）

```
数据量          O(n)          O(n log n)      O(n²)
─────────────────────────────────────────────────
1,000        微秒级          微秒级          毫秒级
10,000       微秒级          毫秒级          百毫秒级
100,000      毫秒级          十毫秒级        10 秒级   ← 卡
1,000,000    十毫秒级        百毫秒级        20 分钟级  ← 崩
10,000,000   百毫秒级        秒级            小时级
```
现实参考：Python 里 10⁸ 次简单操作 ≈ 1 秒量级。**n≤10⁴ 随便写；n≥10⁶ 就必须想 O(n log n) 以内的算法。**

## 九、真实对比：本机实跑 O(n) vs O(n²)

把「往数组尾部追加 n 个数」（O(n) 整体）和「往数组头部插入 n 个数」（每次插入都要把后面元素整体右移，整体 O(n²)）真实跑一遍：

```python
import timeit

def tail_append(n):
    arr = []
    for i in range(n):
        arr.append(i)          # 尾部追加: 平均 O(1)，整体 O(n)

def head_insert(n):
    arr = []
    for i in range(n):
        arr.insert(0, i)       # 头部插入: 每次 O(n)，整体 O(n²)

t1 = timeit.timeit(lambda: tail_append(20000), number=1)
t2 = timeit.timeit(lambda: head_insert(20000), number=1)
print(f"尾部追加: {t1:.4f}s   头部插入: {t2:.4f}s   差距 {t2/t1:.0f} 倍")
```

**本机实跑输出（Python 3.13，n=20000）：**

```
尾部追加: 0.0011s   头部插入: 0.0799s   差距 76 倍
```
同样的 2 万个数，只是"从哪头放"，差了 76 倍——这就是 O(n) 与 O(n²) 的真实差距。n 再大 10 倍（20 万）差距会到数百倍。

> 手推验证：头部插入第 i 次要移动 i 个元素，总移动 = 1+2+...+n = n(n+1)/2 ≈ n²/2，确实 O(n²)；尾部追加分摊下来每次 O(1)。**图的面积差 = 代码的速度差。**

## 十、小结

1. 复杂度 = 算法随 n 增长的工作量趋势，分**时间**与**空间**两本账
2. 最常打交道的五个：**O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)**
3. 只看最高次项，扔系数扔常数；默认报**最坏情况**
4. 递归看调用树（O(2ⁿ) 灾难要从根上避免）
5. 实跑验证了 O(n) 与 O(n²) 差 76 倍（n=20000），n 越大差距越离谱

## 十一、练习 5 题

### 练习 1：给下面每段标复杂度，并手推说明

```python
def f1(arr):                # 找最大
    m = arr[0]
    for x in arr:
        if x > m: m = x
    return m

def f2(arr, target):        # 有序数组二分查找（ch08 会学）
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] == target: return mid
        if arr[mid] < target: lo = mid + 1
        else: hi = mid
    return -1

def f3(n):                  # 打印 n×n 矩阵
    for i in range(n):
        for j in range(n):
            print(i, j)
```

**答案：** `f1` = O(n)（一趟扫完）；`f2` = O(log n)（每次砍半，区间 hi-lo 减半）；`f3` = O(n²)（n×n 双循环，矩阵有 n² 个格子就得打印 n² 次）。手推：f2 循环 k 次后区间剩 n/2ᵏ，直到 1 ⇒ k=log₂n。

### 练习 2：下面的代码哪里浪费了？改成 O(n)

```python
def find_dup(arr):
    for i in range(len(arr)):          # O(n²)：两两比
        for j in range(i+1, len(arr)):
            if arr[i] == arr[j]:
                return arr[i]
    return None
```

**答案：** 用集合记录见过的元素，一趟 O(n)（哈希原理 ch05 讲）：

```python
def find_dup(arr):
    seen = set()
    for x in arr:                      # O(n)
        if x in seen: return x
        seen.add(x)
    return None
```
手推：n=10000 时 O(n²) 约 5000 万次比较，O(n) 只有 1 万次——**5000 倍差距**。

### 练习 3：空间复杂度判断

```python
def rev_copy(arr):          # A
    return arr[::-1]        # 切片新建一份

def rev_inplace(arr):       # B
    i, j = 0, len(arr)-1
    while i < j:
        arr[i], arr[j] = arr[j], arr[i]
        i += 1; j -= 1
```
问：A、B 各自的时间与空间复杂度。

**答案：** A：时间 O(n)、空间 O(n)（新建了同样长的列表）；B：时间 O(n)、空间 O(1)（只用了 i、j 两个变量原地交换）。

### 练习 4：手推计算"最坏"比较次数

用 O(n²) 的笨办法在 1000 个数里找重复，最坏要比较约多少次？（写出算式）

**答案：** 最坏（没有重复，全比完）≈ 999+998+...+1 = 999×1000/2 = **499,500 次**。用 O(n) 哈希只要 1000 次。

### 练习 5：递归复杂度手推

```python
def foo(n):
    if n <= 1: return 1
    return foo(n-1) + foo(n-1)     # 调用自己两次
```
画出 n=3 的调用树，给出复杂度。

**答案：** 每层节点翻倍（1,2,4,...），n=3 时共 1+2+4=7 次调用，总调用数 = 2ⁿ-1 → **O(2ⁿ)**。递归树：
```
              foo(3)
         ┌─────┴─────┐
       foo(2)       foo(2)
      ┌──┴──┐      ┌──┴──┐
   foo(1) foo(1) foo(1) foo(1)   7 个节点
```
