# ch05 哈希表

> 学习目标：理解哈希表「用键换 O(1) 查找」的原理；能手写两数之和、计数统计、集合去重；能实现一个 LRU 缓存。SQL 里的 `GROUP BY`、索引，本质都是哈希/树。

## 一、哈希表是什么

哈希表（Python 的 `dict`、`set`）核心是：**把「键」通过一个哈希函数算成一个整数位置，直接存到那个位置**。理想情况下查找、插入、删除都是 **O(1)**。

```python
d = {"广东": 1200, "浙江": 340}
print(d["广东"])        # 1200  O(1)
d["上海"] = 800        # 插入 O(1)
print("浙江" in d)     # True  O(1)
```

> 代价：① 哈希冲突（不同键算到同一位置）要用链表/开放寻址处理，最坏退化成 O(n)；② 无序（Python 3.7+ 的 dict 保插入序是特例，别依赖）；③ 占内存比数组多（要存哈希值、扩容）。

## 二、两数之和（哈希把 O(n²) 变 O(n)）

ch02 里用双重循环（O(n²)）解过。用哈希「边走边记」，一遍就够。

```python
def two_sum(nums, target):
    seen = {}                      # 值 -> 下标
    for i, x in enumerate(nums):
        if target - x in seen:     # 之前见过 complement 吗？
            return [seen[target - x], i]
        seen[x] = i
    return []

print("两数之和 [2,7,11,15] t=9:", two_sum(nums=[2, 7, 11, 15], target=9))
print("两数之和 [3,2,4] t=6:", two_sum(nums=[3, 2, 4], target=6))
```

**预期输出：**

```text
两数之和 [2,7,11,15] t=9: [0, 1]
两数之和 [3,2,4] t=6: [1, 2]
```

> 走到 7 时发现 `9-7=2` 还没出现过；走到 4 时发现 `6-4=2` 在 seen 里（下标 1）→ 返回 `[1,2]`。**空间换时间**的经典：多花 O(n) 空间，省下 O(n) 时间。

## 三、计数（Counter）

`collections.Counter` 是哈希计数的语法糖，做「频次统计」一行搞定。

### 3.1 字母异位词判定

```python
from collections import Counter

def is_anagram(a, b):
    return Counter(a) == Counter(b)

print("listen/silent 异位词:", is_anagram("listen", "silent"), "| hello/world:", is_anagram("hello", "world"))
```

**预期输出：**

```text
listen/silent 异位词: True | hello/world: False
```

> 两个词字母种类和数量一样就是异位词。SQL 教程里「按品类统计销售额」、`python-tutorial` 里「去重保序」，底层都是这个计数思想。

### 3.2 找出重复元素

```python
def find_dups(nums):
    seen, dups = set(), set()
    for x in nums:
        if x in seen: dups.add(x)
        seen.add(x)
    return sorted(dups)

print("重复 [4,9,5,4,8,9,5]:", find_dups([4, 9, 5, 4, 8, 9, 5]))
```

**预期输出：**

```text
重复 [4,9,5,4,8,9,5]: [4, 5, 9]
```

## 四、集合（set）：去重与集合运算

`set` 是「只有键没有值」的哈希表，用来去重和判断存在。

```python
def common(a, b):
    return list(set(a) & set(b))     # 交集

print("交集 [1,2,3]/[2,3,4]:", common([1, 2, 3], [2, 3, 4]))
```

**预期输出：**

```text
交集 [1,2,3]/[2,3,4]: [2, 3]
```

> `&` 交集、`|` 并集、`-` 差集、`^` 对称差。去重就是 `set(list)` 再转回。你 python-tutorial 里 `dedupe_keep_order` 也是「set 判重 + 列表保序」。

## 五、LRU 缓存（哈希 + 双向链表）

面试难度标杆题：**最近最少使用**缓存——容量满时，扔掉最久没用过的。

思路：哈希表 O(1) 定位 + 双向链表维护「使用顺序」（头=最新，尾=最旧）。Python 的 `OrderedDict` 把两者合体，`move_to_end` 更新顺序，`popitem(last=False)` 扔最旧。

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, cap):
        self.cap = cap
        self.m = OrderedDict()
    def get(self, k):
        if k not in self.m:
            return -1
        self.m.move_to_end(k)        # 用了就移到最新
        return self.m[k]
    def put(self, k, v):
        if k in self.m:
            self.m.move_to_end(k)
        self.m[k] = v
        if len(self.m) > self.cap:
            self.m.popitem(last=False)   # 超容量，扔最旧
    def snapshot(self):
        return list(self.m.items())

c = LRUCache(2)
c.put(1, 1); c.put(2, 2)
print("get 1:", c.get(1), "| 状态:", c.snapshot())
c.put(3, 3)   # 容量2，踢出最旧的 2
print("put3后 状态:", c.snapshot(), "| get2:", c.get(2))
```

**预期输出：**

```text
get 1: 1 | 状态: [(2, 2), (1, 1)]
put3后 状态: [(1, 1), (3, 3)] | get2: -1
```

> `get(1)` 后 1 变最新（排到 2 后面）；`put(3)` 满了，最旧的 2 被踢 → `get(2)` 返回 -1。**这正是操作系统/数据库/浏览器缓存的底层算法**，你学 SQL 索引、Redis 都会碰到同类思想。

## 六、哈希表的工程真相

- **好哈希函数**让键均匀分布，查找接近 O(1)；差哈希（比如全撞一个桶）退化成 O(n)。
- Python `dict` 键必须**可哈希**（不可变）：数字、字符串、元组可以；`list`、`dict`、`set` 不行。
- 遍历 dict 时**别改它大小**（增删），会报错或漏元素；先收集再改。

```python
try:
    hash([1, 2])
except TypeError as e:
    print("列表不可哈希:", e)
```

## 小结

- 哈希表 = 键换 O(1) 查找，代价是内存和哈希冲突。
- 两数之和、计数、去重、集合运算 = 哈希四类高频用法。
- LRU 缓存 = 哈希 + 双向链表，是缓存淘汰的工业标准。
- SQL 的 `GROUP BY`、索引（哈希索引）、`DISTINCT` 全是哈希思想。

## 练习

1. **（两数之和变体）** 写 `two_sum_sorted(nums, target)` 假设数组**已排序**，用 ch08 的二分或双指针做到 O(n) 且不借助哈希（提示：左右夹逼）。测 `[2,3,4,5] t=7`。
2. **（计数）** 写 `top_k(words, k)` 返回出现次数最多的 k 个词。提示：`Counter(words).most_common(k)`。测 `["a","b","a","c","b","a"] k=2`。
3. **（集合）** 写 `unique_morse(words)` 计算一组单词「摩斯密码表示」去重后有多少种（经典题，体会 set 去重）。可只测小例子。
4. **（LRU 理解）** LRU 和 FIFO（先进先出）淘汰有什么区别？各适合什么场景？
5. **（实战联想）** 你 `python-tutorial` 最后用字典累积「各省销售额」。如果数据有 1000 万行，用 dict 累积的复杂度是多少？和「先排序再扫一遍」比，谁更省内存？（提示：哈希 O(n) 空间，排序 O(n log n) 时间）

**答案与解析**

1.
   ```python
   def two_sum_sorted(nums, target):
       i, j = 0, len(nums) - 1
       while i < j:
           s = nums[i] + nums[j]
           if s == target: return [i, j]
           if s < target: i += 1
           else: j -= 1
       return []
   print(two_sum_sorted([2,3,4,5], 7))   # [1, 2]
   ```
   左右指针夹逼，O(n) 时间、O(1) 空间。
2.
   ```python
   from collections import Counter
   def top_k(words, k):
       return Counter(words).most_common(k)
   print(top_k(["a","b","a","c","b","a"], 2))   # [('a', 3), ('b', 2)]
   ```
3.
   ```python
   MORSE = {"a":".-","b":"-...","c":"-.-."}
   def unique_morse(words):
       return len({ "".join(MORSE[ch] for ch in w) for w in words })
   print(unique_morse(["gin","zen"]))   # gin=.--.  zen=--.  -> 2
   ```
   集合自动去重。
4. FIFO 按「进入顺序」扔最老的；LRU 按「使用顺序」扔最久没用的。LRU 更聪明（刚用过的别扔），适合有局部性热点的缓存（如网页/数据库）；FIFO 实现简单，适合无热点差异的队列。
5. dict 累积是 O(n) 时间、O(不同键数) 空间；排序后扫一遍是 O(n log n) 时间、O(1) 额外空间（原数组上排）。**数据量极大、不同键不多时 dict 更快；内存极度紧张时排序法更省内存。** 工程中通常 dict 优先（简单且快）。
