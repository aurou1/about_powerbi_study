# ch06 递归与分治

> 学习目标：理解递归「自己调自己」的运转机制（调用栈、base case）；明白为什么朴素斐波那契慢得离谱、记忆化能加速上万倍；掌握分治「分而治之」的套路。

## 一、递归是什么

**递归 = 函数自己调用自己**，同时有一个「不再递归」的出口（base case）。它靠**调用栈**实现：每次调用把当前现场压栈，返回时弹栈。

写递归三件套：
1. **base case**：最小子问题，直接返回（防止无限递归）。
2. **递推关系**：把大问题拆成更小的同类问题。
3. **向 base case 收敛**：每次递归参数都要更接近出口。

```python
def factorial(n):
    if n <= 1:                  # ① base case
        return 1
    return n * factorial(n - 1) # ② 递推 ③ n-1 向 1 收敛

print("5! =", factorial(5), "| 10! =", factorial(10))
```

**预期输出：**

```text
5! = 120 | 10! = 3628800
```

> `factorial(5)` 展开是 `5 × 4 × 3 × 2 × 1`，每层都压一次栈。n 很大时层数 = n，所以 ch01 说的 `RecursionError` 就来自这里。

## 二、一个血的教训：朴素斐波那契

```python
def fib_naive(n):
    if n < 2:
        return n
    return fib_naive(n-1) + fib_naive(n-2)

from functools import lru_cache
@lru_cache(None)
def fib_memo(n):
    if n < 2:
        return n
    return fib_memo(n-1) + fib_memo(n-2)

print("fib(10) naive:", fib_naive(10), "| memo:", fib_memo(10))
```

**实测：**

```python
import timeit
t_naive = timeit.timeit(lambda: fib_naive(30), number=1)
t_memo   = timeit.timeit(lambda: fib_memo(30), number=1)
print(f"fib(30) 朴素={t_naive:.3f}s  记忆化={t_memo:.5f}s  加速≈{t_naive/max(t_memo,1e-9):.0f}x")
```

**预期输出：**

```text
fib(10) naive: 55 | memo: 55
fib(30) 朴素=0.186s  记忆化=0.00002s  加速≈11617x
```

> 朴素版 `fib(30)` 要算约 2^30 次（指数级 O(2ⁿ)），因为 `fib(28)` 被重复算了几百万次。**记忆化（`@lru_cache`）把算过的结果缓存**，同样子问题只算一次 → 变 O(n)。**加速 1 万多倍**——这就是「同样的答案，换个写法快一万倍」。

## 三、汉诺塔（递归思维的绝佳例子）

把 n 个盘子从 A 移到 C，大盘不能压小盘。核心思想：**要移 n 个，先移上面 n-1 个到 B，再移最大的到 C，再把 n-1 个从 B 移到 C**。

```python
def hanoi(n, src, aux, dst, moves=None):
    if moves is None:
        moves = []
    if n == 0:
        return moves
    hanoi(n - 1, src, dst, aux, moves)   # 1. 上面 n-1 个挪到辅助柱
    moves.append((src, dst))             # 2. 最大的挪到目标柱
    hanoi(n - 1, aux, src, dst, moves)   # 3. n-1 个从辅助柱挪到目标柱
    return moves

m = hanoi(3, "A", "B", "C")
print("汉诺塔(3) 步数:", len(m), "步骤:", m)
```

**预期输出：**

```text
汉诺塔(3) 步数: 7 步骤: [('A', 'C'), ('A', 'B'), ('C', 'B'), ('A', 'C'), ('B', 'A'), ('B', 'C'), ('A', 'C')]
```

> 步数 = 2ⁿ − 1。汉诺塔把「移动 n 个」完全委托给「移动 n−1 个」，自己只管最大那一步。这就是递归的威力：**不用管细节怎么挪，只相信「子问题能搞定」**。

## 四、分治（Divide & Conquer）

**分治 = 把大问题切成独立的小问题，各自解决，再合并。** 三个步骤：分（divide）、治（conquer）、合（combine）。

### 4.1 快速幂（分治把 O(n) 变 O(log n)）

算 xⁿ，不用乘 n 次。n 偶数时 xⁿ = (xⁿᐟ²)²，规模砍半。

```python
def pow_fast(x, n):
    if n == 0:
        return 1
    if n < 0:
        return 1 / pow_fast(x, -n)
    half = pow_fast(x, n // 2)
    return half * half * (x if n % 2 else 1)

print("2^10 =", pow_fast(2, 10), "| 3^5 =", pow_fast(3, 5), "| 0.5^3 =", pow_fast(0.5, 3))
```

**预期输出：**

```text
2^10 = 1024 | 3^5 = 243 | 0.5^3 = 0.125
```

> 朴素要 10 次乘法，分治只要 log₂(10)≈4 次。规模翻 1000 倍，分治只多约 10 步。

### 4.2 数组最大值（分治版）

```python
def max_dc(a, lo, hi):
    if lo == hi:
        return a[lo]                 # base：一个元素
    mid = (lo + hi) // 2
    return max(max_dc(a, lo, mid), max_dc(a, mid + 1, hi))

print("最大值分治 [3,9,1,7,5]:", max_dc([3, 9, 1, 7, 5], 0, 4))
```

**预期输出：**

```text
最大值分治 [3,9,1,7,5]: 9
```

> 左右两半各自求最大再比。这看着多此一举（直接 `max(a)` 就行），但**归并排序、快速排序就是这个「切两半再合并」的骨架**（ch07）。

## 五、递归的代价与坑

- **栈溢出**：递归深度 = 数据规模，太深会 `RecursionError`（链表反转 ch03 提过）。能迭代就迭代。
- **重复计算**：像朴素斐波那契，用记忆化或改成迭代。
- **尾递归**：若递归调用是最后一步且不做额外运算，有些语言能优化成循环（Python **不**做这优化，别依赖）。

> 工程铁律：**能用循环写的，优先循环**；递归留给「问题本身天然递归」的场景（树、分治、回溯 ch13）。

## 小结

- 递归三件套：base case + 递推 + 向 base 收敛，靠调用栈实现。
- 朴素递归常指数级爆炸，记忆化/迭代能救。
- 分治 = 分 → 治 → 合，快速幂、归并、快排都是它。
- 深度大就改迭代，别硬递归。

## 练习

1. **（递归）** 写 `sum_rec(a)` 用递归求列表和（base：空列表返回 0）。测 `[1,2,3,4]`。
2. **（递归树）** `fib_naive(5)` 里 `fib(1)` 被算了多少次？（手画递归树数一下，答案是 8 次）
3. **（分治）** 写 `power_rec(x, n)` 的**迭代**版本（不用递归）算 xⁿ，复杂度 O(log n)。提示：把 n 转二进制，平方累乘。
4. **（记忆化）** 爬楼梯问题：一次爬 1 或 2 阶，`climb(n)` 有几种走法？`climb(n)=climb(n-1)+climb(n-2)`（即斐波那契），用 `@lru_cache` 写并算 `climb(40)`。
5. **（实战联想）** 你 `sql-tutorial` 里写存储过程 `sp_monthly_sales` 按月汇总。若改成「先按天递归汇总、再按月合并」，现实里为什么不用递归？（提示：SQL 擅长集合扫描，递归适合树形；且数据库怕深递归）

**答案与解析**

1.
   ```python
   def sum_rec(a):
       if not a: return 0
       return a[0] + sum_rec(a[1:])
   print(sum_rec([1,2,3,4]))   # 10
   ```
2. 递归树：fib(5)→fib(4)+fib(3)→…展开后 `fib(1)` 出现在每个「叶子或次叶子」共 **8 次**（fib(0) 出现 5 次）。这正是朴素版慢的根源，记忆化后只算 1 次。
3.
   ```python
   def power_iter(x, n):
       if n < 0: x, n = 1/x, -n
       res = 1
       while n:
           if n & 1: res *= x
           x *= x; n >>= 1
       return res
   print(power_iter(2, 10), power_iter(3, 5))   # 1024 243
   ```
   二进制位控制是否乘当前平方值，O(log n)。
4.
   ```python
   from functools import lru_cache
   @lru_cache(None)
   def climb(n):
       if n < 2: return 1
       return climb(n-1) + climb(n-2)
   print(climb(40))   # 165580141
   ```
   不加 lru_cache 会极慢（指数级），加了 O(n)。
5. 月度汇总是「扁平的集合分组」（`GROUP BY month`），用一条 SQL 扫描搞定，O(n)；递归适合「父节点→子节点」的树形数据（如组织结构、BOM 物料清单）。数据库递归（CTE）有深度上限且不好并行，所以这类报表用聚合而非递归。
