## 一、递归的本质：自己调自己，但规模变小

先看一段"问路"的递归：

```
你问 A 怎么去车站，A 说"你先问 B，B 知道"
你问 B，B 说"你先问 C，C 知道"
你问 C，C 说"往前走 100 米就到了"        ← C 知道答案，开始往回传
C 告诉你 → B 告诉你 → A 告诉你 → 你知道了
```

```
递归的"人肉执行"：
  ask(你) ──▶ ask(A) ──▶ ask(B) ──▶ ask(C) ──▶ "向前100米" (到底了!)
     ▲         ▲         ▲         │
     └─────────┴─────────┴─────────┘
      C 把答案一层层传回来 = 回溯（return）
```
> 递归代码三要素（缺一不可）：
> 1. **终止条件**（base case）：什么时候不再调用自己（C 知道答案）
> 2. **递归式**：把问题拆小后调用自己
> 3. **收窄保证**：每次调用规模一定变小（否则无限递归，栈溢出）

```python
def ask(person, depth=1):
    if person == "C":                    # ① 终止条件
        return "向前走100米"
    return ask(下一个人, depth+1)         # ②③ 拆小 + 调自己
```

## 二、手推图示：调用栈——递归是怎么"记住"中途状态的

每次函数调用，CPU 会压一个**栈帧**（保存参数、局部变量、返回地址）。递归就是不断压栈，到底后一层层弹栈。

```
计算 fact(4) = 4×3×2×1

调用过程（压栈）：
  fact(4) 调 fact(3) 调 fact(2) 调 fact(1)
  栈:                                    ┌─────┐
       ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┤n=1  │ ← 栈顶，n=1 到底了
       │n=4  │  │n=3  │  │n=2  │  │n=1  │     │
       │???  │  │???  │  │???  │  │ret 1│
       └─────┘  └─────┘  └─────┘  └─────┘
       ↑自底向上压了 4 层

回溯过程（弹栈，逐个算出结果填回 ???）：
  fact(1) 返回 1
  fact(2) 返回 2×1 = 2        ┌─────┐
  fact(3) 返回 3×2 = 6        │n=3→6│
  fact(4) 返回 4×6 = 24       │n=4→24│
                              └─────┘
  结果 24 ✅
```
```python
def fact(n):
    if n <= 1: return 1        # 终止条件
    return n * fact(n-1)       # 拆小 + 调自己

print(fact(4))   # 24
```
> 一句话：**压栈是"往下钻"，弹栈是"往回算"。** 递归深度 = 栈帧数，Python 默认限制约 1000 层（`sys.setrecursionlimit` 可调，但深度太大建议改迭代）。

## 三、手推图示：汉诺塔——递归"分解动作"的教科书

三根柱子 A/B/C，把 n 个盘从 A 移到 C，**大盘永远不能压小盘**。

```
递归洞察（先想 n=2，再推广到 n）：
把 n 个盘从 A→C，等价于：
  ① 把上面 n-1 个盘从 A→B（用 C 当辅助）
  ② 把最大的第 n 个盘从 A→C（一步）
  ③ 把 B 上 n-1 个盘从 B→C（用 A 当辅助）

n=3 的完整过程（A→C）：
    第一步组: 把 A 上 2 个移到 B（借助 C）
        A→C   （盘1 去 C）
        A→B   （盘2 去 B）
        C→B   （盘1 从 C 去 B，压到盘2 上）
    第二步:   A→C   （盘3 直接去 C）     ← 最大盘就位
    第三步组: 把 B 上 2 个移到 C（借助 A）
        B→A   （盘1 去 A）
        B→C   （盘2 去 C）
        A→C   （盘1 从 A 去 C，完成!）
    共 7 步 = 2³-1 ✅
```
```python
def hanoi(n, src, dst, aux):
    if n == 0: return                       # 没有盘子要搬了
    hanoi(n-1, src, aux, dst)               # ① n-1 个: 源→辅助
    print(f"{src}->{dst}")                  # ② 最大盘: 源→目标
    hanoi(n-1, aux, dst, src)               # ③ n-1 个: 辅助→目标

hanoi(3, 'A', 'C', 'B')
print("移动次数: 2^3-1 =", 2**3-1)
```
**预期输出：**
```
A->C
A->B
C->B
A->C
B->A
B->C
A->C
移动次数: 2^3-1 = 7
```
> 手推复杂度：T(n) = 2T(n-1) + 1 → 解出 T(n) = **2ⁿ - 1**。所以汉诺塔是 O(2ⁿ)——n=64 时全宇宙都搬不完。**递归不一定快，它只是"好写、好懂"。**

## 四、手推图示：分治三步走（以归并排序为例）

分治 = **分（拆两半）→ 治（各自递归排好）→ 合（合并）**。

```
归并排序 [38, 27, 43, 3, 9, 82, 10]

拆（分）:
                    [38 27 43 3 9 82 10]
                   /                    \
          [38 27 43 3]              [9 82 10]
          /         \                /      \
      [38 27]     [43 3]          [9 82]   [10]
      /    \      /    \          /    \
   [38]  [27]  [43]  [3]       [9]   [82]     ← 拆到单个

合（治: 两两合并成有序）:
   [27 38]     [3 43]        [9 82]     [10]
        \       /                \      /
      [3 27 38 43]            [9 10 82]
              \                 /
            [3 9 10 27 38 43 82]          ← 全有序 ✅
```
```
合并两个有序数组的手推（ch02 学过）:
  [27 38] + [3 43] → 比队头: 3<27 取3, 27<43取27, 38<43取38, 剩43
  → [3 27 38 43]
```
```python
def merge_sort(a):
    if len(a) <= 1: return a             # 治: 单个元素天然有序
    m = len(a) // 2
    left = merge_sort(a[:m])             # 分+治: 左半排好
    right = merge_sort(a[m:])            # 分+治: 右半排好
    return merge(left, right)            # 合: 两个有序数组合并

def merge(x, y):
    r, i, j = [], 0, 0
    while i < len(x) and j < len(y):
        if x[i] <= y[j]: r.append(x[i]); i += 1
        else: r.append(y[j]); j += 1
    r += x[i:]; r += y[j:]
    return r

print(merge_sort([38,27,43,3,9,82,10]))   # [3, 9, 10, 27, 38, 43, 82]
```
**预期输出：** `[3, 9, 10, 27, 38, 43, 82]`

### 归并排序复杂度怎么来的（递归树手推）

```
每层都把所有元素"过"一遍合并 → 每层 O(n)
树有几层？每次砍半 → log₂n 层

层1:               [整段]                        → 合并 O(n)
层2:          [左半]    [右半]                   → 两段合并共 O(n)
层3:      [¼][¼]  [¼][¼]                       → 四段合并共 O(n)
...
层 log n:  单个元素...                           → O(n)

总时间 = 层数 × 每层 O(n) = O(n log n)
空间 = 每层临时数组，递归深度 log n → O(n)
```
> **O(n log n) 是通用排序的理论最优档**（比较排序下界），比冒泡的 O(n²) 快得多（ch07 实测 ~68 倍）。

## 五、手推图示：快速排序——选哨兵，小的左大的右

快排也是分治，但"合"不需要额外空间——靠 **partition** 把哨兵放到最终位置。

```
快速排序 [10, 7, 8, 9, 1, 5]   （Lomuto: 选最后一个当哨兵 pivot=5）

partition 手推:
  i 指向"下一个小于哨兵的位置"，j 从头扫

  初始: [10, 7, 8, 9, 1, 5]   i=0
  j=0: 10<5? 否
  j=1: 7<5?  否
  j=2: 8<5?  否
  j=3: 9<5?  否
  j=4: 1<5?  是! → 交换 a[i]和a[4]: a[0]=1  ← [1, 7, 8, 9, 10, 5], i=1
  扫完 → 哨兵归位: 交换 a[1] 和 a[5] → [1, 5, 8, 9, 10, 7]

  → 5 已经在"最终位置"：左边全 <5，右边全 ≥5
  → 递归快排左边 [1] 和右边 [8, 9, 10, 7]

递归分治图:
         [1, 5, 8, 9, 10, 7]     5 就位
        /                    \
   [1](ok)               [8, 9, 10, 7]   pivot=7
                             ↓ partition
                        [7, 8, 10, 9]    7 就位
                          /         \
                     [8](ok)    [10, 9]  pivot=9
                                   ↓
                                [9, 10]  9 就位
                                   \
                                  [10](ok)
   最终: [1, 5, 7, 8, 9, 10] ✅
```
```python
def quicksort(a, lo, hi):
    if lo >= hi: return                 # 空/单元素
    p = partition(a, lo, hi)            # 哨兵归位
    quicksort(a, lo, p-1)               # 排左边
    quicksort(a, p+1, hi)               # 排右边

def partition(a, lo, hi):
    pivot = a[hi]                       # 选最后一个当哨兵
    i = lo                              # i: 小于哨兵的"分界线"
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]     # 把小的换到左边
            i += 1
    a[i], a[hi] = a[hi], a[i]           # 哨兵放到分界线
    return i

arr = [10, 7, 8, 9, 1, 5]
quicksort(arr, 0, len(arr)-1)
print(arr)                              # [1, 5, 7, 8, 9, 10]
```
**预期输出：** `[1, 5, 7, 8, 9, 10]`

### 快排复杂度：平均 vs 最坏

```
平均: 哨兵大致在中间 → 递归树平衡 → O(n log n)，且常数比归并小
最坏: 数组已有序 + 每次选最后 → 每次只切掉一个 → 树退化成一条线 → O(n²)

手推最坏情形 [1,2,3,4,5]:
  pivot=5 → partition 后 4 在 5 左边，只分成 [1,2,3,4] 和 空
  每层只少 1 个元素 → 要 n 层，每层扫 n → O(n²)
```
> 应对：**随机选哨兵 / 三数取中**，让最坏几乎不可能发生。工程上快排仍是默认排序（Python 的 TimSort 是归并+插入的混合体）。

## 六、手推图示：递归树算复杂度——以 Fibonacci 为例

```
朴素 fib(n) = fib(n-1) + fib(n-2)

递归树（每层节点翻倍）:
                    fib(5)                    层0: 1 节点
               ┌─────┴─────┐
            fib(4)        fib(3)              层1: 2
         ┌────┴────┐    ┌────┴────┐
       fib(3)    fib(2) fib(2) fib(1)         层2: 4
      ┌──┴──┐   ┌──┴──┐ ...
   fib(2) fib(1)...
   总节点 ≈ 2⁵ → O(2ⁿ)

优化: 用字典记下算过的（记忆化 memo）:
  fib(5) 只需算 5 个不同子问题 fib(0..4) → O(n)!

  memo = {0:0, 1:1}
  def fib(n):
      if n in memo: return memo[n]
      memo[n] = fib(n-1) + fib(n-2)
      return memo[n]
```
> 递归树里**同一子问题被反复算**（fib(3) 出现 2 次、fib(2) 出现 3 次）就是"重叠子问题"——这正是 ch12 动态规划登场的地方。**看到 2ⁿ 的递归树 → 立刻想记忆化。**

## 七、手推图示：快速选择（快排的 partition 直接找第 K 大）

题目：`[3,2,1,5,6,4]` 找第 2 大（=5）。不用全排序——partition 一次只解决一个位置，**哨兵刚好落在 k 就停**。

```
a=[3,2,1,5,6,4], 找第2大 → 升序第 len-2=4 个（0 基）→ k=4

partition(全段, pivot=4) → 4 落在下标3:
   结果 [3,2,1,4,6,5]   k=4 > 3 → 只搜右半 [6,5]
partition([6,5], pivot=5) → 5 落在下标4 = k! 返回 5 ✅

每轮只搜一半 → 平均 O(n)（不是 O(n log n)）
```
```python
def partition(a, lo, hi):            # 同上
    pivot = a[hi]; i = lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

def find_kth(a, k):                  # k 是升序第 k 个（0 基）
    def qsel(lo, hi):
        p = partition(a, lo, hi)
        if p == k: return a[p]
        return qsel(lo, p-1) if p > k else qsel(p+1, hi)
    return qsel(0, len(a)-1)

a = [3,2,1,5,6,4]
print("第2大:", find_kth(a, len(a)-2))      # 5
b = [3,2,3,1,2,4,5,5,6]
print("第4大:", find_kth(b, len(b)-4))      # 4
```
**预期输出：** `第2大: 5` `第4大: 4`

## 八、手推图示：快速幂——分治的"指数级省事"

算 xⁿ，朴素乘 n 次 O(n)；快速幂每次把指数砍半 O(log n)。

```
算 2^10:
  10 是偶数 → 2^10 = (2^5)²
  5  是奇数 → 2^5  = 2 × 2^4
  4  是偶数 → 2^4  = (2^2)²
  2  是偶数 → 2^2  = (2^1)²
  1  是奇数 → 2^1  = 2 × 2^0 = 2

  自底向上: 2^1=2 → 2^2=4 → 2^4=16 → 2^5=32 → 2^10=1024
  只乘了约 2·log₂n 次而不是 n 次
```
```python
def power(x, n):
    if n == 0: return 1
    if n % 2 == 0:
        half = power(x, n//2)     # 指数砍半
        return half * half
    return x * power(x, n-1)      # 奇数先降 1 变偶数

print(power(2, 10))    # 1024
print(power(3, 5))     # 243
```
**预期输出：** `1024` `243`
复杂度 O(log n)——2¹⁰⁰⁰⁰⁰⁰⁰ 只要几十次乘法。

## 九、分治 & 递归的"使用检查清单"

```
拿到一个问题，先问：
□ 能拆成几个更小的同类子问题吗？（分）
□ 子问题小到一定程度我能直接答吗？（治/终止条件）
□ 子问题的解能合并成原问题的解吗？（合）
→ 三个都是"是"，就可以写递归

警惕：
□ 子问题重复吗？重复 → 记忆化 / 动态规划（ch12）
□ 深度会超过 ~1000 吗？会 → 改迭代 / 尾递归优化
□ 每次都明显变小吗？不缩小 → 会栈溢出
```
> 递归难点不在"写出来"，而在**用递归树想清楚"拆了几层、每层多少工作、有没有重复"**——这三点直接决定复杂度。

## 十、小结

1. 递归三要素：**终止条件 + 递归式 + 收窄保证**
2. 调用栈：压栈往下钻、弹栈往回算；深度太大有栈溢出风险
3. 分治 = **分 → 治 → 合**；归并排序是典型（O(n log n)）
4. 快排靠 partition 让哨兵归位，平均 O(n log n)，最坏 O(n²)（有序+尾哨兵）
5. 递归树两层含义：数复杂度（层数×每层工作量）、发现重复子问题
6. 重复子问题 → 记忆化 → 复杂度从 O(2ⁿ) 变 O(n)（为 ch12 埋伏笔）
7. 快速选择 = partition + 只搜一边 → O(n) 找第 K 大

## 十一、练习 5 题

### 练习 1：用递归求 1 到 n 的和

**答案：**
```python
def sum_n(n):
    if n <= 1: return n          # 终止
    return n + sum_n(n-1)        # n + (1..n-1的和)

print(sum_n(100))    # 5050
```
**预期输出：** `5050`
**解析**：递归式 sum_n(n) = n + sum_n(n-1)。手推 sum_n(3) = 3 + sum_n(2) = 3 + (2 + sum_n(1)) = 3+2+1 = 6。深度 n，**栈空间 O(n)**。

### 练习 2：翻转字符串（递归）

**答案：**
```python
def rev(s):
    if len(s) <= 1: return s
    return rev(s[1:]) + s[0]     # 反转让 s 去掉首字符后的部分 + 首字符

print(rev("hello"))    # olleh
```
**预期输出：** `olleh`
**解析**：手推 rev("ab") = rev("b")+"a" = "ba"。本质：把首字符挪到最后，递归处理剩下的。

### 练习 3：合并 K 个有序链表思路（分治思想，不写码）

三个有序链表，要合成一个有序的。为什么"两两合并"比分治快？若逐个合并（先合1&2，再合3），第 i 次合并要扫 i 个链表的总长 → O(nk²)？还是两两配对合并只需 O(nk log k)？简述即可。

**答案：** **两两配对合并（分治）**。每一轮把所有链表两两配对合并，链表数量减半。每轮所有元素被扫一遍 O(nk)（nk 是总元素数），共 log₂k 轮 → **O(nk log k)**。而逐个合并：第 i 次合并已累积 i 个链表长 → 总 O(nk²)，明显更差。**分治的意义就是让"每层全量扫一遍"只发生 log k 次。**

### 练习 4：爬楼梯——先画递归树再优化

一次可以爬 1 或 2 阶，爬 n 阶有几种方法？递归式 `f(n)=f(n-1)+f(n-2)`，`f(1)=1, f(2)=2`。

**答案（带记忆化）：**
```python
memo = {1:1, 2:2}
def climb(n):
    if n in memo: return memo[n]
    memo[n] = climb(n-1) + climb(n-2)
    return memo[n]

print(climb(4))     # 5
print(climb(10))    # 89
```
**预期输出：** `5` `89`
**解析**：手推 climb(4)：到第 4 阶只能从第 3 阶爬 1 步或第 2 阶爬 2 步来 → f(4)=f(3)+f(2)=(f(2)+f(1))+2=(2+1)+2=5。**不记忆化是 O(2ⁿ)（递归树同 fib），记忆化后 O(n)**。

### 练习 5：归并排序的"分"到底切在哪？

`[4,2,7,1,9,3]` 用 `mid = len//2` 切分，画出完整递归树并给出排序结果。

**答案：**

```
             /             \
       [4 2 7]            [1 9 3]
       /      \            /     \
    [4 2]    [7]        [1 9]    [3]
    /    \              /    \
  [4]   [2]           [1]   [9]

合并:
  [2 4]  [7] → [2 4 7]      [1 9] [3] → [1 3 9]
      \                        /
          [1 2 3 4 7 9]  ✅
```
