## 一、先看一张"全家福"总表（背下来）

```
排序算法      平均        最坏        空间     稳定性
─────────────────────────────────────────────────
冒泡         O(n²)       O(n²)       O(1)     稳定
选择         O(n²)       O(n²)       O(1)     不稳定
插入         O(n²)       O(n²)       O(1)     稳定     ← 近有序超快
归并         O(n log n)  O(n log n)  O(n)     稳定
快排         O(n log n)  O(n²)       O(log n) 不稳定   ← 最坏有序退化
堆排         O(n log n)  O(n log n)  O(1)     不稳定
内置 sorted  O(n log n)  O(n log n)  O(n)     稳定     ← TimSort
```
> 记法：**只有冒泡/插入/归并稳定**；**只有快排最坏会 O(n²)**；**堆排空间最优 O(1)**。

## 二、简单排序

### 2.1 冒泡排序：大的往右"冒"

每一趟把相邻逆序的交换，最大的数像气泡一样浮到最右。

```
[5, 1, 4, 2, 8]  一趟趟演示（红线是已就位的"尾部"）：

第1趟: 5>1换 → [1,5,4,2,8]
       5>4换 → [1,4,5,2,8]
       5>2换 → [1,4,2,5,8]
       5<8 不换          ← 8 已就位（最大浮到最右）
第2趟: 1<4 不换; 4>2换 → [1,2,4,5,8]
       4<5 不换; 5<8 不换    ← 5 就位
第3趟: 1<2 不换; ... 全程没交换 → 提前结束（加了个 swapped 标记）

实跑各趟结果: [[1,4,2,5,8], [1,2,4,5,8], [1,2,4,5,8]]
```
```python
def bubble_sort(a):
    a = a[:]
    for i in range(len(a)):
        swapped = False
        for j in range(len(a)-i-1):        # 已就位的尾部不用再碰
            if a[j] > a[j+1]:
                a[j], a[j+1] = a[j+1], a[j]
                swapped = True
        if not swapped: break              # 一趟没交换 → 已有序
    return a

print(bubble_sort([5,1,4,2,8]))   # [1,2,4,5,8]
```
复杂度：最坏 O(n²)（完全逆序）；**最好 O(n)**（已有序，一趟就停）——这"提前退出"就是自适应。

### 2.2 选择排序：每趟挑最小的放前面

```
[64, 25, 12, 22, 11]

第1趟: 扫全段找最小 11（在最后）→ 和 a[0] 交换 → [11, 25, 12, 22, 64]
第2趟: 在 [25,12,22,64] 找最小 12 → 和 a[1] 换 → [11, 12, 25, 22, 64]
第3趟: 在 [25,22,64] 找最小 22 → 和 a[2] 换 → [11, 12, 22, 25, 64]
第4趟: 在 [25,64] 找最小 25 → 不动          → [11, 12, 22, 25, 64]

实跑各趟: [[11,25,12,22,64], [11,12,25,22,64], [11,12,22,25,64], ...]
```
```python
def selection_sort(a):
    a = a[:]
    for i in range(len(a)):
        m = i
        for j in range(i+1, len(a)):       # 在未排序段找最小
            if a[j] < a[m]: m = j
        a[i], a[m] = a[m], a[i]            # 放到最前
    return a

print(selection_sort([64,25,12,22,11]))    # [11,12,22,25,64]
```
复杂度：不管数据什么样都要全扫找最小 → **永远 O(n²)**（无自适应）。交换次数 ≤ n，比冒泡省交换——所以"交换代价高"时选它。

### 2.3 插入排序：像理扑克牌，新牌插进已排好的手里

```
[5, 2, 4, 6, 1, 3]

i=1: 摸到 2，跟前面 5 比: 5>2 → 5 右移 → [5,5,4,6,1,3]
     空位在 0 → 放 2       → [2,5,4,6,1,3]
i=2: 摸到 4，5>4 右移，2<4 停 → 放中间 → [2,4,5,6,1,3]
i=3: 摸到 6，5<6 不动 → [2,4,5,6,1,3]
i=4: 摸到 1，一路把 6,5,4,2 都右移 → 放最前 → [1,2,4,5,6,3]
i=5: 摸到 3，把 6,5,4 右移，2<3 停 → [1,2,3,4,5,6]

图形（i=4 那步，1 往左"插队"）:
  [2,4,5,6 | 1,3]
      ↑ 1 逐个和 6,5,4,2 比，都比它大 → 全部右移一格
  [2,4,5,6 | 1,3] → 空出最左 → 放 1
  [1,2,4,5,6 | 3]
```
```python
def insertion_sort(a):
    a = a[:]
    for i in range(1, len(a)):
        k = a[i]                      # 摸到的新牌
        j = i - 1
        while j >= 0 and a[j] > k:    # 比 k 大的都右移
            a[j+1] = a[j]
            j -= 1
        a[j+1] = k                    # k 落到空位
    return a

print(insertion_sort([5,2,4,6,1,3]))  # [1,2,3,4,5,6]
```
复杂度：最坏 O(n²)（逆序）；**最好 O(n)**（有序，while 一次都不跑）。**近有序时插入排序是 O(n²) 家族里的王者**——实测见下文。

## 三、进阶排序（回顾 + 补齐）

### 3.1 归并排序（ch06 详讲）

分治：拆两半 → 各自排好 → 合并。稳定，O(n log n)，空间 O(n)。

### 3.2 快速排序（ch06 详讲）

选哨兵 partition → 左小右大。平均 O(n log n)、最坏 O(n²)、不稳定。

### 3.3 堆排序（ch10 细讲，这里先会用它）

**先建堆，再一个个弹出最大值。** Python 用 `heapq`：

```python
import heapq

def heapsort(a):
    h = a[:]
    heapq.heapify(h)                  # 建小顶堆 O(n)
    return [heapq.heappop(h) for _ in range(len(h))]   # 逐个弹出 O(n log n)

print(heapsort([3,1,4,1,5,9,2,6]))    # [1,1,2,3,4,5,6,9]
```
堆排 O(n log n) 且空间 O(1)，但**不稳定**（相同值可能换位）。

## 四、稳定性：为什么重要？（配图讲透）

**稳定 = 相等元素的相对顺序排完不变。**

```
场景: 先按"姓名"排好，再按"班级"排 —— 希望每个班内仍按姓名有序

数据（已按姓名排）:  [(2班, 阿明), (1班, 小丽), (2班, 阿强)]

稳定排序（按班级）:  [(1班, 小丽), (2班, 阿明), (2班, 阿强)]
                          ↑ 两个2班的仍按 阿明→阿强（原名序）
不稳定排序:          [(1班, 小丽), (2班, 阿强), (2班, 阿明)]
                          ↑ 两个2班内部顺序可能乱

为什么选择排序不稳定？
  [2a, 2b, 1] 第1趟找最小 1（在最后）→ 和 a[0]=2a 交换
  → [1, 2b, 2a]   2a 被换到 2b 后面 → 相对顺序破坏!
```
```python
data = [(2,'a'), (1,'x'), (2,'b')]
# 稳定插入排序按第一键排
def stable_sort(pairs):
    a = pairs[:]
    for i in range(1, len(a)):
        k = a[i]; j = i - 1
        while j >= 0 and a[j][0] > k[0]:   # 注意: 严格大于才移动
            a[j+1] = a[j]; j -= 1
        a[j+1] = k
    return a

print(stable_sort(data))     # [(1,'x'), (2,'a'), (2,'b')]  ← (2,a) 仍在 (2,b) 前
```
**预期输出：** `[(1, 'x'), (2, 'a'), (2, 'b')]`

> 稳定性实用场景：**Excel 多级排序、数据库 ORDER BY 多列**——先排次要键、再排主要键，靠稳定排序保住第一趟结果。Python `sorted`/`list.sort` 稳定；`heapq` 不稳定。

## 五、自适应（Adaptive）：数据越有序越快

```
冒泡/插入: 最好 O(n)（已有序一趟搞定）
归并:      检测到有序段可跳过合并（TimSort 就这么干）
选择:      永远 O(n²)，不自适应

为什么插入排序近有序时接近 O(n)?
  内层 while 只在 a[j] > k 时才移动；
  数据有序 → while 几乎不跑 → 只做 n 次外层 → O(n)
```
> 近有序数据（比如"昨天排好的表，今天只改了 50 行"）→ **插入排序是 O(n²) 里唯一能接近 O(n) 的**。TimSort 正是"先检测有序片段 + 插入排序收拾小片段"。

## 六、本机实测：谁快谁慢（n=3000 随机数）

```python
import random, timeit, heapq

# 六个排序实现（bubble/insertion/merge_sort/quick/heapsort 见上文）
random.seed(42)
data = [random.randint(0, 9999) for _ in range(3000)]

for name, fn in [("冒泡", bubble_sort), ("插入", insertion_sort),
                 ("归并", merge_sort), ("快排", quick_sort),
                 ("堆排", heapsort), ("内置sorted", sorted)]:
    t = timeit.timeit(lambda: fn(data), number=1)
    print(f"{name}: {t:.4f}s")
```

**本机实跑输出（Python 3.13，n=3000）：**
```
冒泡: 0.4110s
插入: 0.1855s
归并: 0.0061s
快排: 0.0045s
堆排: 0.0008s
内置sorted: 0.0003s
```
**读表结论：**
- O(n log n) 组全面碾压 O(n²) 组：**归并比冒泡快 ~67 倍**
- 同为 O(n²)，插入比冒泡快一倍（交换少）
- 快排常数小；堆排 0.0008s 快是因为 `heapq` 是 **C 实现的**——纯 Python 手写堆排与归并/快排同阶，别被数字误导
- 内置 `sorted` 是 C 写的 TimSort，最快

> 同复杂度算法，**实测速度差异来自"常数因子"与"是否 C 实现"**——大 O 描述趋势，不等于秒表排名。

## 七、近有序实测：插入排序逆袭

```python
data2 = sorted(random.randint(0, 9999) for _ in range(3000))
data2[-50:] = [random.randint(0, 9999) for _ in range(50)]   # 尾部打乱 50 个

t_ins = timeit.timeit(lambda: insertion_sort(data2), number=1)
t_q = timeit.timeit(lambda: quick_sort(data2), number=1)
print(f"近有序: 插入 {t_ins:.4f}s vs 快排 {t_q:.4f}s")
```
**本机实跑输出：**
```
近有序: 插入 0.0059s vs 快排 0.0195s
```
**近有序时插入排序 0.006s 反超快排 0.020s（快 ~3 倍）**——这就是 TimSort 在"几乎排好"的真实数据上快的原因。**没有万能排序，要看数据长相。**

## 八、排序稳定性与复杂度速查（面试问答模板）

```
Q: 快排为什么不稳定?
A: partition 会把相等的元素隔着哨兵换位（如 5a 5b 1，选1当哨兵…），
   相等元素相对顺序可能被打乱 → 不稳定

Q: 需要稳定排序用哪个?
A: 归并 / 插入 / 冒泡（Python sorted 也是稳定的 TimSort）

Q: 数据基本有序用哪个?
A: 插入排序（最好 O(n)）; 工程上 TimSort 自动检测

Q: 内存极紧（不能 O(n) 额外空间）?
A: 堆排 O(1) 空间、O(n log n) 时间（但 unstable）
```

## 九、小结

1. 三大 O(n²) 简单排序：**冒泡**（相邻交换）、**选择**（挑最小）、**插入**（理牌）
2. 三大 O(n log n) 进阶排序：归并（分治+合并）、快排（partition）、堆排（堆顶弹出）
3. **稳定**（冒泡/插入/归并）≠ **不稳定**（选择/快排/堆排）——多列排序靠稳定
4. **自适应**：冒泡/插入最好 O(n)，近有序数据插入排序实测反超快排
5. 实测：O(n log n) 组比 O(n²) 组快 ~67 倍（n=3000）；同阶比常数与是否 C 实现
6. 工程默认：Python `sorted`（稳定 TimSort）

## 十、练习 5 题

### 练习 1：手推冒泡一趟的结果

对 `[3, 0, 2, 5, 1]` 只执行第 1 趟冒泡（到末尾），写出数组。

**答案：** 相邻两两比较交换：3>0 换 → `[0,3,2,5,1]`；3>2 换 → `[0,2,3,5,1]`；3<5 不动；5>1 换 → `[0,2,3,1,5]`。**第1趟后 5 就位。**

### 练习 2：选择排序第 2 趟后数组

`[29, 10, 14, 37, 13]`，做两趟选择排序后数组是什么？

**答案：** 第1趟全段最小 10 → 换到 a[0] → `[10,29,14,37,13]`；第2趟在 `[29,14,37,13]` 找最小 13 → 与 a[1]=29 换 → `[10,13,14,37,29]`。

### 练习 3：判断稳定性

对 `[(1,'x'), (2,'a'), (2,'b')]` 用**选择排序**按第一键排，结果是？稳定吗？

**答案：** 第1趟找最小 (1,'x') 已在位；第2趟在 `[(2,'a'),(2,'b')]` 找最小，m 默认取 i 指向 (2,'a')，比较 j 的 (2,'b')：`2 < 2` 不成立 → 不换 → `[(1,'x'),(2,'a'),(2,'b')]` 恰好保持。但若数据是 `[(2,'a'),(2,'b'),(1,'x')]`：第1趟最小 (1,'x') 与 a[0]=(2,'a') 交换 → `[(1,'x'),(2,'b'),(2,'a')]`，**两个 2 顺序被破坏 → 不稳定**。结论：选择排序不稳定（相等键可能因"远距离交换"乱序）。

### 练习 4：给"几乎有序"的大数组选排序

100 万个数，99.9% 已有序，选哪种最快？为什么？

**答案：** **插入排序**（或其工程版 TimSort）。因为近乎有序时内层 while 几乎不执行，整体接近 O(n)；而快排/归并不管数据是否有序都照常 O(n log n) 全量跑。实测近有序 n=3000 时插入 0.006s 比快排 0.020s 快 3 倍，n 越大优势越明显。

### 练习 5：综合——手推归并排序的合并过程

归并排序在合并 `[2,4,7]` 与 `[1,3,9]` 时，写出每次取数的过程与最终结果。

**答案：** 1<2 取1 → 2<3 取2 → 3<4 取3 → 4<9 取4 → 7<9 取7 → 剩9 兜底 → **`[1,2,3,4,7,9]`**。手推：i、j 分别指向两段队头，每次取较小者，某段取完把另一段整体接上。
