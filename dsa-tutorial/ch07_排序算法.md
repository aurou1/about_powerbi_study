# ch07 排序算法

> 学习目标：手写冒泡/选择/插入/归并/快排/堆排；理解每种的复杂度与适用场景；用 `timeit` 看 O(n²) 和 O(n log n) 的真实差距。排序是「二分查找」和「TopK」的前置技能。

## 一、为什么要学这么多排序

排序是算法的「hello world」：它把「比较、交换、分治、堆」这些基础动作串起来。而且——**有序才能二分（ch08）、才能快速取中位数（ch10）**。SQL 的 `ORDER BY`、pandas 的 `sort_values`，底层都是这些算法。

## 二、三种 O(n²)：冒泡、选择、插入

### 2.1 冒泡排序（最直观，最慢）

相邻比大小，大的往后冒。每轮把当前最大沉底。

```python
def bubble_sort(a):
    a = a[:]; n = len(a)
    for i in range(n):
        for j in range(n - 1 - i):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
    return a
```

### 2.2 选择排序（每轮选最小放前面）

```python
def selection_sort(a):
    a = a[:]; n = len(a)
    for i in range(n):
        k = i
        for j in range(i + 1, n):
            if a[j] < a[k]: k = j
        a[i], a[k] = a[k], a[i]
    return a
```

### 2.3 插入排序（像摸牌理牌）

```python
def insertion_sort(a):
    a = a[:]
    for i in range(1, len(a)):
        key = a[i]; j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]; j -= 1
        a[j + 1] = key
    return a
```

验证它们都正确：

```python
data = [64, 34, 25, 12, 22, 11, 90, 5, 77, 33, 8, 50, 41, 60, 2]
print("冒泡正确:", bubble_sort(data) == sorted(data))
print("选择正确:", selection_sort(data) == sorted(data))
print("插入正确:", insertion_sort(data) == sorted(data))
```

**预期输出：**

```text
冒泡正确: True
选择正确: True
插入正确: True
```

## 三、三种 O(n log n)：归并、快排、堆排

### 3.1 归并排序（典型分治）

切两半各自排好，再「双指针」合并（和 ch03 合并链表同思路）。

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    L, R = merge_sort(a[:mid]), merge_sort(a[mid:])
    out = []; i = j = 0
    while i < len(L) and j < len(R):
        if L[i] <= R[j]:
            out.append(L[i]); i += 1
        else:
            out.append(R[j]); j += 1
    return out + L[i:] + R[j:]
```

### 3.2 快速排序（选基准，小的左大的右）

```python
def quick_sort(a):
    if len(a) <= 1:
        return a
    pivot = a[len(a) // 2]
    L = [x for x in a if x < pivot]
    M = [x for x in a if x == pivot]
    R = [x for x in a if x > pivot]
    return quick_sort(L) + M + quick_sort(R)
```

> 这个写法用了列表推导，清晰但占额外空间。工业版快排是「原地 partition」，省内存。平均 O(n log n)，最坏（已排序+选首尾做基准）退化 O(n²)——所以选**中间**或随机基准。

### 3.3 堆排序（用堆，ch10 细讲）

```python
def heap_sort(a):
    import heapq
    a = a[:]
    heapq.heapify(a)
    return [heapq.heappop(a) for _ in range(len(a))]
```

验证：

```python
print("归并正确:", merge_sort(data) == sorted(data))
print("快排正确:", quick_sort(data) == sorted(data))
print("堆排正确:", heap_sort(data) == sorted(data))
```

**预期输出：**

```text
归并正确: True
快排正确: True
堆排正确: True
```

## 四、实测计时：O(n²) 到底慢多少

```python
import timeit, random
random.seed(0)
big = [random.random() for _ in range(5000)]
for name, fn in [("归并", merge_sort), ("快排", quick_sort), ("堆排", heap_sort),
                 ("插入", insertion_sort), ("冒泡", bubble_sort)]:
    t = timeit.timeit(lambda: fn(big[:]), number=1)
    print(f"{name:4s} n=5000: {t:.4f}s")
```

**预期输出（机器不同秒数有差异，看倍数）：**

```text
归并   n=5000: 0.0117s
快排   n=5000: 0.0086s
堆排   n=5000: 0.0011s
插入   n=5000: 0.5911s
冒泡   n=5000: 1.1359s
```

> 重点看**阶**：归并/快排/堆排都是 O(n log n)，冒泡/插入是 O(n²)。n=5000 时**冒泡比归并慢约 97 倍**（1.14s vs 0.012s）。
> ⚠️ 注意「堆排最快」是因为我用了 C 实现的 `heapq`；归并/快排是纯 Python 写的列表操作。三者**算法复杂度是同阶** O(n log n)，这里快慢主要来自「C vs Python」的实现差异，不是阶的差异。面试比的是复杂度，不是谁用内置函数。

## 五、插入排序的反击：数据越有序越快

O(n²) 不代表永远菜。插入排序对「近乎有序」的数据只要 O(n)（几乎不搬）。

```python
nearly = list(range(5000))
nearly[1000], nearly[1001] = nearly[1001], nearly[1000]   # 只交换两个
t_ins = timeit.timeit(lambda: insertion_sort(nearly[:]), number=1)
t_q   = timeit.timeit(lambda: quick_sort(nearly[:]), number=1)
print(f"近乎有序 n=5000: 插入 {t_ins:.4f}s vs 快排 {t_q:.4f}s")
```

**预期输出：**

```text
近乎有序 n=5000: 插入 0.0005s vs 快排 0.0059s
```

> 插入排序比快排还快 10 倍！**工程启示：没有「最好的排序」，只有「最适合数据的排序」。** Python 的 `sorted()` 用的是 Timsort——融合「插入排序（小段）+ 归并（大段）」的混合算法，就是这个思想。

## 六、排序算法速查表

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(1) | 稳定 | 教学用，别上生产 |
| 选择 | O(n²) | O(n²) | O(1) | 不稳定 | 交换少，但永远慢 |
| 插入 | O(n²) | O(n²) | O(1) | 稳定 | 近乎有序时 O(n) |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 | 稳，但占额外空间 |
| 快排 | O(n log n) | O(n²) | O(log n) | 不稳定 | 平均最快，怕有序 |
| 堆排 | O(n log n) | O(n log n) | O(1) | 不稳定 | 原地，但缓存不友好 |

> **稳定** = 相等元素的相对顺序不变（排序前 a 在 b 前，排后还这样）。报表里「先按省排、再按金额排」常依赖稳定性。

## 小结

- O(n²) 三兄弟（冒泡/选择/插入）教学价值大，生产基本不用（除非数据很小或近乎有序）。
- O(n log n) 三兄弟（归并/快排/堆排）是主力，复杂度差 100 倍量级。
- 归并稳定占空间；快排平均最快但怕有序；堆排原地但缓存差。
- 真实排序（Timsort）是混合算法，按数据特征挑策略。

1. **（写）** 默写插入排序，对 `[5,2,4,6,1,3]` 手推前两轮，写出每轮后数组。
2. **（稳定）** 为什么归并排序稳定、快排不稳定？用「相等元素」举例说明。
3. **（优化）** 冒泡排序加一个「本轮没交换就提前结束」的 flag，对 `[1,2,3,4,5]` 能一轮结束。写一下并测。
4. **（复杂度）** 快排最坏 O(n²) 在什么数据下发生？怎么避免？
5. **（实战联想）** 你 `sql-tutorial` 里 `ORDER BY province, sales DESC`。这先用省排、再在省内按销售排——依赖排序的什么性质？（提示：稳定排序才能「省内顺序不被省排序打乱」）如果数据库用了不稳定排序会怎样？

**答案与解析**

1. 插入排序：第1轮把 2 插到 5 前 → `[2,5,4,6,1,3]`；第2轮把 4 插到 5 前 → `[2,4,5,6,1,3]`。
2. 归并合并时 `if L[i] <= R[j]` 用 `<=`，相等时取左半的，保持原序 → 稳定。快排按「基准」 partition，相等元素可能被分到两侧、相对顺序打乱 → 不稳定。
3.
   ```python
   def bubble_sort_opt(a):
       a = a[:]; n = len(a)
       for i in range(n):
           swapped = False
           for j in range(n-1-i):
               if a[j] > a[j+1]:
                   a[j], a[j+1] = a[j+1], a[j]; swapped = True
           if not swapped: break
       return a
   print(bubble_sort_opt([1,2,3,4,5]))   # 一轮就停
   ```
4. 最坏：数组已排序（或逆序）且总选「端点」做基准，每次只减少 1 个元素 → O(n²)。避免：选**中间元素或随机基准**，或小数组切到插入排序（Timsort 思路）。
5. 依赖**稳定排序**：先按省排（广东都挨着），再按销售降序排时，稳定排序保证「同省内的相对顺序由销售决定、且不会把不同省混进来」——其实这里两次独立排序更常见是 `ORDER BY province, sales DESC` 一次多列排序。若底层不稳定，相同省+相同销售的两行可能顺序乱，一般不影响数值结果，但分页/去重场景可能出问题。
