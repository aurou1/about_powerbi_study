# ch08 二分查找

> 学习目标：掌握二分查找的三个模板（精确找、找左边界、找右边界）；能处理旋转数组；理解「答案空间二分」——不只在数组里找，也能在数值范围里找。这是 O(log n) 的核心。

## 一、二分查找的前提：有序

ch01 说过二分只要约 `log₂n` 步。但它**要求数据有序**（或答案有单调性）。无序数组先排序（ch07），再二分。

## 二、模板一：精确查找

`lo <= hi`，命中即返回；没命中 `lo > hi` 退出返回 -1。

```python
def binary_search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

a = [1, 3, 5, 7, 9, 11, 13]
print("找 7:", binary_search(a, 7), "| 找 4:", binary_search(a, 4))
```

**预期输出：**

```text
找 7: 3 | 找 4: -1
```

> 找 7：mid=3（值7）命中。找 4：最后 `lo` 越过 `hi` 返回 -1。**每次砍掉一半，7 个元素最多 3 步**。

⚠️ 死循环陷阱：`mid = (lo+hi)//2` 当区间只剩两个元素且 `hi = mid - 1` 不收敛时可能死循环。本模板 `lo<=hi` 配合 `±1` 是安全的。

## 三、模板二/三：找边界（lower_bound / upper_bound）

真实业务常问「**第一个** ≥ target 的位置」（如「订单日期 ≥ 2024-01-01 的第一条」）。

```python
def lower_bound(a, target):
    lo, hi = 0, len(a)            # 注意 hi = len(a)，不是 -1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

b = [1, 3, 3, 3, 5, 7]
print("lower_bound(3):", lower_bound(b, 3), "| 第一个>=4:", lower_bound(b, 4))
```

**预期输出：**

```text
lower_bound(3): 1 | 第一个>=4: 4
```

> 区别：模板二用 `lo < hi` + `hi = mid`（不 `-1`），`hi` 初始化成 `len(a)`。返回的是「插入位置」。这正好是 `bisect_left` 的底层——Python 的 `bisect` 模块就是干这个的。

## 四、旋转排序数组（面试高频）

数组被「旋转」过（如 `[4,5,6,7,0,1,2]`），仍可用二分：每次至少有一半是有序的。

```python
def search_rotated(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[lo] <= a[mid]:                 # 左半有序
            if a[lo] <= target < a[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                              # 右半有序
            if a[mid] < target <= a[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1

r = [4, 5, 6, 7, 0, 1, 2]
print("旋转[4,5,6,7,0,1,2] 找0:", search_rotated(r, 0), "| 找3:", search_rotated(r, 3))
```

**预期输出：**

```text
旋转[4,5,6,7,0,1,2] 找0: 4 | 找3: -1
```

> 先判断哪一半有序，再判断 target 是否落在那一半，是就正常二分、否就搜另一半。依然是 O(log n)。

## 五、答案空间二分（最被低估的用法）

二分不只「在数组里找下标」，还能「在答案范围里找满足条件的最小值/最大值」。**只要答案有单调性**。

### 5.1 整数开平方

答案在 `[1, x]` 之间，且 `mid² ≤ x` 有单调性。

```python
def isqrt(x):
    if x < 2:
        return x
    lo, hi = 1, x
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= x:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi                       # hi 是最后一个满足 mid²<=x 的

print("isqrt(8)=", isqrt(8), "| isqrt(16)=", isqrt(16), "| isqrt(300)=", isqrt(300))
```

**预期输出：**

```text
isqrt(8)= 2 | isqrt(16)= 4 | isqrt(300)= 17
```

### 5.2 分书问题（最小化最大值）

k 个人连续分书，求「最长分配时长」的最小值。这是经典的「二分答案」。

```python
def min_max_pages(pages, k):
    def can(mx):                      # 单人上限 mx 时，能否 k 人装下
        groups, s = 1, 0
        for p in pages:
            if s + p > mx:
                groups += 1; s = p
            else:
                s += p
        return groups <= k
    lo, hi = max(pages), sum(pages)
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid): hi = mid
        else: lo = mid + 1
    return lo

print("分书 [1,2,3,4,5] 3人 最小最大:", min_max_pages([1, 2, 3, 4, 5], 3))
```

**预期输出：**

```text
分书 [1,2,3,4,5] 3人 最小最大: 6
```

> 3 人分 `[1,2,3,4,5]`：最优是 `[1,2,3]=6`、`[4]=4`、`[5]=5` → 最长 6。若上限设 5，`1+2+3=6>5` 要 4 组超了；设 6 刚好 3 组。**「能/不能」随上限单调，所以能二分**。

## 六、二分的两个易错点

1. **死循环**：`lo/hi` 更新没 `+1/-1` 或 `hi` 初值错。两个模板背熟一个就稳。
2. **溢出**：`(lo+hi)//2` 在 Python 不会溢出（整数无限大），但 Java/C++ 要写 `lo + (hi-lo)//2`。

## 小结

- 二分前提：有序或有单调性。复杂度 O(log n)。
- 精确找：`lo<=hi` + `±1`；边界找：`lo<hi` + `hi=mid`。
- 旋转数组：每次必有一半有序，判断 target 落哪半。
- 二分答案：在数值范围里找「满足条件的最值」，关键是写出 `can(mid)` 单调判断。

## 练习

1. **（精确）** 在 `[2,4,6,8,10,12]` 里二分找 8 和 5，写出每步 `lo/hi/mid`。
2. **（边界）** 用 `bisect` 模块重写下 `lower_bound`，并求 `bisect_right([1,3,3,3,5,7], 3)`。
3. **（旋转）** `[4,5,6,7,0,1,2]` 找 2 和 6，返回什么下标？手推一步验证。
4. **（二分答案）** 写 `min_eat_speed(piles, h)`：piles 是每堆香蕉数，h 小时内吃完，每小时吃 k 根（一堆吃不完留到下一小时），求最小 k。提示：can(k)=sum(ceil(p/h))<=h。测 `piles=[3,6,7,11], h=8`。
5. **（实战联想）** 你 `sql-tutorial` 里算「有效订单 2,366 单 / 销售额 7,195,492.73」。如果要找「销售额刚好 ≥ 某阈值的第一天」，用二分还是全扫？前提是按什么排好序？

**答案与解析**

1. 找 8：lo=0,hi=5,mid=2(6)<8→lo=3；mid=4(10)>8→hi=3；mid=3(8)==8 返回 3。找 5：mid=2(6)>5→hi=1；mid=0(2)<5→lo=1；mid=1(4)<5→lo=2；lo>hi 返回 -1。
2.
   ```python
   import bisect
   print(bisect.bisect_left([1,3,3,3,5,7], 3))    # 1
   print(bisect.bisect_right([1,3,3,3,5,7], 3))   # 4
   ```
   `bisect_left` = lower_bound；`bisect_right` 返回「插入到所有相等元素之后」的位置。
3. 找 2：命中 mid=5（值2）返回 5。找 6：a[lo]=4<=a[mid]，左半有序，target=6 在 [4,7] 内 → hi=mid-1 收缩到左半，最终在 mid=2（值6）命中返回 2。
4.
   ```python
   import math
   def min_eat_speed(piles, h):
       def can(k): return sum(math.ceil(p/k) for p in piles) <= h
       lo, hi = 1, max(piles)
       while lo < hi:
           mid = (lo+hi)//2
           if can(mid): hi = mid
           else: lo = mid+1
       return lo
   print(min_eat_speed([3,6,7,11], 8))   # 4
   ```
   k=4：ceil(3/4)+ceil(6/4)+ceil(7/4)+ceil(11/4)=1+2+2+3=8=h，刚好。
5. 用二分——但前提是**按日期（或累计销售额）排好序**。二分答案的前提是单调性：累计销售额随日期单调不减，所以「≥阈值的第一天」可用 lower_bound 在「累计销售额数组」上 O(log n) 找到，比全扫 O(n) 快。
