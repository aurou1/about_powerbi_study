# ch10 堆与优先队列

> 学习目标：理解堆（完全二叉树 + 父≤子）的本质；能手写 TopK、第 K 大、合并 K 个有序序列、数据流中位数。堆是「取最值」的最高频结构，也是 ch07 堆排序和 ch11 Dijkstra 的底层。

## 一、堆是什么

**堆**是一种完全二叉树，满足 **父节点 ≤ 子节点**（最小堆；最大堆反过来）。两个性质：
- 堆顶（根）永远是**最值**，`O(1)` 取。
- 插入/删除最值 `O(log n)`（树高 = log n）。
- 用数组存最省：`i` 的左孩子是 `2i+1`、右孩子 `2i+2`、父是 `(i-1)//2`。

Python 的 `heapq` 是**最小堆**。

```python
import heapq
a = [5, 2, 8, 1, 9, 3]
heapq.heapify(a)                       # 原地建堆 O(n)
print("堆顶:", a[0], "| 弹出:", [heapq.heappop(a) for _ in range(len(a))])
```

**预期输出：**

```text
堆顶: 1 | 弹出: [1, 2, 3, 5, 8, 9]
```

> 弹出顺序就是升序——堆排序（ch07）就是这么来的。`heapify` 之后数组**不是完全有序**，只是「堆顶最小」。

## 二、TopK 与第 K 大

### 2.1 最大的 K 个（一行）

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
print("最大3个:", heapq.nlargest(3, nums))
```

**预期输出：**

```text
最大3个: [9, 6, 5]
```

### 2.2 第 K 大（维护大小为 K 的最小堆）

只留 K 个元素，堆顶是当前第 K 大。新元素比堆顶大就替换。

```python
def kth_largest(nums, k):
    h = nums[:k]
    heapq.heapify(h)
    for x in nums[k:]:
        if x > h[0]:
            heapq.heapreplace(h, x)   # 弹出最小 + 压入 x
    return h[0]

print("第3大:", kth_largest(nums, 3), "| 第1大:", kth_largest(nums, 1))
```

**预期输出：**

```text
第3大: 5 | 第1大: 9
```

> 空间 O(k) 而非 O(n)，适合「流式数据 / 内存小」。**你 FDE 取数时「各省 Top 5 客户」就是这题**——ch02 用哈希分组后，每组用堆取 Top5。

## 三、合并 K 个有序序列

经典题：把 K 个有序链表/数组合成一个。每次从 K 个堆顶取最小。

```python
def merge_k(lists):
    h = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(h, (lst[0], i, 0))   # (值, 来源, 下标)
    out = []
    while h:
        val, i, j = heapq.heappop(h)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

print("合并K个 [[1,4,7],[2,5],[3,6]]:", merge_k([[1, 4, 7], [2, 5], [3, 6]]))
```

**预期输出：**

```text
合并K个 [[1,4,7],[2,5],[3,6]]: [1, 2, 3, 4, 5, 6, 7]
```

> 堆里同时放 K 个序列的「当前头」，`heappop` 取全局最小，再把那个序列的下一个压回。O(N log K)，N 是总元素数。

## 四、数据流中位数（双堆）

难点：数据一边来一边问中位数。诀窍：**两个堆**——`hi` 最小堆存较大的一半，`lo` 最大堆（存负数）存较小的一半，两堆大小差 ≤ 1。

```python
class MedianFinder:
    def __init__(self):
        self.lo = []          # 最大堆（负数）
        self.hi = []          # 最小堆
    def add(self, x):
        heapq.heappush(self.lo, -heapq.heappushpop(self.hi, x))
        if len(self.lo) > len(self.hi):
            heapq.heappush(self.hi, -heapq.heappop(self.lo))
    def median(self):
        if len(self.hi) > len(self.lo):
            return self.hi[0]
        return (self.hi[0] - self.lo[0]) / 2

mf = MedianFinder()
for x in [1, 3, 5, 7, 9]:
    mf.add(x)
    print(f"加入{x} 后中位数:", mf.median())
```

**预期输出：**

```text
加入1 后中位数: 1
加入3 后中位数: 2.0
加入5 后中位数: 3
加入7 后中位数: 4.0
加入9 后中位数: 5
```

> `heappushpop` 先压后弹，保证 x 进对的那一半。奇数个取 `hi[0]`（较小堆顶），偶数个取两堆顶平均。这是**实时统计中位数**的工业标准写法（监控系统 P50 延迟就用它）。

## 五、堆 vs 排序取头

| 需求 | 堆 | 先排序 |
|---|---|---|
| 只要 Top K | O(n log k) | O(n log n) |
| 数据在流里 | ✅ 边来边维护 | ❌ 得等全到 |
| 要全部排序 | ❌ 堆只保证堆顶 | ✅ |

## 小结

- 堆 = 完全二叉树，堆顶最值，插入/删 O(log n)；`heapq` 是最小堆。
- TopK / 第 K 大 / 合并 K 路 / 中位数 = 堆四大高频题。
- 双堆（最大堆 + 最小堆）处理「实时分位数」。
- ch07 堆排序、ch11 Dijkstra 都靠堆。

## 练习

1. **（TopK）** 写 `kth_smallest(nums, k)` 用堆求第 K 小（参考第 K 大，但用最大堆还是最小堆？）。测 `[3,1,4,1,5] k=2`。
2. **（堆）** 解释为什么 `heapq` 只提供最小堆——要「最大堆」怎么模拟？（提示：存负数）
3. **（合并）** `merge_k` 若 K 很大（比如 10 万个短序列），每次 `heappush` 的代价？有没有更省的？（提示：胜者树/多路归并，了解即可）
4. **（中位数）** 往 `MedianFinder` 加 `[2,4,6]`（偶数个），中位数应是多少？手算验证。
5. **（实战联想）** 你 `sql-tutorial` 里「每个省 TOP5 客户」。若客户有 50 万、只要前 5，用堆（O(n log 5)）还是全排序（O(n log n)）？哪个省？（提示：log 5 ≈ 2.3）

**答案与解析**

1.
   ```python
   def kth_smallest(nums, k):
       h = nums[:k]; heapq.heapify(h)         # 最小堆存前k小，堆顶是第k小
       for x in nums[k:]:
           if x < h[0]: heapq.heapreplace(h, x)
       return h[0]
   print(kth_smallest([3,1,4,1,5], 2))   # 3
   ```
   第 K 小：维护大小为 K 的**最大堆**（堆顶是最大，即第 K 小）；这里直接用最小堆存前 k 小也行，堆顶即答案。两种都 O(n log k)。
2. `heapq` 只给最小堆。要最大堆，把值取负存：`heapq.heappush(h, -x)`，取时 `-h[0]`。因为 Python 比较的是负数，最大的正数对应最小的负数 → 堆顶是负数最小的 = 原数最大的。
3. 每次压/弹 O(log K)，总 O(N log K)。更省的是「胜者树（loser tree）」，每个节点只比较一次，O(N log K) 但常数更小，外部排序（归并大文件）用。面试通常堆就够了。
4. `[1,3,5,7,9,2,4,6]` 排序后 `[1,2,3,4,5,6,7,9]` 中间两数 4 和 5，中位数 4.5。双堆：lo=[-4,-3,-2,-1]（最大堆，存小半 1,2,3,4），hi=[5,6,7,9]（最小堆，存大半），中位 (hi[0]-lo[0])/2 = (5+4)/2 = 4.5。
5. 用堆 O(n log 5) ≈ O(2.3n) 远胜全排序 O(n log n)（50 万时 log n ≈ 19）。**只取头部用堆**，这是大数据 TopN 的标准做法，数据库 `ORDER BY ... LIMIT 5` 内部也是类似思路（索引或堆）。
