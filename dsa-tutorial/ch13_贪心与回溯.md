# ch13 贪心与回溯

> 学习目标：区分「贪心」（每步选局部最优，简单但要对）和「回溯」（穷举所有选择再剪枝）；能手写区间调度、硬币找零、子集/排列、N 皇后。这是「组合优化」的两种主武器。

## 一、贪心：每步选当前最优

贪心算法：**每一步都做「看起来最好」的选择，不再回头**。简单、快（常 O(n log n)），但**只在问题有「贪心选择性质」时才正确**——错了不会报错，只是答案不对，所以要用前几个例子验证。

### 1.1 区间调度（最多不重叠会议）

选「结束最早」的会议，给后面留最多时间。

```python
def max_meetings(intervals):
    intervals.sort(key=lambda x: x[1])     # 按结束时间升序
    cnt, end = 0, -1
    for s, e in intervals:
        if s >= end:                        # 不冲突就选
            cnt += 1; end = e
    return cnt

print("最多会议 [[1,3],[2,4],[3,5],[5,7]]:", max_meetings([[1, 3], [2, 4], [3, 5], [5, 7]]))
```

**预期输出：**

```text
最多会议 [[1,3],[2,4],[3,5],[5,7]]: 3
```

> 选 [1,3]、[3,5]、[5,7] 共 3 个。若贪心选「开始最早」就错了。**按结束时间贪心**才有证明。你 FDE 排「会议室 / 机器档期」就是这个题。

### 1.2 硬币找零（规范币制下贪心正确）

```python
def coin_change_greedy(amount, coins):
    coins = sorted(coins, reverse=True)
    res = {}
    for c in coins:
        if amount >= c:
            res[c] = amount // c; amount %= c
    return res, amount

print("找零 63 (25,10,5,1):", coin_change_greedy(63, [25, 10, 5, 1]))
```

**预期输出：**

```text
找零 63 (25,10,5,1): ({25: 2, 10: 1, 1: 3}, 0)
```

> 2×25 + 1×10 + 3×1 = 63，硬币数最少。**但注意**：换成 `[10, 7, 1]` 找 14，贪心给 10+1+1+1=4 枚，而 7+7=2 枚更优 → 贪心失败，必须用 DP（ch12 思路）。所以「贪心对不对」取决于币制，不能想当然。

## 二、回溯：穷举 + 剪枝

当「所有组合都要试」时（子集、排列、N 皇后、路径），用**回溯**：递归地做选择，走到头就记录，不合适就撤销（undo），像走迷宫。

核心三步：**做选择 → 递归 → 撤销选择**（`path.append` / `back()` / `path.pop`）。

### 2.1 子集（所有组合）

```python
def subsets(nums):
    out = []
    def back(start, path):
        out.append(path[:])                 # 每个节点都是一个子集
        for i in range(start, len(nums)):
            path.append(nums[i])
            back(i + 1, path)
            path.pop()                      # 撤销
    back(0, [])
    return out

print("子集 [1,2,3] 共", len(subsets([1, 2, 3])), "个:", subsets([1, 2, 3]))
```

**预期输出：**

```text
子集 [1,2,3] 共 8 个: [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

> n 个元素有 2ⁿ 个子集（含空集）。`start` 参数保证不重复（每个数只从它之后选）。ch05 用哈希判重、这里用「起点」避免重复，**2ⁿ 是指数级，数据大就爆**——这是回溯的代价。

### 2.2 全排列

```python
def permutations(nums):
    out = []
    def back(path):
        if len(path) == len(nums):
            out.append(path[:]); return
        for x in nums:
            if x not in path:
                path.append(x); back(path); path.pop()
    back([])
    return out

print("全排列 [1,2,3] 共", len(permutations([1, 2, 3])), "个")
```

**预期输出：**

```text
全排列 [1,2,3] 共 6 个
```

> n! 种排列。用 `x not in path` 排除已用的。`x in path` 是 O(n)，大规模可用 `used` 布尔数组优化到 O(1)。

### 2.3 N 皇后（回溯 + 剪枝的经典）

8×8 棋盘放 8 个皇后，互相不攻击（不同行/列/对角线）。

```python
def solve_n_queens(n):
    res = []
    def back(row, cols, diag1, diag2, path):
        if row == n:
            res.append(path[:]); return
        for c in range(n):
            if c in cols or (row + c) in diag1 or (row - c) in diag2:
                continue                 # 剪枝
            cols.add(c); diag1.add(row + c); diag2.add(row - c); path.append(c)
            back(row + 1, cols, diag1, diag2, path)
            path.pop(); cols.discard(c); diag1.discard(row + c); diag2.discard(row - c)
    back(0, set(), set(), set(), [])
    return len(res)

print("N皇后 n=4 解数:", solve_n_queens(4), "| n=8:", solve_n_queens(8))
```

**预期输出：**

```text
N皇后 n=4 解数: 2 | n=8: 92
```

> 用 `cols`（列）、`diag1`（左上-右下对角线 `row+c`）、`diag2`（右上-左下 `row-c`）三个集合剪枝，冲突就 `continue` 不往下走。**剪枝是回溯的灵魂**——提前排除不可能，指数级才能压下来。

## 三、贪心 vs 回溯：怎么选

| | 贪心 | 回溯 |
|---|---|---|
| 思路 | 每步取最优，不回头 | 穷举所有选择 + 剪枝 |
| 复杂度 | 常 O(n log n) | 常指数 O(2ⁿ)/O(n!) |
| 正确性 | 需证明「贪心选择性质」 | 暴力穷举必对（慢但稳） |
| 适用 | 区间调度、最小生成树、Huffman | 子集/排列/组合/约束满足 |
| 风险 | 错了不报错，答案悄悄不对 | 数据大就超时 |

> 工程经验：**先想贪心，能证明就用；证明不了或要「所有解」，就回溯**；回溯太慢就加剪枝或转 DP。

## 小结

- 贪心：局部最优，简单快，但要对「贪心性质」负责。
- 区间调度按结束时间贪心；规范币制硬币找零贪心，奇葩币制要 DP。
- 回溯 = 选择→递归→撤销，子集/排列/N 皇后通用骨架。
- 剪枝让指数级回溯变可行；选贪心还是回溯看能否证明。

## 练习

1. **（贪心）** 区间调度若改成「按开始时间升序贪心」，对 `[[1,5],[2,3],[4,6]]` 会选几个？和按结束时间比哪个对？（手推）
2. **（贪心失败）** 币制 `[10,7,1]` 找 14，贪心给几枚？最优几枚？
3. **（回溯）** 写 `combine(candidates, target)`：candidates 可重复使用，凑出和为 target 的所有组合（LeetCode 39）。测 `combine([2,3,6,7], 7)`。
4. **（回溯）** 写 `combination_sum_k` 的「每个数最多用一次」版（类似 0/1 背包枚举），和上面区别在哪？
5. **（实战联想）** 你 `python-tutorial` 里「列出所有客户等级组合」或 FDE「给客户搭方案时枚举可选模块」——这是子集还是排列问题？为什么？

**答案与解析**

1. 按开始时间：`[1,5]` 先选→`[2,3]` 冲突跳过→`[4,6]` 冲突（4<5）跳过，只 1 个。按结束时间：`[2,3]`→`[4,6]` 共 2 个。**按结束时间对**。说明「开始时间贪心」不满足贪心性质。
2. 贪心 `[10,7,1]` 找 14：10 + 1+1+1 = 4 枚。最优 7+7 = 2 枚。→ 贪心错，需 DP。
3.
   ```python
   def combine(candidates, target):
       out = []
       def back(start, path, s):
           if s == target: out.append(path[:]); return
           if s > target: return
           for i in range(start, len(candidates)):
               path.append(candidates[i]); back(i, path, s+candidates[i]); path.pop()
       back(0, [], 0)
       return out
   print(combine([2,3,6,7], 7))   # [[2,2,3], [7]]
   ```
   用 `start=i` 允许重复使用同一元素。注意 candidates 要先排序才能剪枝（`s>target` 早停）。
4. 「每个数最多用一次」把 `back(i, ...)` 改成 `back(i+1, ...)`（不回头取同一个），并跳过重复值。本质枚举子集看哪些和=target，等价于背包的「枚举所有选法」。
5. 是**子集**问题（不是排列）：方案 `{模块A, 模块C}` 和 `{模块C, 模块A}` 是同一个方案，顺序不重要。组合数 = 选/不选每个模块的 2ⁿ 种；若顺序也重要（如操作步骤先后）才是排列。
