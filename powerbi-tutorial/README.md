# Power BI 零基础 → 进阶高手教程

一份写给「要真上手干活的人」的 Power BI 教程，共 12 章。

配套数据库：`study_powerbi_demodata`（电商订单星型模型，共 15,780 行）。**所有示例都用这套数据，能跑出真实数字**，你可以拿 SQL 算一遍、再用 DAX 复现对拍。

---

## 一、这份教程的定位

| 它是什么 | 它不是什么 |
|---|---|
| 讲**为什么**、**怎么做**、**什么时候用** | 不是功能菜单说明书 |
| 每章有可复现的示例 + 带预期结果的练习 | 不是「点击这里、再点击那里」的截图流水账 |
| 站在**交付者视角**（数据对不对、口径怎么定、上线后怎么维护） | 不是考证题库 |

**特别适合**：制造业 / 业务岗转数据分析、甲方 IT、需要给客户交付报表的实施顾问（FDE）。你已经会一点 SQL，想把数据变成别人能看懂、能自助查看的报表。

**不适合**：只想拖拖拽拽做张图、不关心口径对错的人。

## 七、八条统一口径（全教程一致，不许出现第二种说法）

| # | 口径 | 具体值 |
|---:|---|---|
| 1 | 品牌名 | 正文一律 `Power BI`（带空格） |
| 2 | **毛利率默认成交口径** | 数码 1.16% < 食品 21.75% < 家居 27.22% < 服饰 38.00% < 美妆 49.47% |
| 3 | 吊牌口径毛利率（仅讲定价逻辑时用） | 数码 12% / 食品 30% / 家居 35% / 服饰 45% / 美妆 55% |
| 4 | 数据规模 | **15,780 行**（维度 1,806 + 事实 11,974） |
| 5 | **金额取数** | 写 **SQL** 用 `fact_order.order_amount`；写 **DAX** 用 `fact_order_item.line_amount`；**两者不要同时求和** |
| 6 | **有效销售** | 必须 `status = '已完成'`（2,366 单 / 7,195,492.73 元）。已取消 591 + 退款 572 = 1,163 单的金额仍在表里 |
| 7 | 客户等级 | 人数 241/149/83/27；每客订单数 普通4/银卡6/金卡12/钻石25；折扣 0.02/0.08/0.15/0.20 |
| 8 | 术语 | 度量值、视觉对象、切片器、矩阵、筛选上下文、时间智能、环比/同比、星型模型 |

**数据局限（教程不出这类题）**：

- 无跨省下单（`dim_customer.region_id` 与 `fact_order.region_id` 同源）
- `unit_price` 恒等于 `list_price`，**无价格随时间变化**
- 无库存 / 渠道 / 退货表
- `dim_date` 止于 2025-12-31，超出后时间智能返回空白

## 八、关于练习题

每章末尾 3-5 题，**全部附完整答案 + 逐步解析 + 预期结果数字**。

用法建议：

1. 先自己写，写在 Power BI 里跑
2. 卡住再看提示（题目下方有 Hint）
3. 跑出数字后和「预期结果」对拍
4. 对不上就按「解析」一步步查

> 数字对不上**不是失败**，是最有价值的学习时刻 —— 通常意味着你对筛选上下文的理解还差一层。

## 九、常见故障速查

| 现象 | 原因 / 解决 |
|---|---|
| 报「需要 ODBC 驱动」 | 没装或装了 32 位 → 重装 64 位 MySQL Connector/ODBC |
| 连超时 / 连不上 | MySQL 没启动、端口不是 3306、防火墙挡了 |
| 中文显示为问号 | 连接字符集不是 utf8mb4；ODBC 里设 `charset=utf8mb4` |
| 时间智能函数返回空白 | `dim_date` 没标记为日期表（ch02） |
| 金额翻倍 | 同时求和了 `fact_order` 和 `fact_order_item`（口径 5） |
| 销售额虚高 47% | 没过滤 `status='已完成'`（口径 6） |
| RANKX 全是 1 | 排名范围没用 `ALL(...)`（ch07） |
| 占比合计不是 100% | 用了 `ALL` 但被切片器截断（ch06） |
