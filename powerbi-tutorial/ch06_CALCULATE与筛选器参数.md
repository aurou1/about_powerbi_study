# ch06 CALCULATE 与筛选器参数 ⚡

> 本章目标：掌握 DAX 里**唯一能修改筛选上下文**的函数 `CALCULATE`，以及配套的 ALL 家族。

## 二、CALCULATE 为什么是 DAX 之王

Power BI 社区有一句话：

> **「如果 DAX 只能留一个函数，那就是 `CALCULATE`。」**

原因：**它是唯一能修改筛选上下文的函数。**

回顾 ch05：筛选上下文由矩阵行列、切片器、筛选器窗格共同决定，度量值只能"被动接受"。

`CALCULATE` 打破了这个限制 —— 它能在**度量值内部主动改变筛选**，从而算出：

| 你想算什么 | 需要怎么做 | 没有 CALCULATE |
|---|---|---|
| 华东销售额 | 在任意格子里强制筛"华东" | 做不到（只能靠切片器） |
| 各品类占全网比例 | 分子按品类筛，分母**去掉品类筛选** | 做不到 |
| 已完成订单占比 | 强制筛 status='已完成' | 做不到 |
| 去年同期 | 把日期筛选**平移一年** | 做不到（时间智能全靠它） |

**语法**：

```dax
CALCULATE(表达式, 筛选器1, 筛选器2, ...)
```

例如 ch04 就一直在用：

```dax
有效销售额 =
CALCULATE(
    SUM('fact_order_item'[line_amount]),   -- 表达式
    'fact_order'[status] = "已完成"         -- 筛选器参数
)
```

## 三、CALCULATE 的求值四步（必背）

理解这四步，你就不会再被 CALCULATE 的"诡异"行为困扰。

```
CALCULATE(表达式, 筛选器)
```

**第 1 步：复制当前筛选上下文**
把外部的筛选上下文原样复制一份作为起点。

**第 2 步：计算筛选器参数**
⚠️ **关键**：筛选器参数是在**第 1 步复制的旧上下文**里求值的，不是在新上下文里。

**第 3 步：生成新的筛选上下文**
用第 2 步的结果，对旧上下文做**覆盖或追加**（见第 5 节），得到新上下文。

**第 4 步：在新上下文中求值表达式**
执行第 1 个参数（表达式）。

### 3.1 一个具体例子

假设报表上矩阵行是「广东」，你写了：

```dax
华东销售额 = CALCULATE([有效销售额], 'dim_region'[zone] = "华东")
```

| 步骤 | 发生什么 |
|---|---|
| 1 | 复制上下文：`省份 = 广东` |
| 2 | 计算筛选器 `'dim_region'[zone]="华东"` → 得到筛选条件 `大区 = 华东` |
| 3 | **覆盖**：`大区 = 华东` 与 `省份 = 广东` 涉及**不同列**（zone 和 province_name）→ 实际是追加，得到 `省份=广东 AND 大区=华东` |
| 4 | 求值 → 结果是**空**（广东属于华南，不属于华东） |

**这个结果常常让人意外**：明明写了"华东"，在广东行却显示空白 —— 因为省份筛选还在。

**想真正强制只看华东**（忽略行上的省份），要用 `ALL`：

```dax
华东销售额_强制 = CALCULATE([有效销售额], 'dim_region'[zone] = "华东", REMOVEFILTERS('dim_region'[province_name]))
```

或更彻底：

```dax
华东销售额_强制2 = CALCULATE([有效销售额], 'dim_region'[zone] = "华东", REMOVEFILTERS('dim_region'))
```

## 四、筛选器参数的两种写法

### 4.1 写法一：布尔筛选（简单条件）

```dax
CALCULATE([有效销售额], 'dim_region'[zone] = "华东")
```

**优点**：简洁、性能好、可读。

**限制**：只能写**最简单的形式**：

| 能写 | 不能写 |
|---|---|
| `'表'[列] = 常量` | `'表'[列] = 另一个列` |
| `'表'[列] <> 常量` | `'表'[列] = 度量值` |
| `'表'[列] > 常量` | 涉及多列的复杂条件 |

**背后的机制**（重要）：

布尔筛选 `'dim_region'[zone] = "华东"` 会被 DAX **自动改写**成：

```dax
FILTER(ALL('dim_region'[zone]), 'dim_region'[zone] = "华东")
```

注意那个 **`ALL`** —— 它意味着：**该列上原有的筛选会被清除**。

这就是为什么布尔筛选的行为是"覆盖"而不是"追加"。

### 4.2 写法二：表筛选（FILTER 函数）

```dax
CALCULATE(
    [有效销售额],
    FILTER('dim_region', 'dim_region'[zone] = "华东")
)
```

**优点**：可以写任意复杂条件，包括多列、跨表、引用度量值。

**行为**：`FILTER` 返回一张**表**，这张表作为筛选条件。它**不会自动清除原有的列筛选**，所以通常与现有筛选**取交集**（追加）。

### 4.3 两者对比

| | 布尔筛选 | FILTER 表筛选 |
|---|---|---|
| 写法 | `'表'[列] = 值` | `FILTER('表', 条件)` |
| 复杂度 | 只能简单条件 | 任意复杂条件 |
| 是否清除该列原有筛选 | **会**（内部有 `ALL`） | **不会**（取交集） |
| 性能 | 好（走存储引擎优化） | 差（要逐行迭代） |
| 适用场景 | 90% 的日常需求 | 复杂条件、多列判断 |

> ⚠️ **踩坑提醒**：**能用布尔筛选就用布尔筛选。** `FILTER(整张事实表, ...)` 是性能杀手（ch10 会实测）。
> 只有当你需要"逐行判断是否满足条件"时（比如 `FILTER('fact_order_item', [line_amount] > [line_cost] * 2)`）才不得不用。

### 4.4 布尔筛选的等价写法对照

这几种写法**结果相同**：

```dax
-- 写法 1：布尔（推荐）
CALCULATE([有效销售额], 'dim_region'[zone] = "华东")

-- 写法 2：显式 FILTER + ALL（等价展开）
CALCULATE([有效销售额], FILTER(ALL('dim_region'[zone]), 'dim_region'[zone] = "华东"))

-- 写法 3：用整表
CALCULATE([有效销售额], FILTER(ALL('dim_region'), 'dim_region'[zone] = "华东"))
```

而这两种**不同**（不会清除其他列的筛选）：

```dax
CALCULATE([有效销售额], FILTER('dim_region', 'dim_region'[zone] = "华东"))
CALCULATE([有效销售额], FILTER(VALUES('dim_region'), 'dim_region'[zone] = "华东"))
```

## 五、覆盖 vs 追加（同名列覆盖，异名列追加）

当 `CALCULATE` 的新筛选与已有筛选冲突时：

| 情况 | 行为 | 结果 |
|---|---|---|
| **同一列**有筛选 | **覆盖**（新的替换旧的） | 只保留新条件 |
| **不同列**有筛选 | **追加**（AND 叠加） | 两个条件同时生效 |

### 5.1 覆盖的例子

报表上切片器选了 `省份 = 广东`，你写：

```dax
测试_覆盖 = CALCULATE([有效销售额], 'dim_region'[province_name] = "浙江")
```

- 原筛选：`省份 = 广东`
- 新筛选：`省份 = 浙江`（**同一列**）
- 结果：**覆盖** → 只看浙江，得到 **849,660.63**

### 5.2 追加的例子

报表上切片器选了 `省份 = 广东`，你写：

```dax
测试_追加 = CALCULATE([有效销售额], 'dim_product'[category] = "数码")
```

- 原筛选：`省份 = 广东`
- 新筛选：`品类 = 数码`（**不同列**）
- 结果：**追加** → `省份=广东 AND 品类=数码`

### 5.3 想强制清除某个筛选：用 REMOVEFILTERS / ALL

```dax
-- 清除省份筛选，只看数码全网的销售额
数码全网销售额 =
CALCULATE(
    [有效销售额],
    'dim_product'[category] = "数码",
    REMOVEFILTERS('dim_region')      -- 清除地区维度的所有筛选
)
```

## 六、ALL 家族全家福

| 函数 | 作用 | 典型用途 |
|---|---|---|
| `ALL(表)` | 清除**整张表**的所有筛选 | 算"占全网比例"的分母 |
| `ALL(列)` | 清除**某一列**的筛选 | 只去掉一个维度，保留其他 |
| `ALLEXCEPT(表, 列1, 列2...)` | 清除表上**除指定列外**的所有筛选 | 保留某几个维度，清掉其他 |
| `ALLSELECTED(表/列)` | 清除筛选，但**保留切片器的选择** | 算"占当前所选范围的比例" |
| `REMOVEFILTERS(表/列)` | 与 `ALL` 同义，但**不能返回表** | 专用于 CALCULATE 的筛选器参数（语义更清晰） |
| `KEEPFILTERS(筛选器)` | 让筛选**追加而非覆盖** | 保留用户原有选择 |

### 6.1 `ALL` vs `REMOVEFILTERS`：该用哪个

**功能上等价**（作为 CALCULATE 的筛选器参数时），区别在语义：

```dax
CALCULATE([有效销售额], ALL('dim_region'))            -- 能
CALCULATE([有效销售额], REMOVEFILTERS('dim_region'))  -- 能，语义更清晰
```

**推荐**：作为 `CALCULATE` 参数时用 `REMOVEFILTERS`（一眼能看出"这是要清除筛选"）；需要返回表做迭代时用 `ALL`。

## 七、实战：算占比（ALL vs ALLSELECTED）

这是本章最实用的部分，也是**面试和实战都高频**的考点。

### 7.1 需求：各大区销售额占全网比例

```dax
销售额占比_ALL =
DIVIDE(
    [有效销售额],
    CALCULATE([有效销售额], ALL('dim_region'))
)
```

**预期结果**：

| 大区 | 销售额 | 占全网 |
|---|---:|---:|
| 华东 | 3,138,680.06 | 43.62% |
| 华南 | 1,078,152.70 | 14.98% |
| 华北 | 761,942.54 | 10.59% |
| 华中 | 700,373.18 | 9.73% |
| 西南 | 562,613.26 | 7.82% |
| 东北 | 517,676.34 | 7.19% |
| 西北 | 436,054.65 | 6.06% |
| **合计** | **7,195,492.73** | **100.00%** |

分母恒等于 **7,195,492.73**（全网有效销售额），因为 `ALL('dim_region')` 清除了地区维度的所有筛选。

**合计正好 100%** ✅

### 7.2 需求：切片器选中"华东"后，看各省占华东的比例

现在你在报表上加一个「大区」切片器，选**华东**。矩阵行是省份。

**用 `ALL`（错误的结果）**：

| 省份 | 销售额 | 占全网（ALL 口径） |
|---|---:|---:|
| 浙江 | 849,660.63 | 11.81% |
| 上海 | 816,614.17 | 11.35% |
| 江苏 | 800,322.96 | 11.12% |
| 山东 | 672,082.30 | 9.34% |
| **合计** | **3,138,680.06** | **43.62%** ❌ |

**百分比加起来只有 43.62%，不是 100%！** 因为分母用的还是全网。

**用 `ALLSELECTED`（正确）**：

```dax
销售额占比_ALLSELECTED =
DIVIDE(
    [有效销售额],
    CALCULATE([有效销售额], ALLSELECTED('dim_region'))
)
```

| 省份 | 销售额 | 占华东（ALLSELECTED 口径） |
|---|---:|---:|
| 浙江 | 849,660.63 | 27.07% |
| 上海 | 816,614.17 | 26.02% |
| 江苏 | 800,322.96 | 25.50% |
| 山东 | 672,082.30 | 21.41% |
| **合计** | **3,138,680.06** | **100.00%** ✅ |

分母变成了 **3,138,680.06**（华东合计），因为 `ALLSELECTED` **保留了切片器的选择**（华东），只清除了矩阵行上的省份筛选。

### 7.3 两者区别总结

| | `ALL` | `ALLSELECTED` |
|---|---|---|
| 清除什么 | **所有**筛选（包括切片器） | 清除视觉对象内部的筛选，**保留切片器的选择** |
| 分母 | 恒为全网 7,195,492.73 | 当前切片器选中的范围 |
| 百分比合计 | 可能 < 100% | **恒为 100%** |
| 适用场景 | "占全网比例"（绝对份额） | "占当前所选范围的比例"（内部结构） |

> ⚠️ **踩坑提醒**：业务方说"我要看占比"时，**一定要问清楚分母是什么**：
> - "各省占全国的份额" → 用 `ALL`（分母 = 全网），各省加起来 = 100%
> - "我筛了华东，看华东内部各省怎么分" → 用 `ALLSELECTED`（分母 = 华东），华东内部加起来 = 100%
>
> 用错了不会报错，只是百分比"看起来不对" —— 这类错误最容易蒙混过关，然后被业务方当场抓包。

**验证 SQL**：

```sql
-- ALL 口径：各省占全网
SELECT r.province_name AS 省,
       ROUND(SUM(o.order_amount),2) AS 销售额,
       ROUND(SUM(o.order_amount)*100/(SELECT SUM(order_amount)
             FROM fact_order WHERE status='已完成'),2) AS 占全网pct
FROM fact_order o JOIN dim_region r ON o.region_id=r.region_id
WHERE o.status='已完成' GROUP BY r.province_name ORDER BY 销售额 DESC;

-- ALLSELECTED 口径：华东内部各省
SELECT r.province_name AS 省,
       ROUND(SUM(o.order_amount),2) AS 销售额,
       ROUND(SUM(o.order_amount)*100/(SELECT SUM(o2.order_amount)
             FROM fact_order o2 JOIN dim_region r2 ON o2.region_id=r2.region_id
             WHERE o2.status='已完成' AND r2.zone='华东'),2) AS 占华东pct
FROM fact_order o JOIN dim_region r ON o.region_id=r.region_id
WHERE o.status='已完成' AND r.zone='华东'
GROUP BY r.province_name ORDER BY 销售额 DESC;
```

## 八、KEEPFILTERS：让筛选变成"取交集"

默认情况下，`CALCULATE` 的布尔筛选会**覆盖**同列的原有筛选。`KEEPFILTERS` 可以改变这个行为。

```dax
-- 不加 KEEPFILTERS：覆盖（用户选"已取消"也会被强行改成"已完成"）
强制已完成 = CALCULATE([有效销售额], 'fact_order'[status] = "已完成")

-- 加 KEEPFILTERS：取交集（用户选"已取消" → 空集）
尊重用户选择 = CALCULATE([有效销售额], KEEPFILTERS('fact_order'[status] = "已完成"))
```

**行为对比**（假设用户在切片器选了「已取消」）：

| 写法 | 结果 |
|---|---|
| 不加 `KEEPFILTERS` | 强行筛"已完成" → 显示 7,195,492.73（**无视用户选择**） |
| 加 `KEEPFILTERS` | `已完成 AND 已取消` = 空集 → 显示**空白** |

**什么时候用**：

- 你希望度量值**尊重用户的切片器选择** → 加 `KEEPFILTERS`
- 你希望度量值**强制使用自己的口径**（比如"有效销售额"这个指标定义上就是只算已完成） → 不加

**本库的选择**：`有效销售额` 应该**不加** `KEEPFILTERS`，因为它是"定义性"的口径 —— 无论用户怎么选，有效销售额就是只算已完成。这是**刻意的设计**，不是 bug。

## 九、常见错误速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 百分比合计不是 100% | 用了 `ALL` 但想算"占所选比例" | 改 `ALLSELECTED` |
| 百分比恒为 100% | 分子分母都清除了筛选 | 分子不要加 `ALL` |
| 数字不随切片器变化 | `ALL` 清除了切片器筛选 | 用 `ALLSELECTED` 或 `ALLEXCEPT` 保留 |
| 加了筛选条件反而变空白 | 追加条件导致交集为空 | 检查是否需要 `REMOVEFILTERS` |
| `FILTER` 很慢 | 迭代了整张事实表 | 改用布尔筛选，或 `FILTER(维度表, ...)` |
| 计算列里 `CALCULATE` 结果奇怪 | 触发了上下文转换 | 见 ch05 第 8 节 |

## 十、FDE 现场场景

### 场景 1：客户要"占比"，但没说分母

**这是最高频的需求歧义。** 处理模板：

> "您要的占比，分母是**全部**，还是**当前筛选出来的这部分**？
> 比如您筛了华东，那浙江应该显示 27%（占华东）还是 11.8%（占全国）？"

给出**具体数字**让客户选，比讲概念有效一百倍。

**然后建议**：

- 市场份额类分析 → 用 `ALL`（看绝对份额，跨筛选可比较）
- 结构分析（这个区域内部怎么构成）→ 用 `ALLSELECTED`（合计必然 100%，好看）

**可以在报表上同时提供两个**，用不同颜色标注，让业务方自己看。

### 场景 2：报表上有多个切片器，占比怎么算都对不上

典型症状：用户选了「2024年 + 华东 + 数码」，然后占比数字看起来很怪。

**排查清单**：

1. 分母用了 `ALL(整张表)` 还是 `ALL(列)`？—— `ALL(表)` 会清掉该表**所有列**的筛选，可能清过头
2. 是否该用 `ALLEXCEPT` 保留某些维度？
3. 有没有日期筛选被 `ALL('dim_date')` 清掉了（导致分母变成三年总和）？

**最常见的错误**：

```dax
-- 错误：ALL('dim_date') 把年份筛选也清了，分母变成 2023-2025 三年总和
占比 = DIVIDE([有效销售额], CALCULATE([有效销售额], ALL('dim_date')))

-- 正确：只清除日期表里的"月"这一列，保留年份筛选
YTD内各月占比 = DIVIDE([有效销售额], CALCULATE([有效销售额], ALLEXCEPT('dim_date', 'dim_date'[year])))
```

> 这个错误的表现是：**选 2024 年看月度占比，1 月显示的比例特别小**（因为分母包含了 2023 和 2025）。

### 场景 3：客户说"这个数应该随切片器变，怎么不变"

**原因**：度量值里用了 `ALL`，把切片器的筛选也清了。

**判断依据**：

| 客户期望 | 该用什么 |
|---|---|
| 分母固定不变（如"占全网"） | `ALL` |
| 分母随切片器变（如"占当前所选"） | `ALLSELECTED` |

**沟通话术**：

> "这个占比的分母现在是**全网**。如果您希望它跟着上面的筛选走，我改成'占当前所选范围'，两分钟就好。"

| 你学到了 | 关键点 |
|---|---|
| CALCULATE 地位 | **唯一能修改筛选上下文的函数** |
| 求值四步 | 复制上下文 → 算筛选器（**在旧上下文**）→ 生成新上下文 → 求值 |
| 布尔筛选 | `'列' = 值`，内部等价 `FILTER(ALL(列), ...)`，**会清除该列原筛选** |
| FILTER 表筛选 | 可写复杂条件，**取交集不清除**，但性能差 |
| 覆盖 vs 追加 | **同列覆盖，异列追加** |
| ALL 家族 | `ALL` 清全部、`ALLEXCEPT` 保留指定、`ALLSELECTED` 保留切片器、`KEEPFILTERS` 强制交集 |
| **ALL vs ALLSELECTED** | ALL 分母恒为 **7,195,492.73**；ALLSELECTED 分母为当前所选（华东 **3,138,680.06**） |
| 占比验证 | ALL 口径华东四省合计 43.62%；ALLSELECTED 口径合计 **100%** |

## 十二、练习题

### 练习 1：华东销售额的两种写法（考：布尔 vs FILTER）

**题目**：分别用布尔筛选和 `FILTER` 写出「华东大区有效销售额」，拖进按**省份**的矩阵里，观察两者差异并解释。

```dax
华东_布尔 = CALCULATE([有效销售额], 'dim_region'[zone] = "华东")

华东_FILTER =
CALCULATE([有效销售额], FILTER('dim_region', 'dim_region'[zone] = "华东"))
```

**预期结果**：

| 省份 | 华东_布尔 | 华东_FILTER |
|---|---:|---:|
| 浙江 | 849,660.63 | 849,660.63 |
| 上海 | 816,614.17 | 816,614.17 |
| 江苏 | 800,322.96 | 800,322.96 |
| 山东 | 672,082.30 | 672,082.30 |
| 广东 | **空白** | **空白** |
| 四川 | **空白** | **空白** |

**解析**：

本例中两者结果相同，但原因不同：

- **布尔**：`zone="华东"` 清除 zone 列原筛选，加上 `zone=华东`；但矩阵行是 `province_name`（**不同列**），省份筛选保留 → `省份=浙江 AND 大区=华东` = 浙江的数据；广东行 → `广东 AND 华东` = 空集 = 空白
- **FILTER**：保留 `dim_region` 表上所有列的筛选，与 `zone=华东` 取交集 → 同样的结果

**但如果矩阵行是大区而不是省份**，两者就有区别了：

| 矩阵行（大区） | 华东_布尔 | 华东_FILTER |
|---|---:|---:|
| 华东 | 3,138,680.06 | 3,138,680.06 |
| 华南 | **3,138,680.06** ❌ | **空白** ✅ |

**关键差异**：

- 布尔筛选在华南行会**覆盖**掉 `zone=华南`，强行显示华东的数字（3,138,680.06）
- `FILTER` 保留原有 `zone=华南`，与华东取交集 = 空 = 空白

> **哪个"对"取决于你的意图**：
> - 想做"华东 vs 各区对比"的固定基准线 → 用布尔（每行都显示华东，方便对比）
> - 想让筛选自然生效 → 用 `FILTER`

**验证 SQL**：

```sql
SELECT ROUND(SUM(o.order_amount),2) AS 华东销售额
FROM fact_order o JOIN dim_region r ON o.region_id=r.region_id
WHERE o.status='已完成' AND r.zone='华东';
-- 预期：3138680.06
```

### 练习 2：占所选省份比（考：ALL vs ALLSELECTED，高频）

**题目**：加一个「大区」切片器，选**华东**。建两个占比度量值，观察差异：

```dax
占比_ALL = DIVIDE([有效销售额], CALCULATE([有效销售额], ALL('dim_region')))

占比_ALLSELECTED = DIVIDE([有效销售额], CALCULATE([有效销售额], ALLSELECTED('dim_region')))
```

**预期结果**（切片器选中「华东」时）：

| 省份 | 销售额 | 占比_ALL | 占比_ALLSELECTED |
|---|---:|---:|---:|
| 浙江 | 849,660.63 | 11.81% | **27.07%** |
| 上海 | 816,614.17 | 11.35% | **26.02%** |
| 江苏 | 800,322.96 | 11.12% | **25.50%** |
| 山东 | 672,082.30 | 9.34% | **21.41%** |
| **合计** | 3,138,680.06 | **43.62%** ❌ | **100.00%** ✅ |

**解析**：

- `ALL` 分母 = **7,195,492.73**（全网），所以四省加起来只有 43.62%
- `ALLSELECTED` 分母 = **3,138,680.06**（华东，保留了切片器选择），所以合计 = 100%

**什么时候用哪个**：

| 业务问题 | 用哪个 | 分母 |
|---|---|---|
| 浙江在全国占多大份额？ | `ALL` | 7,195,492.73 |
| 华东内部，哪个省贡献最大？ | `ALLSELECTED` | 3,138,680.06 |

**答案**：看"内部结构"用 `ALLSELECTED`，看"绝对份额"用 `ALL`。

### 练习 3：让筛选覆盖生效（考：CALCULATE 覆盖行为）

**题目**：在报表上放一个 `status` 切片器，选「已取消」。然后建两个度量值：

```dax
-- A：不加 KEEPFILTERS
有效销售额_强制 = CALCULATE([有效销售额], 'fact_order'[status] = "已完成")

-- B：加 KEEPFILTERS
有效销售额_尊重 = CALCULATE([有效销售额], KEEPFILTERS('fact_order'[status] = "已完成"))
```

观察结果并解释。

**预期结果**（切片器选「已取消」时）：

| 度量值 | 结果 | 原因 |
|---|---:|---|
| 有效销售额_强制 | **7,195,492.73** | 布尔筛选**覆盖**了切片器的"已取消"，强行筛已完成 |
| 有效销售额_尊重 | **空白** | `KEEPFILTERS` 取交集：`已完成 AND 已取消` = 空集 |

**解析**：

这个练习揭示了 `CALCULATE` 最关键的行为差异：

- **默认（覆盖）**：度量值"说了算"，不管用户选什么
- **KEEPFILTERS（交集）**：用户"说了算"，度量值只在用户选择范围内生效

**本库该怎么选**：

`有效销售额` 应该用**默认（不加 KEEPFILTERS）**。因为"有效销售额"是一个**定义明确的口径**（只算已完成），不应该被用户的切片器干扰 —— 否则用户选了"已取消"，这个指标就失去意义了。

**但要注意**：如果报表上同时有"有效销售额"和"订单状态分析"两个场景，就要小心了。建议做法：

- 用**不同的度量值名**区分（`有效销售额` vs `所选状态销售额`）
- 或者在报表上加文字说明

> **FDE 视角**：这类"筛选到底听谁的"问题，是报表交互设计的常见争议点。
> **解决原则**：**指标的口径定义 > 用户的临时选择**。核心指标（如有效销售额）应该保持稳定，不要因为用户点了一下切片器就变含义 —— 那会让报表失去可信度。

### 练习 4：算出"华东 + 数码"的交叉值（考：多条件筛选）

**题目**：建一个度量值，算出「华东大区 + 数码品类」的有效销售额。

**答案**：

```dax
华东数码销售额 =
CALCULATE(
    [有效销售额],
    'dim_region'[zone] = "华东",
    'dim_product'[category] = "数码"
)
```

**预期结果：1,126,366.70**

**解析**：两个筛选器参数是**不同表、不同列**，所以是**追加**（AND）关系：

```
status = '已完成'  AND  zone = '华东'  AND  category = '数码'
```

注意 `[有效销售额]` 本身已经包含 `status='已完成'`，而 `CALCULATE` 的多个筛选器会一起生效。

**验证 SQL**：

```sql
SELECT ROUND(SUM(i.line_amount),2) AS 销售额
FROM fact_order_item i
JOIN fact_order o ON i.order_id=o.order_id
JOIN dim_region r ON o.region_id=r.region_id
JOIN dim_product p ON i.product_id=p.product_id
WHERE o.status='已完成' AND r.zone='华东' AND p.category='数码';
-- 预期：1126366.70
```

**延伸**：这个数字说明什么？

- 华东全网数码销售额 1,126,366.70
- 全网数码销售额 2,612,383.09
- 华东占数码的 **43.12%**（1,126,366.70 ÷ 2,612,383.09）

和华东占全网的比例（43.62%）非常接近 —— 说明**数码品类在各区的分布是均匀的**，没有特别的区域偏好。这也是一个有用的业务结论。

### 练习 5：排查一个错误度量值（考：综合）

**题目**：同事写了这个度量值，说"算各品类占全网比例，但每个品类都显示 100%"：

```dax
错误占比 = DIVIDE(
    CALCULATE([有效销售额], ALL('dim_product')),
    CALCULATE([有效销售额], ALL('dim_product'))
)
```

找出问题并改正。

<details>
<summary>Hint</summary>
分子和分母长得一模一样，能不出问题吗？
</details>

**答案与解析**：

**问题**：分子和分母都加了 `ALL('dim_product')`，都变成了"全网销售额"，所以恒等于 1（100%）。

**正确写法**：

```dax
品类占比 =
DIVIDE(
    [有效销售额],                                    -- 分子：随矩阵行变化（各品类）
    CALCULATE([有效销售额], ALL('dim_product'))       -- 分母：清除品类筛选（全网）
)
```

**预期结果**：

| 品类 | 销售额 | 占全网 |
|---|---:|---:|
| 数码 | 2,612,383.09 | 36.31% |
| 家居 | 1,408,258.89 | 19.57% |
| 美妆 | 1,381,720.47 | 19.20% |
| 服饰 | 1,351,789.04 | 18.79% |
| 食品 | 441,341.24 | 6.13% |
| **合计** | **7,195,492.73** | **100.00%** |

**通用模板**（记住这个结构）：

```dax
占比 =
DIVIDE(
    [当前度量值],                        -- 分子：保持当前筛选（随矩阵行变化）
    CALCULATE([当前度量值], ALL(维度表))  -- 分母：清除该维度筛选
)
```

> **调试技巧**：当你发现占比恒为 100% 或恒为某个固定值时，**99% 是分子被误加了 `ALL`**。检查分子——它应该**什么都不加**，直接引用基础度量值。

**验证 SQL**：

```sql
SELECT p.category AS 品类,
       ROUND(SUM(i.line_amount),2) AS 销售额,
       ROUND(SUM(i.line_amount)*100/(SELECT SUM(i2.line_amount)
             FROM fact_order_item i2 JOIN fact_order o2 ON i2.order_id=o2.order_id
             WHERE o2.status='已完成'),2) AS 占全网pct
FROM fact_order_item i
JOIN dim_product p ON i.product_id=p.product_id
JOIN fact_order o ON i.order_id=o.order_id
WHERE o.status='已完成'
GROUP BY p.category ORDER BY 销售额 DESC;
```
