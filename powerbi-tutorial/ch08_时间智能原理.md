# ch08 时间智能原理 📅

> 本章目标：理解时间智能的**本质**（不是黑魔法，就是 `CALCULATE` + 日期筛选），能手写 YTD、同比、环比、滚动平均。
> 这是业务方问得最多的一类分析。

## 二、时间智能的本质：没有魔法

很多教程把时间智能讲得很神秘。其实一句话说清：

> **时间智能函数 = 帮你生成"一段日期区间"，然后塞进 `CALCULATE` 当筛选器。**

看这个等价关系：

```dax
-- 时间智能函数
CALCULATE([有效销售额], DATESYTD('dim_date'[date_key]))

-- 手工展开（完全等价）
CALCULATE(
    [有效销售额],
    FILTER(
        ALL('dim_date'[date_key]),
        'dim_date'[date_key] >= DATE(YEAR(MAX('dim_date'[date_key])), 1, 1)
        && 'dim_date'[date_key] <= MAX('dim_date'[date_key])
    )
)
```

**`DATESYTD` 只是个语法糖**，它内部就是算出"今年1月1日 ~ 当前日期"这段区间。

理解这点后，所有时间函数的行为你都能推导出来，而不用死记硬背。

### 2.1 为什么必须用独立日期表

你可能会问：为什么不能直接用 `fact_order[order_date]`？

| 问题 | 用事实表日期 | 用独立日期表 |
|---|---|---|
| 日期连续性 | ❌ **有断档**（没订单的日期不存在） | ✅ 连续（1,096 天，一天不缺） |
| 时间智能函数 | ❌ 不生效 | ✅ 生效 |
| 跨表共用 | ❌ 每张事实表各有一套 | ✅ 一张日期表服务所有事实表 |
| 额外属性（周末/假日/财年） | ❌ 没有 | ✅ 有 |

**本库的事实**：订单覆盖 1,018 个不同日期，而日期表有 1,096 天 —— **有 78 天没有订单**。这些"空白天"在时间智能里是必须的（比如算日均，分母应该是 365 天而不是有订单的天数）。

## 三、日期表三要素（ch02 回顾 + 深化）

| 条件 | 要求 | 本库 | 不满足的后果 |
|---|---|---|---|
| **唯一** | 日期列无重复 | ✅ `date_key` 主键 | 关系无法建立 |
| **连续** | 无断档 | ✅ 2023-01-01 ~ 2025-12-31 连续 | YTD/同比算错 |
| **整年** | 覆盖完整年度 | ✅ 3 个完整自然年 | 同比跨年时出错 |

**以及必须做的动作**：选中 `dim_date` → 表工具 → **标记为日期表** → 选 `date_key`。

> ⚠️ **踩坑提醒**：即使三要素都满足，不标记日期表时间智能**照样不工作**。这是 Power BI 里排名前三的新手问题。

## 四、时间智能函数族

### 4.1 累计类（YTD / QTD / MTD）

| 函数 | 含义 | 区间 |
|---|---|---|
| `DATESYTD(日期列, [年结日])` | 年初至今 | 1月1日 → 当前日期 |
| `DATESQTD(日期列)` | 季初至今 | 本季首日 → 当前日期 |
| `DATESMTD(日期列)` | 月初至今 | 本月1日 → 当前日期 |

```dax
销售额_YTD = CALCULATE([有效销售额], DATESYTD('dim_date'[date_key]))
销售额_MTD = CALCULATE([有效销售额], DATESMTD('dim_date'[date_key]))
```

### 4.2 平移类（同比 / 环比 / 上期）

| 函数 | 含义 | 例子 |
|---|---|---|
| `SAMEPERIODLASTYEAR(日期列)` | 去年同期 | 2024-06 → 2023-06 |
| `DATEADD(日期列, N, 单位)` | 平移 N 个周期 | `DATEADD(日期, -1, MONTH)` = 上月 |
| `PARALLELPERIOD(日期列, N, 单位)` | 平移 N 个**完整**周期 | `PARALLELPERIOD(日期, -1, YEAR)` |
| `DATESINPERIOD(日期列, 起点, N, 单位)` | 从起点算 N 个周期 | 最近 3 个月 |

**`DATEADD` vs `PARALLELPERIOD` 的区别**（容易混淆）：

| | `DATEADD` | `PARALLELPERIOD` |
|---|---|---|
| 粒度 | **精确保留当前粒度** | 返回**完整周期** |
| 例：当前筛选是 2024-06-15 | `DATEADD(-1,YEAR)` → 2023-06-15 | `PARALLELPERIOD(-1,YEAR)` → 2023 全年 |
| 用途 | 算同比（对齐同一天/月） | 算整段对比 |

### 4.3 移动区间（滚动平均）

```dax
销售额_滚动3月 =
CALCULATE(
    [有效销售额],
    DATESINPERIOD('dim_date'[date_key], MAX('dim_date'[date_key]), -3, MONTH)
)
```

## 五、手写 YTD：证明它没魔法

**强烈建议你亲手做一遍这个实验。**

```dax
-- 版本 A：用函数
YTD_函数版 = CALCULATE([有效销售额], DATESYTD('dim_date'[date_key]))

-- 版本 B：手写
YTD_手写版 =
VAR 当前最后日期 = MAX('dim_date'[date_key])
VAR 年初 = DATE(YEAR(当前最后日期), 1, 1)
RETURN
CALCULATE(
    [有效销售额],
    FILTER(
        ALL('dim_date'[date_key]),
        'dim_date'[date_key] >= 年初 && 'dim_date'[date_key] <= 当前最后日期
    )
)
```

拖进按月的矩阵（2024 年），**两者结果完全一致**：

| 月 | 当月销售额 | YTD 累计 |
|---:|---:|---:|
| 1 | 238,217.59 | 238,217.59 |
| 2 | 176,572.22 | 414,789.81 |
| 3 | 151,444.50 | 566,234.31 |
| 4 | 164,071.45 | 730,305.76 |
| 5 | 172,763.94 | 903,069.70 |
| 6 | 316,127.25 | 1,219,196.95 |
| 7 | 160,830.68 | 1,380,027.63 |
| 8 | 175,090.40 | 1,555,118.03 |
| 9 | 171,828.80 | 1,726,946.83 |
| 10 | 141,717.68 | 1,868,664.51 |
| 11 | 323,919.78 | 2,192,584.29 |
| 12 | 342,525.66 | **2,535,109.95** |

**12 月的 YTD = 全年累计 = 2,535,109.95**，与年度汇总一致 ✅

**解析（版本 B 的三个关键点）**：

1. `MAX('dim_date'[date_key])` 取当前筛选区间里**最后一天**
2. `ALL('dim_date'[date_key])` **清除原有日期筛选**（否则会和当前月的筛选取交集，结果只剩当月）
3. `FILTER` 生成"年初 → 当前最后一天"的日期列表

**理解了版本 B，你就理解了所有时间智能函数。**

**验证 SQL**：

```sql
SELECT MONTH(order_date) AS 月,
       ROUND(SUM(order_amount),2) AS 销售额,
       ROUND(SUM(SUM(order_amount)) OVER (ORDER BY MONTH(order_date)),2) AS 累计YTD
FROM fact_order
WHERE status='已完成' AND YEAR(order_date)=2024
GROUP BY MONTH(order_date) ORDER BY 月;
```

## 六、实战：建 7 个时间度量值

```dax
-- 1. 年初至今
销售额YTD = CALCULATE([有效销售额], DATESYTD('dim_date'[date_key]))

-- 2. 月初至今
销售额MTD = CALCULATE([有效销售额], DATESMTD('dim_date'[date_key]))

-- 3. 去年同期
销售额_去年同期 =
CALCULATE([有效销售额], SAMEPERIODLASTYEAR('dim_date'[date_key]))

-- 4. 同比增长率
销售额同比% =
VAR 今年 = [有效销售额]
VAR 去年 = [销售额_去年同期]
RETURN DIVIDE(今年 - 去年, 去年)

-- 5. 上月
销售额_上月 =
CALCULATE([有效销售额], DATEADD('dim_date'[date_key], -1, MONTH))

-- 6. 环比增长率
销售额环比% =
VAR 本月 = [有效销售额]
VAR 上月 = [销售额_上月]
RETURN DIVIDE(本月 - 上月, 上月)

-- 7. 滚动 3 个月
销售额_滚动3月 =
CALCULATE([有效销售额], DATESINPERIOD('dim_date'[date_key], MAX('dim_date'[date_key]), -3, MONTH))
```

### 6.1 年度级验证

拖一个表，行 = `dim_date[year]`，值 = 有效销售额、去年同期、同比%：

| 年 | 有效销售额 | 去年同期 | 同比% |
|---|---:|---:|---:|
| 2023 | 2,340,401.59 | — | — |
| 2024 | 2,535,109.95 | 2,340,401.59 | **+8.32%** |
| 2025 | 2,319,981.19 | 2,535,109.95 | **-8.49%** |

**解读**：

- 2024 年增长 8.32%（+194,708.36）
- 2025 年下滑 8.49%（-215,128.76）
- 三年整体在 230-254 万区间波动，没有明显趋势

> **注意**：2023 年的"去年同期"是空白 —— 因为日期表从 2023-01-01 开始，**没有 2022 年数据**。这是正常的边界行为，不是错误。

## 七、边界问题：日期表止于 2025-12-31

本库日期表到 2025-12-31 结束。这带来一个实际问题：

**如果你在报表上筛选 2025 年 12 月，算「滚动 3 个月」和「同比」，会怎样？**

| 度量值 | 2025-12 的结果 | 说明 |
|---|---|---|
| 有效销售额 | 正常 | 2025-12 有数据 |
| 销售额_去年同期 | 正常 | 2024-12 有数据 |
| 销售额_滚动3月 | 正常 | 2025-10 ~ 12 都在范围内 |

**但如果筛选 2026 年（日期表里没有）**：

- 所有度量值返回**空白**
- 时间智能函数**不会报错**，只是没数据

**更隐蔽的问题**：如果你把报表发布上线，日期表不自动延长，到了 2026 年报表就"没数据"了。

**解决方案**：

| 方案 | 做法 | 推荐度 |
|---|---|---|
| 日期表覆盖未来 | 生成到 2027 或更远（`CALENDAR` 里改结束日期） | ⭐⭐⭐ 最简单 |
| 动态日期表 | 用 `CALENDARAUTO()` 或按事实表最大日期动态生成 | ⭐⭐⭐ 自动，但要注意边界 |
| 手动延长 | 每年改一次 | ⭐ 容易忘 |

**推荐做法**（ch03 的 M 代码改一行即可）：

```m
结束日期 = #date(2027, 12, 31),   -- 从 2025 改到 2027
```

> **FDE 视角**：**这是上线前必查项**。我见过太多报表在新年第一天"数据全空"，原因就是日期表没延长。交付前一定要确认日期表覆盖范围，并在文档里写明"本报表日期表覆盖至 XXXX-12-31，届时需延长"。

## 八、财年（非自然年）怎么配

很多公司的财年不是 1 月到 12 月（比如 4 月到次年 3 月，或 7 月到次年 6 月）。

`DATESYTD` 支持第二个参数：

```dax
-- 财年从 7 月 1 日开始
销售额_财年YTD = CALCULATE([有效销售额], DATESYTD('dim_date'[date_key], "6/30"))
```

**参数写法**：传入"**财年结束日**"。

| 财年起始 | 参数写法 |
|---|---|
| 1月1日（自然年） | 省略（默认） |
| 4月1日 | `"3/31"` |
| 7月1日 | `"6/30"` |
| 10月1日 | `"9/30"` |

> ⚠️ **注意格式**：用 `"6/30"`（月/日），不同区域设置可能有差异，写完一定要验证。

**本库是自然年**，所以不需要这个参数。但你在客户现场大概率会遇到财年需求。

## 九、FDE 现场场景

### 场景 1：客户说"YTD 和去年同期对不上"

**排查清单**：

| 检查项 | 常见问题 |
|---|---|
| 日期表标记了吗？ | 没标记 → YTD 空白 |
| 日期表连续吗？ | 用事实表日期 → 有断档 |
| 口径一致吗？ | YTD 算了全部状态，去年只算已完成 |
| 日期范围一致吗？ | 今年 YTD 到 6 月，去年却是全年 |
| 有未来日期的数据吗？ | 数据里有 2026 年的订单，但日期表只到 2025 |

**最常见的坑是第 4 条**：

> 业务方说"今年 YTD 是 X，去年是 Y，为什么降了这么多？"
> 你一看：今年的 YTD 只到 6 月，去年是**全年**数据 —— 当然降了。

**正确对比方式**：**同期对比（Like-for-Like）**

```dax
-- 去年"同一时间段"的销售额（而不是去年全年）
去年同期_同期 =
VAR 当前最后日期 = MAX('dim_date'[date_key])
VAR 去年同日 = EDATE(当前最后日期, -12)
RETURN
CALCULATE(
    [有效销售额],
    DATESBETWEEN('dim_date'[date_key], DATE(YEAR(去年同日),1,1), 去年同日)
)
```

> **这个度量值非常实用** —— 它保证"今年 1/1~6/30" 对比 "去年 1/1~6/30"，真正可比。

### 场景 2：客户要看"日均"而不是"总额"

**常见需求**："这个月卖了 30 万，那日均多少？"

```dax
日均销售额 =
DIVIDE(
    [有效销售额],
    COUNTROWS('dim_date')     -- 日期表行数 = 天数
)
```

**关键点**：分母用**日期表的天数**（含没有订单的日子），而不是"有订单的天数"。

本库订单覆盖 1,018 天，日期表有 1,096 天 —— 两者差 78 天。用错分母，日均会虚高 7.7%。

> **这是"日期表为什么必须连续"的最好例证。**

### 场景 3：大促期间的日环比没有意义

**现象**：双 11 后一天，环比暴跌 -60%，业务方紧张地来问"是不是出问题了"。

**正确做法**：大促期间看**同比**（跟去年双 11 比），不要看环比（跟大促当天比必然暴跌）。

**报表设计建议**：

- 常规月份：看**环比**（反映短期趋势）
- 大促月份：看**同比**（剔除季节性）

可以在报表上加一个「大促标记」列（在日期表里加 `is_promotion`），大促月自动切换显示同比。

## 十、本章小结

| 你学到了 | 关键点 |
|---|---|
| **本质** | 时间智能 = `CALCULATE` + 一段日期区间，**没有魔法** |
| 三要素 | 唯一 + 连续 + 整年，且必须**手动标记日期表** |
| 累计 | `DATESYTD` / `DATESQTD` / `DATESMTD` |
| 平移 | `SAMEPERIODLASTYEAR`（同期）、`DATEADD`（精确保粒度）、`PARALLELPERIOD`（完整周期） |
| 移动区间 | `DATESINPERIOD(日期, MAX(日期), -3, MONTH)` |
| 手写 YTD | `VAR 年初=DATE(YEAR(MAX(日期)),1,1)` + `FILTER(ALL(日期), 日期>=年初 && 日期<=MAX(日期))` |
| 年度数据 | 2023 **2,340,401.59** / 2024 **2,535,109.95(+8.32%)** / 2025 **2,319,981.19(-8.49%)** |
| 季节性 | 6月+82.98%、11月+128.57%、12月全年最高 342,525.66 |
| 边界 | 日期表止于 2025-12-31，**上线前要延长** |
| 财年 | `DATESYTD(日期, "6/30")` 表示财年从 7 月开始 |

## 十一、练习题

### 练习 1：不标记日期表会怎样（考：前提条件）

**题目**：

1. 先取消 `dim_date` 的「标记为日期表」（表工具 → 标记为日期表 → 选"无"）
2. 看 `销售额YTD` 卡片显示什么
3. 重新标记回来，看数字

**预期结果**：

| 状态 | 卡片显示 |
|---|---|
| 未标记日期表 | **空白**（或部分版本报"需要日期表"） |
| 标记后 | 正常返回累计值 |

**解析**：

时间智能函数内部依赖日期表的元数据。Power BI 需要知道：

- 哪列是日期列
- 日期范围是否连续
- 是否覆盖整年

不标记 → 它被当成普通表 → 函数无法工作。

> **这是 Power BI 求助论坛里出现频率最高的问题之一。** 记住这个排查顺序：**遇到时间智能返回空白，第一件事检查日期表标记。**

**延伸排查清单**（YTD 空白时的四步法）：

1. 日期表标记了吗？
2. 关系建了吗（`dim_date[date_key]` → `fact_order[order_date]`）？
3. 筛选的日期在日期表范围内吗？
4. 度量值本身（如有效销售额）有值吗？

---

### 练习 2：DATEADD 替代 SAMEPERIODLASTYEAR（考：函数等价性）

**题目**：建两个度量值，验证它们结果相同：

```dax
去年_A = CALCULATE([有效销售额], SAMEPERIODLASTYEAR('dim_date'[date_key]))
去年_B = CALCULATE([有效销售额], DATEADD('dim_date'[date_key], -1, YEAR))
```

**预期结果**：

| 年 | 有效销售额 | 去年_A | 去年_B |
|---|---:|---:|---:|
| 2023 | 2,340,401.59 | 空白 | 空白 |
| 2024 | 2,535,109.95 | **2,340,401.59** | **2,340,401.59** |
| 2025 | 2,319,981.19 | **2,535,109.95** | **2,535,109.95** |

**结论**：两者等价 ✅

**解析**：

`SAMEPERIODLASTYEAR(日期)` 内部就是 `DATEADD(日期, -1, YEAR)` 的语法糖。当筛选粒度是"整年"时，两者都返回上一整年。

**那什么时候有区别？**

在**月份粒度**上，两者都返回"去年同月"，也等价。真正的区别在 `PARALLELPERIOD`：

```dax
-- 筛选 2024-06 时：
去年同月 = CALCULATE([有效销售额], DATEADD('dim_date'[date_key], -1, YEAR))
-- → 2023 年 6 月

去年全年 = CALCULATE([有效销售额], PARALLELPERIOD('dim_date'[date_key], -1, YEAR))
-- → 2023 年全年（完整周期）
```

> **记忆**：
> - 要"去年同一个月/同一天" → `SAMEPERIODLASTYEAR` 或 `DATEADD(-1, YEAR)`
> - 要"去年一整年" → `PARALLELPERIOD(-1, YEAR)`

### 练习 4：算日均销售额（考：日期表连续性的价值）

**题目**：算 2024 年的日均销售额。给出两种分母的结果：

```dax
-- 分母 A：日期表天数（正确）
日均_日期表 = DIVIDE([有效销售额], COUNTROWS('dim_date'))

-- 分母 B：有订单的天数（会虚高）
日均_有订单天 = DIVIDE([有效销售额], DISTINCTCOUNT('fact_order'[order_date]))
```

**预期结果（2024 年）**：

| 指标 | 值 |
|---|---:|
| 有效销售额 | 2,535,109.95 |
| 日期表天数 | **366**（2024 是闰年） |
| 有订单天数 | 约 340 左右 |
| 日均_日期表 | **6,926.53** |
| 日均_有订单天 | 约 7,456（虚高约 7.6%） |

**解析**：

2024 年有 366 天（闰年），但并不是每天都有订单。用"有订单天数"做分母，等于**默认没订单的日子不算数**，会高估日常经营水平。

**正确做法：分母必须包含没有业务的日子** —— 这正是独立日期表存在的意义。

**验证 SQL**：

```sql
SELECT ROUND(SUM(order_amount)/366, 2) AS 日均_按366天,
       ROUND(SUM(order_amount)/COUNT(DISTINCT order_date), 2) AS 日均_按有订单天,
       COUNT(DISTINCT order_date) AS 有订单天数
FROM fact_order
WHERE status='已完成' AND YEAR(order_date)=2024;
```

**延伸思考**：

如果是**门店日均**，更常见的做法是除以"**营业天数**"（排除闭店日）。这需要在日期表里加一个 `is_business_day` 标记列，排除法定假日和店休日。本库的 `is_holiday` 就是这类标记的雏形（虽然只标了 3 个节日）。

### 练习 5：同期对比（Like-for-Like）（考：真实业务场景）

**题目**：现在是 2025 年 7 月，业务方要看"今年到 7 月为止 vs 去年同期"。

如果直接用 `SAMEPERIODLASTYEAR`，你会发现：今年的数据是 1-7 月（7 个月），去年的数据却是**全年**（12 个月）—— 完全不可比。

写出正确的度量值。

<details>
<summary>Hint</summary>
先把"当前统计截止到哪天"算出来，再把去年截断到同一天。
</details>

**答案与解析**：

```dax
去年同期_同期对比 =
VAR 当前最后日期 = MAX('dim_date'[date_key])
VAR 去年同日 = DATE(YEAR(当前最后日期) - 1, MONTH(当前最后日期), DAY(当前最后日期))
RETURN
CALCULATE(
    [有效销售额],
    DATESBETWEEN('dim_date'[date_key], DATE(YEAR(去年同日), 1, 1), 去年同日)
)
```

**对比两种写法**（假设当前筛选是 2025 年 1-7 月）：

| 度量值 | 去年取哪段 | 可比性 |
|---|---|---|
| `SAMEPERIODLASTYEAR` | 2024 **全年** | ❌ 7个月 vs 12个月 |
| `去年同期_同期对比` | 2024 **1-7月** | ✅ 7个月 vs 7个月 |

**这个度量值的价值**：

> 这是**实际项目里几乎必建**的一个度量值。只要业务方在做"年度进度对比"（今年到现在 vs 去年同期），就必须用它。

**变体：如果只要截止到上月底**

有时候当月数据还不完整（比如今天是 7 月 15 日），比到 7 月 15 日也不公平（可能差几天）。更严谨的做法是**比到上月底**：

```dax
去年同期_截至上月 =
VAR 当前最后日期 = MAX('dim_date'[date_key])
VAR 上月底 = EOMONTH(当前最后日期, -1)
VAR 去年同月底 = EDATE(上月底, -12)
RETURN
CALCULATE(
    [有效销售额],
    DATESBETWEEN('dim_date'[date_key], DATE(YEAR(去年同月底), 1, 1), 去年同月底)
)
```

> **FDE 视角**：这类"口径对齐"的细节，正是专业报表和普通报表的区别。
> 业务方不一定说得出来，但他们看到"今年 7 个月 vs 去年 12 个月"的对比图时，会觉得"哪里怪怪的"。
> **你主动把它对齐，并加一行说明"对比区间：1月-7月"，信任感立刻建立起来。**
