## 二、为什么先搞环境

Python 新手最常见的翻车，90% 不是语法错，而是环境问题：

- 代码没错，但 `'python' 不是内部或外部命令` → 解释器没找到
- 明明装了 pandas，却 `ModuleNotFoundError` → 装到了另一个 Python 里
- 在自己电脑上跑得好好的，发给同事就报错 → 没隔离、包版本不一致
- 中文输出乱码 / 读中文文件报 `UnicodeDecodeError` → 编码没统一

这些坑**一次配好，永久免疫**。花 20 分钟搞懂这一章，后面省 20 小时。

## 三、概念：四个词先分清楚

| 词 | 是什么 | 类比 |
|---|---|---|
| **解释器** | 真正执行代码的程序，`python.exe` | 发动机 |
| **脚本** | 你写的 `.py` 文件 | 乐谱 |
| **虚拟环境（venv）** | 一个**独立隔离**的 Python + 它的包 | 每辆车一个独立油箱，互不串味 |
| **包（package）** | 别人写好的现成功能，`pandas`、`matplotlib` | 现成零件 |

> **为什么必须用虚拟环境？**
> 系统 Python 是很多工具的公共底座，你往里乱装包可能把它搞坏。
> 虚拟环境 = 复制一份干净的 Python 出来，你在里面随便折腾，搞崩了删掉重来，**不影响系统**。
> 交付给客户时，也可以把环境一键导出，对方装出来和你一模一样。

### 4.2 第一行代码

新建 `hello.py`：

```python
# -*- coding: utf-8 -*-
"""第一行 Python：打印一张生产日报的抬头"""

line1 = "东莞常青树体育用品"
line2 = "静音球日产量报表"

print("=" * 30)
print(f"{line1:^24}")
print(f"{line2:^26}")
print("=" * 30)
```

**预期输出：**

```
==============================
     东莞常青树体育用品
       静音球日产量报表
==============================
```

几个知识点：

- `#` 开头是**注释**，不执行
- `"""` 三引号是**文档字符串**，说明这个文件/函数干嘛的
- `print` 默认换行；`f"{值:^24}"` 表示**居中占 24 个字符宽**
- `"=" * 30` 字符串可以「乘」，重复 30 次

### 4.4 print 的几个实用开关

```python
print("A", "B", "C")                  # 默认空格分隔、结尾换行
print("A", "B", "C", sep="|")         # 分隔符改成 |
print("加载中", end="")                # 不换行
print("完成")                          # 接在上面那一行的后面

x = 10
print(f"{x=}", f"{x*2=}")             # Python 3.8+ 调试神器：连变量名一起打印
```

**预期输出：**

```
A B C
A|B|C
加载中完成
x=10 x*2=20
```

> `f"{x=}"` 是 3.8 加入的**调试语法**，等价于 `print("x =", x)` 但更省事。排查数据时非常顺手。

### 4.5 接收命令行参数：`sys.argv`

脚本要给别人用，就得能传入参数。新建 `report.py`：

```python
import sys

print("收到的参数:", sys.argv)
print("参数个数:", len(sys.argv))
if len(sys.argv) > 1:
    print("第一个参数:", sys.argv[1])
```

命令行运行：

```bash
python report.py 2026-09-04 静音球
```

**预期输出：**

```
收到的参数: ['report.py', '2026-09-04', '静音球']
参数个数: 3
第一个参数: 2026-09-04
```

> 注意：**`sys.argv[0]` 永远是脚本自己的名字**，真正的第一个参数是 `sys.argv[1]`。
> 所以判断「有没有传参」要写 `len(sys.argv) > 1`，不是 `> 0`。

### 4.6 `if __name__ == "__main__"` 到底干嘛的

这是每个正经 Python 文件底部都会出现的一行，很多人抄了但不懂：

```python
def calc_margin(revenue, cost):
    return (revenue - cost) / revenue * 100

print("模块被加载了，这行总会执行")

if __name__ == "__main__":
    print("只有直接运行本文件时，这行才执行")
    print("毛利率:", round(calc_margin(1000, 763), 2), "%")
```

- **直接运行** `python x.py` → `__name__` 的值是 `"__main__"`，缩进里的代码执行
- **被别的模块 import** → `__name__` 的值是 `"x"`（模块名），缩进里的代码**不执行**

**用途**：把「函数定义」和「真正干活」分开。别人 `import` 你的模块时，只想用你的函数，不想看你的测试输出。

> 一句话：**这是 Python 的「入口门」 。** 所有脚本都应该有，包括后面 ch14 的完整项目。

### 4.9 怎么读报错（Traceback）

故意写个错的：

```python
def calc_margin(revenue, cost):
    return (revenue - cost) / revenue * 100

print(calc_margin(1000, "763"))
```

**真实报错：**

```
Traceback (most recent call last):
  File "D:\...\demo_err.py", line 4, in <module>
    print(calc_margin(1000, "763"))
          ~~~~~~~~~~~^^^^^^^^^^^^^
  File "D:\...\demo_err.py", line 2, in calc_margin
    return (revenue - cost) / revenue * 100
            ~~~~~~~^~~~~~
TypeError: unsupported operand type(s) for -: 'int' and 'str'
```

**读法（永远从下往上看）：**

1. **最后一行**是错误类型和原因：`TypeError: unsupported operand type(s) for -: 'int' and 'str'`
   → 减号两边一个是 int 一个是 str，类型不对
2. **倒数第二行**告诉你错在哪个文件的第几行：`line 2, in calc_margin`
3. **最上面**是调用链：第 4 行调用了第 2 行的函数

> **排查口诀**：最后一行看「什么错」，倒数第二行看「在哪错」，`^^^^` 指的位置看「哪个值错」。
> 常见错误类型：`SyntaxError`（语法写错）、`IndentationError`（缩进错）、`NameError`（名字没定义）、`TypeError`（类型不对）、`ValueError`（值不合法）、`KeyError` / `IndexError`（取不到）。

## 六、FDE 现场场景：为什么环境规范这么重要

你写好一个「自动出生产日报」的脚本，发给客户 IT 跑，对方双击没反应。

- **没有虚拟环境**：你不知道对方机器上装了什么版本的 pandas，可能一行就报错
- **没有 `requirements.txt`**：对方得猜你用了哪些包
- **没有 `if __name__ == "__main__"`**：对方想 `import` 你的函数复用，结果一导入就开始打印垃圾输出
- **没写编码**：对方是老机器 GBK 环境，读中文 Excel 直接崩

**专业的交付长这样**：

```
my_project/
├── requirements.txt     # pip install -r requirements.txt 一键装齐
├── config.py            # 数据库地址、路径等配置集中放
├── main.py              # 入口：if __name__ == "__main__":
├── utils/               # 可复用的函数模块
└── README.md            # 怎么跑、传什么参数
```

ch14 会带你把这套结构搭出来。

### 练习 1：打印一张报价单抬头（考：print 与 f-string 格式化）

**题目**：用 `print` 和 f-string 输出下面这张表（公司名居中、金额右对齐、带千分位）。

**答案：**

```python
company = "东莞常青树体育用品有限公司"
items = [("ST-BD-42 包布静音球", 1200, 8.65),
         ("ST-BD-60 滴胶静音球", 400, 12.30)]

print("=" * 46)
print(f"{company:^40}")
print("=" * 46)
print(f"{'品名':<20}{'数量':>8}{'单价':>10}{'金额':>12}")
print("-" * 46)
total = 0
for name, qty, price in items:
    amount = qty * price
    total += amount
    print(f"{name:<20}{qty:>8}{price:>10.2f}{amount:>12,.2f}")
print("-" * 46)
print(f"{'合计':<20}{'':>8}{'':>10}{total:>12,.2f}")
print("=" * 46)
```

**实际输出：**

```
==============================================
             东莞常青树体育用品有限公司              
==============================================
品名                        数量        单价          金额
----------------------------------------------
ST-BD-42 包布静音球          1200      8.65   10,380.00
ST-BD-60 滴胶静音球           400     12.30    4,920.00
----------------------------------------------
合计                                       15,300.00
==============================================
```

**解析**：`{值:<20}` 左对齐占 20 宽、`{值:>10}` 右对齐、`{:>12,.2f}` 右对齐 + 千分位 + 两位小数。

注意**中文对不齐**的问题：`f"{'品名':<20}"` 里「品名」占 2 个字符宽度，但显示在终端时占 4 个英文字符宽。Python 的格式化按**字符数**算，终端按**显示宽度**算，所以对不齐。

解决方案（ch14 出报表时会用）：

```python
import unicodedata

def pad_cn(text, width, align="left"):
    """按显示宽度补齐（中文算 2 格）"""
    w = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in text)
    pad = max(0, width - w)
    if align == "left":
        return text + " " * pad
    if align == "right":
        return " " * pad + text
    left = pad // 2
    return " " * left + text + " " * (pad - left)

print(pad_cn("品名", 20) + pad_cn("数量", 8, "right"))
print(pad_cn("ST-BD-42 包布静音球", 20) + pad_cn("1200", 8, "right"))
```

真实输出（中文列也能对齐了）：

```
品名                    数量
ST-BD-42 包布静音球     1200
ST-BD-60 滴胶静音球      400
```

> 原理：`unicodedata.east_asian_width(c)` 返回 `W`/`F` 表示这是个宽字符（中文、全角符号），按 2 格算；其余按 1 格。
> 两行都补到 20 格，在等宽字体终端里就齐了。这个函数在 ch14 导出纯文本报表时还会用到。

### 练习 2：命令行参数计算器（考：sys.argv）

**题目**：写 `calc.py`，接收两个数字参数，输出它们的和、差、积、商。

**答案：**

```python
import sys

if __name__ == "__main__":
    if len(sys.argv) != 3:
        print("用法: python calc.py <数字1> <数字2>")
        sys.exit(1)

    a = float(sys.argv[1])
    b = float(sys.argv[2])
    print(f"{a} + {b} = {a + b}")
    print(f"{a} - {b} = {a - b}")
    print(f"{a} * {b} = {a * b}")
    print(f"{a} / {b} = {round(a / b, 4)}")
```

运行 `python calc.py 1200 12.3`，**预期输出：**

```
1200.0 + 12.3 = 1212.3
1200.0 - 12.3 = 1187.7
1200.0 * 12.3 = 14760.0
1200.0 / 12.3 = 97.561
```

**解析**：`sys.argv` 拿到的**永远是字符串**，必须 `float()` 转换后才能算。`sys.exit(1)` 表示异常退出（0 是正常）。参数个数不对时给个用法提示，是专业脚本的基本礼仪。

### 练习 3：入口门实验（考：`__name__`）

**题目**：写两个文件 `tool.py` 和 `use_tool.py`，验证 `if __name__ == "__main__"` 的效果。

**答案（`tool.py`）：**

```python
def double(x):
    return x * 2

print("[tool] 模块顶层代码，import 时也会执行")

if __name__ == "__main__":
    print("[tool] 只有直接运行才看到这行")
```

**答案（`use_tool.py`）：**

```python
from tool import double
print("调用结果:", double(21))
```

运行 `python use_tool.py`，**预期输出：**

```
[tool] 模块顶层代码，import 时也会执行
调用结果: 42
```

**解析**：`import` 时 `tool.py` 顶层代码（那个 `print`）执行了，但 `__main__` 保护下的那行没有。这证明入口门确实把「测试代码」挡住了。

### 练习 4：读报错（考：Traceback 阅读）

**题目**：下面这段代码会报错，说出错误类型、出错行号、以及怎么改。

```python
prices = {"ST-BD-42": 8.65, "ST-BD-60": 12.30}
code = "ST-BD-99"
print("单价:", prices[code])
```

**答案**：

- **错误类型**：`KeyError: 'ST-BD-99'`
- **出错行号**：第 3 行 `print("单价:", prices[code])`
- **原因**：字典里没有 `ST-BD-99` 这个键
- **改法**（三选一）：

```python
print("单价:", prices.get(code))                  # 没有就返回 None
print("单价:", prices.get(code, 0))               # 没有就返回 0
if code in prices:                                 # 先判断再取
    print("单价:", prices[code])
```

**解析**：`KeyError` 是字典专属错误，处理外部传入的料号时必须用 `get()` 兜底——客户给你的料号表永远可能有脏数据。
