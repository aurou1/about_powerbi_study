## 1. 迭代器：for 循环背后的机制

```python
nums = [10, 20, 30]
it = iter(nums)              # 拿到迭代器
print("next:", next(it))     # 10
print("next:", next(it))     # 20
print("next:", next(it))     # 30
try:
    next(it)                 # 取空了
except StopIteration:
    print("StopIteration 正常抛出")
```

**预期输出：**

```
next: 10
next: 20
next: 30
StopIteration 正常抛出
```

> `for x in 列表` 背后就是：`iter(列表)` 拿迭代器，然后反复 `next()` 直到 `StopIteration`。任何能被 `for` 遍历的对象，都是「可迭代的」。

### for 等价于 while + next

```python
nums = [1, 2]
it = iter(nums)
result = []
while True:
    try:
        result.append(next(it))
    except StopIteration:
        break
print("for 等价 while+next:", result)
```

**预期输出：**

```
for 等价 while+next: [1, 2]
```

## 2. 生成器：`yield` 一次产出一个

> 生成器是「懒」的迭代器：用到才算，算完就丢，**不占内存**。用 `yield` 代替 `return`，函数就变成生成器。

```python
def countdown(n):
    while n > 0:
        yield n          # 每次到这里「暂停并返回」，下次从这儿继续
        n -= 1

gen = countdown(3)
print("生成器:", list(gen))      # 一次性取完
print("next 逐个:", end=" ")
g = countdown(3)
print(next(g), next(g), next(g)) # 3 2 1
```

**预期输出：**

```
生成器: [3, 2, 1]
next 逐个: 3 2 1
```

> **生成器 vs 函数**：函数 `return` 一次就结束；生成器 `yield` 可以多次「吐出」值，中间状态保留。适合「一个一个产出的序列」。

## 3. 生成器表达式：省内存版列表推导式

```python
gen_expr = (x * x for x in range(5))     # 注意是 () 不是 []
print("生成器表达式:", list(gen_expr))
gen_expr2 = (x * x for x in range(5))
next(gen_expr2); next(gen_expr2)         # 取走前两个
print("再取:", list(gen_expr2))           # 只剩后三个
```

**预期输出：**

```
生成器表达式: [0, 1, 4, 9, 16]
再取: [4, 9, 16]
```

> 生成器「一次性消费」——取过的没了。这就是为什么上面「再取」只剩 `[4, 9, 16]`。

### 内存对比（ch06 提过，这里量化）

```python
import sys
big_list = [i for i in range(100000)]
big_gen = (i for i in range(100000))
print("列表内存:", f"{sys.getsizeof(big_list):,} 字节")
print("生成器:", f"{sys.getsizeof(big_gen):,} 字节")
```

**预期输出：**

```
列表内存: 800,984 字节
生成器: 192 字节
```

> 10 万个元素：列表占近 **800 KB**，生成器只占 **192 字节**（它只记「当前到哪了」）。处理百万行日志时，这个差距就是「跑得动」和「内存爆」的区别。

## 4. 生成器流式读大文件（实战）

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip()          # 一行一行产，不整文件入内存

count = sum(1 for _ in read_lines("demo.txt"))
print("生成器读文件行数:", count)
```

**预期输出：**

```
生成器读文件行数: 4
```

> 这是处理大日志/大 CSV 的**标准姿势**：`yield` 逐行产出，内存恒定。配合 `if` 过滤，能边读边筛。

## 5. 上下文管理器：`with` 的底层

> ch08 用过 `with open()`。它的底层是**上下文管理器协议**：`__enter__`（进入时）和 `__exit__`（退出时，无论是否报错）。

### 5.1 类实现

```python
import time

class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                      # with ... as 拿到的是这个返回值
    def __exit__(self, exc_type, exc, tb):
        self.cost = time.perf_counter() - self.t0
        return False                     # False = 不吞异常

with Timer() as t:
    sum(range(1000000))
print("类上下文管理器: 耗时", round(t.cost, 4), "s | cost 属性:", round(t.cost, 6))
```

**预期输出：**

```
类上下文管理器: 耗时 0.0014 s | cost 属性: 0.001396
```

### 5.2 `@contextmanager` 装饰器（更简洁）

```python
from contextlib import contextmanager

@contextmanager
def timed_block(name):
    t0 = time.perf_counter()
    try:
        yield                          # yield 前是 __enter__，后是 __exit__
    finally:
        print(f"    [{name}] 耗时 {time.perf_counter() - t0:.4f}s")

with timed_block("求和"):
    sum(range(1000000))
```

**预期输出：**

```
    [求和] 耗时 0.0014s
```

> `@contextmanager` 把「一个 yield 分成前后两段」写成普通函数，比手写类省事。资源清理（关连接、解锁、计时）都用它。

### 5.3 `suppress`：优雅吞掉指定异常

```python
from contextlib import suppress

with suppress(FileNotFoundError):
    open("不存在的文件.txt")            # 报错但被 suppress 吞掉，继续往下
print("suppress 吞掉异常：继续执行到这行")
```

**预期输出：**

```
suppress 吞掉异常：继续执行到这行
```

> 明确「这个异常我不在乎」时，`suppress` 比 `try/except pass` 语义更清晰。

## 6. 综合：生成器 + 装饰器 + 上下文管理器

```python
import time
from contextlib import contextmanager

@contextmanager
def timer(name):
    t0 = time.perf_counter()
    try:
        yield
    finally:
        print(f"    [{name}] 耗时 {time.perf_counter() - t0:.4f}s")

def read_orders(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip()

with timer("流式统计"):
    n = sum(1 for _ in read_orders("demo.txt"))
print("行数:", n)
```

**预期输出：**

```
    [流式统计] 耗时 0.0002s
行数: 4
```

> 这 4 个工具（迭代器 / 生成器 / 装饰器 / 上下文管理器）组合起来，就是「流式、省内存、带计时、自动清理」的工业级数据脚本骨架。

## 小结

| 工具 | 关键点 | 实战 |
|---|---|---|
| 迭代器 | `iter` / `next` / `StopIteration` | 理解 for 循环本质 |
| 生成器 `yield` | 懒计算、可暂停 | 大数据流、逐行读文件 |
| 生成器表达式 | `(x for x in ...)` | 省内存版列表推导 |

## 练习

### 练习 1：写生成器（考：yield）
**题目**：写 `evens(n)` 生成器，产出 0 到 n 之间的偶数。取前 5 个。
<details><summary>答案与解析</summary>

```python
def evens(n):
    for i in range(n + 1):
        if i % 2 == 0:
            yield i

print(list(evens(10))[:5])   # [0, 2, 4, 6, 8]
```
</details>

### 练习 2：生成器读文件（考：流式）
**题目**：用生成器逐行读 `demo.txt`，过滤掉空行，返回非空行数。
<details><summary>答案与解析</summary>

```python
def non_empty(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                yield line.rstrip()

print(sum(1 for _ in non_empty("demo.txt")))   # 4
```
</details>

### 练习 3：上下文管理器类（考：__enter__/__exit__）
**题目**：写 `OpenFile` 类，进入时打开文件、退出时关闭，支持 `with OpenFile(...) as f`。
<details><summary>答案与解析</summary>

```python
class OpenFile:
    def __init__(self, path):
        self.path = path
    def __enter__(self):
        self.f = open(self.path, encoding="utf-8")
        return self.f
    def __exit__(self, *a):
        self.f.close()
        return False

with OpenFile("demo.txt") as f:
    print(len(f.read()))   # 文件字符数
```
</details>

### 练习 4：@contextmanager（考：装饰器版）
**题目**：用 `@contextmanager` 写一个 `tag(name)`，进入打印 `<name>`，退出打印 `</name>`。
<details><summary>答案与解析</summary>

```python
from contextlib import contextmanager
@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")

with tag("body"):
    print("内容")
# <body>
# 内容
# </body>
```
</details>

### 练习 5：生成器 vs 列表内存（考：理解）
**题目**：解释为什么 `(i for i in range(10**6))` 比 `[i for i in range(10**6)]` 省内存？用 `sys.getsizeof` 验证两者字节数差异。
<details><summary>答案与解析</summary>

```python
import sys
print(sys.getsizeof([i for i in range(10**6)]))   # 约 8,000,056 字节
print(sys.getsizeof((i for i in range(10**6))))   # 约 112~200 字节
```
**解析**：列表要把 100 万个整数对象都放进内存；生成器只记录「当前状态」，按需产出，占用恒定。大数据场景必须用生成器。
</details>
