## 4. 日志 `logging`：别用 `print` 调试生产脚本

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    filename="etl.log", encoding="utf-8",
)
logging.info("开始拉取订单数据")
try:
    # ... 业务逻辑
    logging.info("拉取完成：%d 行", 8445)
except Exception as e:
    logging.error("拉取失败: %s", e, exc_info=True)     # exc_info 记录堆栈
```

> FDE 的脚本常跑在客户服务器上、无人盯着。**用 `logging` 写文件日志**，出问题能回看；`print` 只适合本地临时看。`exc_info=True` 把异常堆栈也写进去，定位最快。

## 5. 调试技巧

| 技巧 | 用法 |
|---|---|
| `print` / f-string 调试 | `f"{x=}"` 一行打印变量名和值 |
| `breakpoint()` | 交互式断点（PyCharm 里点行号左边红点更方便） |
| `type()` / `df.info()` | 不确定变量类型/列类型时先查 |
| `df.head()` / `shape` | 数据进来先「看两眼」，确认行数/列对 |
| 小样本复现 | 大数据跑不动，先取 100 行调通逻辑 |

> **铁律**：新数据源进来，**先 `df.head()` + `df.info()` + `df.shape` 三连**，确认结构和预期一致，再写复杂逻辑。80% 的 bug 出在「以为数据长这样」。

## 6. Python 代码规范（PEP 8 要点）

- 缩进 4 空格；行宽 ≤ 79（推荐 100）
- 变量/函数用小写蛇形 `order_amount`；类用大驼峰 `Product`
- 导入顺序：标准库 → 第三方 → 自己的
- 每个模块写 `if __name__ == "__main__":` 包裹主流程
- 函数写 docstring，复杂逻辑写注释「为什么」而非「是什么」
- 用 `pathlib` 不用 `os.path`；用 `with` 开关文件

> 规范和客户代码库对齐，FDE 才能「进场就融入」。PyCharm 默认按 PEP 8 提示，跟着走就行。
