# SQL 零基础 → 进阶高手教程

一份写给「要真上手查数据的人」的 SQL 教程，共 12 章。和同目录的 `powerbi-tutorial/` 是**一套数据、两种视角**：Power BI 负责「把数据变成别人能看的报表」，本教程负责「用 SQL 把数据查出来、算明白」。

配套数据库：`study_powerbi_demodata`（电商订单星型模型，共 13,780 行）。**所有示例都用这套数据，能跑出真实数字**，你可以拿 SQL 算一遍，再回到 Power BI 教程用 DAX 复现对拍。

---

## 一、这份教程的定位

| 它是什么 | 它不是什么 |
|---|---|
| 讲**为什么这么写**、**什么时候用**、**写出来对不对** | 不是 SQL 关键字速查表 |
| 每章有可复现的示例 + 带预期结果的练习 | 不是「照抄这条语句」的练习册 |
| 站在**交付者视角**（口径怎么定、JOIN 会不会膨胀、慢查询怎么救） | 不是考证题库 |

**特别适合**：制造业 / 业务岗转数据分析、甲方 IT、需要给客户交付报表的实施顾问（FDE）。你已经会一点 Python 基础，想把数据库里的数据变成可靠的报表数字。

**不适合**：只想背 `SELECT *` 应付面试、不关心数字对不对的人。

## 七、八条统一口径（全教程一致，不许出现第二种说法）

| # | 口径 | 具体值 |
|---:|---|---|
| 1 | 品牌名 | 正文一律 `Power BI`（带空格）；SQL 教程只写 SQL |
| 2 | **毛利率默认成交口径** | 数码 1.16% < 食品 21.75% < 家居 27.22% < 服饰 38.00% < 美妆 49.47% |
| 3 | 吊牌口径毛利率（仅讲定价逻辑时用） | 数码 12% / 食品 30% / 家居 35% / 服饰 45% / 美妆 55% |
| 4 | 数据规模 | **13,780 行**（维度 1,806 + 事实 11,974） |
| 5 | **金额取数** | 本教程**统一用 `fact_order_item.line_amount` / `line_profit`**（明细级，可与 DAX 对拍）；`fact_order.order_amount` 是它的表头汇总，二者不要同时求和 |
| 6 | **有效销售** | 必须 `status = '已完成'`（2,366 单 / 7,195,492.73 元）。已取消 591 + 退款 572 = 1,163 单金额仍在表里 |
| 7 | 客户等级 | 人数 241/149/83/27；折扣 0.02/0.08/0.15/0.20 |
| 8 | 术语 | 事实表、维度表、星型模型、主键、外键、窗口函数、执行计划、索引、事务 |

**数据局限（教程不出这类题）**：

- 无跨省下单（`dim_customer.region_id` 与 `fact_order.region_id` 同源）
- `unit_price` 恒等于 `list_price`，**无价格随时间变化**
- 无库存 / 渠道 / 退货明细表
- `dim_date` 止于 2025-12-31，超出后时间智能返回空白

## 八、关于练习题

每章末尾 3-5 题，**全部附完整答案 + 逐步解析 + 预期结果数字**。

用法建议：

1. 先自己写，在 MySQL 客户端跑
2. 卡住再看 Hint
3. 跑出数字后和「预期结果」对拍
4. 对不上就按「解析」一步步查

> 数字对不上**不是失败**，是最有价值的学习时刻 —— 通常意味着你对 JOIN 膨胀或筛选口径的理解还差一层。

## 九、常见故障速查

| 现象 | 原因 / 解决 |
|---|---|
| `Can't connect to MySQL server` | MySQL 没启动 → 打开小皮面板点启动，或手动 `mysqld.exe --console` |
| 中文显示为问号 | 连接字符集不是 utf8mb4；客户端加 `--default-character-set=utf8mb4` |
| 销售额虚高到 1,069 万 | 没过滤 `status='已完成'`（口径 6） |
| 客单价算成 9,192.99 | JOIN 后把订单头金额 `order_amount` 重复求和了（ch04） |
| 订单数莫名其妙变多 | JOIN 明细表后一行变多行，COUNT 要用 `COUNT(DISTINCT order_id)`（ch04） |
| NOT IN 子查询返回 0 行 | 子查询里藏着 NULL（ch08） |
| 查询很慢 | 没走索引 / 对索引列套了函数，看 ch10 |
| 改错数据想撤销 | 没开事务 → 以后先 `BEGIN`，确认无误再 `COMMIT`（ch09、ch12） |
