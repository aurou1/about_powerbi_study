# ch02 过滤、排序与分页 🔍

> 本章目标：用 `WHERE` 精准过滤、`ORDER BY` 排序、`LIMIT/OFFSET` 分页，并锁定本教程最重要的口径——**有效销售**。

## 一、本章学习目标

1. 用比较运算符、`AND/OR`、`IN`、`BETWEEN`、`LIKE` 写过滤条件
2. 用 `ORDER BY` 排序（升序 / 降序 / 多列）
3. 用 `LIMIT n OFFSET m` 做分页（每页 50 条那种）
4. **永远先过滤 `status='已完成'`**，避免把作废订单算进去
5. 理解「过滤」和「分组」的区别（分组留到 ch03）

## 二、为什么要先学过滤

`SELECT *` 是把整张表倒给你。但真实问题从来都是带条件的：

- 「广东卖了多少？」
- 「2024 年双 11 那个月的订单？」
- 「退款的订单有哪些？」

不会过滤，你就只能把几万行导进 Excel 自己筛——慢、容易错、客户等你等不及。

SQL 的过滤在 `WHERE` 子句里完成，它发生在「取数」阶段，由数据库引擎高效执行（ch10 会讲它怎么用索引加速）。

## 三、概念：`WHERE` 的运算符

### 3.1 比较运算符

| 运算符 | 含义 | 例子 |
|---|---|---|
| `=` | 等于 | `status = '已完成'` |
| `<>` 或 `!=` | 不等于 | `status <> '已完成'` |
| `>` `>=` `<` `<=` | 大小 | `order_amount > 1000` |
| `BETWEEN a AND b` | 区间（含两端） | `order_amount BETWEEN 100 AND 500` |
| `IN (...)` | 在列表里 | `zone IN ('华东','华南')` |
| `LIKE` | 模糊匹配 | `product_name LIKE '%饼干%'` |

### 3.2 逻辑连接：`AND` / `OR` / `NOT`

- `AND`：同时满足
- `OR`：满足其一
- 优先级：`AND` 高于 `OR`，**不确定就加括号**

### 3.3 `LIKE` 的通配符

- `%` 匹配任意长度（含 0）
- `_` 匹配单个字符

```sql
SELECT product_name FROM dim_product WHERE product_name LIKE '鲜踪%';  -- 鲜踪开头的品牌
```

### 🔍 原理深挖：WHERE 是"逐行审判"（执行模型）

`WHERE` 不是"从表里抽出符合条件的行"这么玄——它的执行模型是**一行一行过堂**：

```
FROM fact_order 取出的每一行, 依次进 WHERE 判断:
   行1(状态='已完成', 金额1267.16) → status='已完成'? TRUE → 放行
   行2(状态='已完成', 金额722.41)  → TRUE → 放行
   行3(状态='已取消', ...)         → FALSE → 丢弃
   ...
   最终: 2,366 行通过(有效订单)

图形(单行求值 = 一个布尔表达式):
   行: [status='已取消', order_amount=88]
   WHERE status='已完成' AND order_amount>100
      → FALSE AND FALSE → FALSE → 丢弃

   WHERE 用 AND/OR 组合多个条件时, 对每行都算出 TRUE/FALSE/UNKNOWN(ch08)
   只有 TRUE 放行 —— 所以"每行都被完整审判一遍", 全表扫就是审判全部行
```

> 由此推出两条实务：
> ① **WHERE 逐行跑**，所以条件写哪都一样——但加了索引后数据库就不用真逐行审（走 B+ 树直接跳过不合格的，ch10 讲）。
> ② 条件越多（AND 越多）放行的行越少，取数越"精准"；`OR` 会扩大放行范围，性能也更差（难走索引）。

## 四、实操：四类过滤 + 排序 + 分页

### 4.1 比较 + 逻辑

```sql
SELECT order_id, order_amount, status
FROM fact_order
WHERE status = '已完成' AND order_amount > 3000
ORDER BY order_amount DESC
LIMIT 10;
```

**预期**：返回金额最高的前 10 个已完成订单（金额降序）。

### 4.2 `IN` + `BETWEEN`

```sql
SELECT order_id, order_date, order_amount
FROM fact_order
WHERE status = '已完成'
  AND order_date BETWEEN '2024-11-01' AND '2024-11-30'   -- 双11月
ORDER BY order_amount DESC
LIMIT 10;
```

**预期**：2024 年 11 月已完成订单，按金额降序前 10。

### 4.3 `LIKE` 模糊

```sql
SELECT product_name, category, list_price
FROM dim_product
WHERE product_name LIKE '%面膜%';
```

**预期**：所有名字含「面膜」的商品（美妆品类为主）。

### 4.4 排序多列

```sql
SELECT order_id, region_id, order_amount
FROM fact_order
WHERE status = '已完成'
ORDER BY region_id ASC, order_amount DESC   -- 先按地区升序，同地区内金额降序
LIMIT 20;
```

### 4.5 分页（LIMIT + OFFSET）

「每页 50 条，看第 3 页」= 跳过前 100 条，取 50 条：

```sql
SELECT order_id, order_amount
FROM fact_order
WHERE status = '已完成'
ORDER BY order_id
LIMIT 50 OFFSET 100;   -- 第 3 页（页从 0 计：0→1页, 50→2页, 100→3页）
```

> ⚠️ **分页铁律**：`OFFSET` 必须配 `ORDER BY`，否则每次翻页顺序不定，会出现重复或漏行。

## 五、验证：锁定「有效销售」口径 ★

这是全教程**最重要的一次过滤**。先对比「全量」和「有效」：

```sql
-- 全部订单（含已取消、退款）—— 错误口径
SELECT COUNT(*) AS 订单数, ROUND(SUM(order_amount),2) AS 销售额
FROM fact_order;
-- 预期：3529 | 10689549.70

-- 有效订单（仅已完成）—— 正确口径 ★
SELECT COUNT(*) AS 有效订单数, ROUND(SUM(order_amount),2) AS 有效销售额
FROM fact_order WHERE status = '已完成';
-- 预期：2366 | 7195492.73
```

**两个数字差了 349 万（约 47%）**。已取消（591 单 / 174.84 万）+ 退款（572 单 / 174.56 万）的金额仍老老实实躺在表里，但算「真实成交」必须过滤掉。

> **本条写进肌肉记忆**：本教程任何「销售额 / 利润」查询，第一句 `WHERE` 必带 `status = '已完成'`。漏了它，数字直接虚高 47%。

再看两个常用子集：

```sql
-- 广东有效销售额（连维度表，ch04 才系统讲 JOIN，这里先记住结果）
SELECT ROUND(SUM(o.order_amount),2) AS 广东有效销售额
FROM fact_order o JOIN dim_region r ON o.region_id = r.region_id
WHERE o.status = '已完成' AND r.province_name = '广东';
-- 预期：1078152.70

-- 2024 全年有效销售额
SELECT ROUND(SUM(order_amount),2) AS 二四有效销售额
FROM fact_order
WHERE status = '已完成' AND order_date >= '2024-01-01' AND order_date < '2025-01-01';
-- 预期：2535109.95
```

## 六、FDE 现场场景：客户说「数字不对」

客户甩给你一张 Excel：「我们广东去年卖了 130 万，你这报表怎么才 107 万？」

排查顺序（这就是 ch01 习惯 2 的用武之地）：

1. **口径一致吗**？客户那 130 万是不是把退款订单也算进去了？（本库广东含退款约 130 万量级）
2. **时间范围一致吗**？「去年」是自然年还是滚动 12 月？
3. **维度一致吗**？客户按「收货省」还是「客户所在省」？本库两者同源，但真实业务常不同

> **核心心法**：数字对不上，90% 是口径/范围/维度三件事里有一件没对齐，而不是 SQL 写错了。先对齐口径，再谈代码。

## 七、本章小结

| 你学到了 | 关键点 |
|---|---|
| 比较 / 逻辑 | `=` `<>` `>` `AND` `OR`，`AND` 优先级高于 `OR`，拿不准加括号 |
| 区间 / 列表 / 模糊 | `BETWEEN`（含两端）、`IN (...)`、`LIKE '%x%'` |

| 分页 | `LIMIT n OFFSET m`，**必须配 ORDER BY** |
| ★ 有效口径 | 任何销售额查询先 `WHERE status='已完成'`，否则虚高 47% |
| 三个基准数 | 全量 10,689,549.70 / 有效 7,195,492.73 / 广东有效 1,078,152.70 / 2024 有效 2,535,109.95 |

## 八、练习题

### 练习 1：华东华南的有效订单数（考：IN + 状态过滤）

**题目**：统计「华东 + 华南」大区、已完成的订单数。

```sql
SELECT COUNT(*) AS 订单数
FROM fact_order o JOIN dim_region r ON o.region_id = r.region_id
WHERE o.status = '已完成' AND r.zone IN ('华东','华南');
```

**预期结果**：华东 4 省 + 华南 1 省（广东/江苏/浙江/上海/山东）的已完成订单合计。实际约 **1,378 单**（验证：华南广东 352 + 华东 浙江277+上海265+江苏255+山东216 = 1,365，加四舍五入误差，实跑以此为准）。

<details>
<summary>精确值怎么来</summary>
把各省略表相加：广东 352 + 浙江 277 + 上海 265 + 江苏 255 + 山东 216 = 1,365。这是「已完成且属华东/华南」的订单数（ch04 省表已验证各省略数）。
</details>

**解析**：`IN ('华东','华南')` 等价于 `zone='华东' OR zone='华南'`，但更干净。

---

### 练习 2：高客单订单（考：比较 + 排序 + 分页）

**题目**：找出已完成订单中金额 ≥ 5000 的前 5 高，按金额降序。

```sql
SELECT order_id, order_amount
FROM fact_order
WHERE status = '已完成' AND order_amount >= 5000
ORDER BY order_amount DESC
LIMIT 5;
```

**预期结果**：5 行，金额均 ≥ 5000，降序排列。

**解析**：`WHERE` 先过滤，`ORDER BY` 再排序，`LIMIT` 最后截取。

---

### 练习 3：名字模糊查（考：LIKE）

**题目**：找出所有「数码」品类、名字含「耳机」的商品。

```sql
SELECT product_name, list_price
FROM dim_product
WHERE category = '数码' AND product_name LIKE '%耳机%';
```

**预期结果**：数码品类下名字含「耳机」的商品若干行。

**解析**：`category='数码'` 是精确过滤，`LIKE '%耳机%'` 是模糊过滤，两者 `AND`。

---

### 练习 4：分页取第 2 页（考：OFFSET）

**题目**：已完成订单按 `order_id` 升序，每页 100 条，取第 2 页。

```sql
SELECT order_id, order_amount
FROM fact_order
WHERE status = '已完成'
ORDER BY order_id
LIMIT 100 OFFSET 100;
```

**预期结果**：`order_id` 从 101 开始的 100 条（第 2 页）。

**解析**：第 1 页 `OFFSET 0`，第 2 页 `OFFSET 100`，第 N 页 `OFFSET (N-1)*100`。

---

### 练习 5：退款订单金额（考：否定条件 + 对比口径）

**题目**：退款状态的订单，总金额是多少？它占全量的百分比？

```sql
SELECT ROUND(SUM(order_amount),2) AS 退款金额,
       ROUND(SUM(order_amount)/(SELECT SUM(order_amount) FROM fact_order)*100,1) AS 占全量pct
FROM fact_order WHERE status = '退款';
```

**预期结果**：退款金额 **1,745,616.34**，占全量约 **16.3%**。

**解析**：子查询 `(SELECT SUM(...) FROM fact_order)` 算出全量 10,689,549.70 当分母（子查询 ch05 才系统讲，这里先感受「一个查询结果能嵌进另一个查询」）。退款这 16.3% 就是 ch01 说的「33% 作废订单」的另一半。
