# ch06 窗口函数（上）：排序与排名 🏅

> 本章目标：用 `ROW_NUMBER` / `RANK` / `DENSE_RANK` 给每一行打名次，且**不打碎行**——这是 `GROUP BY` 做不到的。
> 学完你能算出「每个省内的客户销售排名」「全国 TOP 10 客户」。

---

## 一、本章学习目标

1. 说清**窗口函数和 GROUP BY 的本质区别**（窗口不折叠行）
2. 写 `函数() OVER (PARTITION BY ... ORDER BY ...)` 标准骨架
3. 用 `ROW_NUMBER` / `RANK` / `DENSE_RANK` 排名，并讲清三者差异
4. 用 `PARTITION BY` 在「每个省内 / 每个等级内」分别排名
5. 锁定：全国 TOP5 客户、省份排名（广东第 1 … 陕西第 10）

---

## 二、为什么 GROUP BY 不够用

ch03 的 `GROUP BY` 会把一组行**聚合成一行**。但「排名」需求是：**保留每一行，额外加一列名次**。

- 需求：「列出所有客户，并标注他在全国的消费排名」→ `GROUP BY` 会把 500 个客户压成 1 行，不行
- 需求：「每个省内，客户按消费排 1/2/3…」→ 要分组排名，还保留所有人

这正是**窗口函数**（Window Function）的领地。它「开一个窗口」看一组相关的行，算出一个值**贴回原行**，原行数量不变。

---

## 三、概念：窗口函数骨架

```sql
函数() OVER (
  [PARTITION BY 分组列]      -- 类似 GROUP BY，但不折叠
  [ORDER BY 排序列]          -- 窗口内按什么排
)
```

| 函数 | 作用 | 同名次处理 |
|---|---|---|
| `ROW_NUMBER()` | 1,2,3,4… 连续 | 即使并列也强制给不同号（谁 1 谁 2 看排序稳定性） |
| `RANK()` | 1,1,1,4… | 并列占同一名次，**跳过**后续名次 |
| `DENSE_RANK()` | 1,1,1,2… | 并列占同一名次，**不跳过** |

**三者差异（经典例子：3 人考 100 分，1 人 90 分）**：

| 函数 | 结果 |
|---|---|
| `ROW_NUMBER` | 1, 2, 3, 4（100 分三人被强行分开） |
| `RANK` | 1, 1, 1, **4**（并列第 1，下一名直接第 4） |
| `DENSE_RANK` | 1, 1, 1, **2**（并列第 1，下一名第 2） |

> 实战里：`ROW_NUMBER` 用来「取每组第 1 行」；`RANK` 用来「并列排名」（如比赛名次）；`DENSE_RANK` 用来「不跳号的等级」。

### 🔍 原理深挖：窗口函数在"哪一步"算？（SQL 执行顺序）

窗口函数和 `GROUP BY` 最大的区别是**求值时机**。SQL 逻辑执行顺序（ch08 会细讲）里：

```
FROM → WHERE → GROUP BY → HAVING → 窗口函数 → SELECT → ORDER BY → LIMIT
                                       ↑
                             窗口函数在这里算(WHERE/GROUP之后, SELECT之前)

这带来两个"反直觉"但必考的结论:

① WHERE 里不能过滤窗口结果
   SELECT *, ROW_NUMBER() OVER(...) AS rn FROM 订单 WHERE rn = 1
   → 报错! 因为 WHERE 先执行时 rn 还不存在(窗口函数在 WHERE 之后才算)
   → 正确姿势: 先算窗口, 再在外面套一层过滤(子查询/CTE, ch05 讲过)

② 窗口结果不能直接进 GROUP BY
   想让"每组第一名"参与聚合 → 同样要先子查询包一层

图形(一条完整 SELECT 的求值流水线):
   原始行 ──WHERE 过滤──▶ 幸存行 ──GROUP BY 分组──▶
        ──窗口函数逐行贴结果──▶ SELECT 挑列/算表达式 ──▶ ORDER BY ──▶ 输出
   ↑窗口函数能看到"过滤后、分组后"的所有行(所以叫窗口/框架)
```

## 四、实操：三种排名 + 分区排名

### 4.1 全国客户消费排名（RANK）

```sql
SELECT c.customer_name, c.tier,
       ROUND(SUM(oi.line_amount),2)                              AS 消费额,
       RANK() OVER (ORDER BY SUM(oi.line_amount) DESC)          AS 全国排名
FROM fact_order o
JOIN fact_order_item oi ON o.order_id = oi.order_id
JOIN dim_customer   c  ON o.customer_id = c.customer_id
WHERE o.status = '已完成'
GROUP BY c.customer_id
ORDER BY 全国排名
LIMIT 5;
```

**预期结果**：

| 客户 | 等级 | 消费额 | 全国排名 |
|---|---|---:|---:|
| 梁诗 | 钻石 | 70,022.89 | 1 |
| 唐宇伟 | 钻石 | 67,890.55 | 2 |
| 马晨博 | 钻石 | 66,012.90 | 3 |
| 吴涛 | 钻石 | 65,767.42 | 4 |
| 彭艳鑫 | 钻石 | 61,699.01 | 5 |

> 注意：`GROUP BY c.customer_id` 先把每人聚成一行（500 行），`RANK() OVER` 再在这 500 行上打分，**行数不变，只是多了名次列**。这就是窗口函数「不折叠」的含义。

### 4.2 省份销售排名（单分区）

```sql
SELECT r.province_name,
       ROUND(SUM(oi.line_amount),2)                        AS 销售额,
       RANK() OVER (ORDER BY SUM(oi.line_amount) DESC)    AS 排名
FROM fact_order o
JOIN fact_order_item oi ON o.order_id = oi.order_id
JOIN dim_region     r  ON o.region_id = r.region_id
WHERE o.status = '已完成'
GROUP BY r.province_name
ORDER BY 排名;
```

**预期结果**：广东 1 / 浙江 2 / 上海 3 / 江苏 4 / 北京 5 / 湖北 6 / 山东 7 / 四川 8 / 辽宁 9 / 陕西 10。

### 4.3 分区排名：每个等级内 TOP 3（PARTITION BY）

```sql
SELECT c.tier, c.customer_name,
       ROUND(SUM(oi.line_amount),2)                               AS 消费额,
       ROW_NUMBER() OVER (
         PARTITION BY c.tier
         ORDER BY SUM(oi.line_amount) DESC)                       AS 等级内序号
FROM fact_order o
JOIN fact_order_item oi ON o.order_id = oi.order_id
JOIN dim_customer   c  ON o.customer_id = c.customer_id
WHERE o.status = '已完成'
GROUP BY c.customer_id
QUALIFY ROW_NUMBER() OVER (PARTITION BY c.tier ORDER BY SUM(oi.line_amount) DESC) <= 3
ORDER BY c.tier, 等级内序号;
```

> ⚠️ `QUALIFY` 是 MySQL 8.0 支持的「窗口函数结果过滤」子句（类似 HAVING 但针对窗口函数）。若你的客户端不支持，可用子查询/CTE 包一层再 `WHERE 等级内序号 <= 3`。

**预期结果（每等级 TOP3）**：

| 等级 | 客户 | 消费额 | 等级内序号 |
|---|---|---:|---:|
| 普通 | 胡浩 | 41,188.96 | 1 |
| 普通 | 邓娟桂 | 36,035.69 | 2 |
| 普通 | 陈勇敏 | 24,957.71 | 3 |
| 钻石 | 梁诗 | 70,022.89 | 1 |
| 钻石 | 唐宇伟 | 67,890.55 | 2 |
| 钻石 | 马晨博 | 66,012.90 | 3 |

> `PARTITION BY c.tier` 让排名**在每个等级内重新从 1 开始**——普通客户和钻石客户各排各的，互不干扰。这是「分组内排名」的标准写法。

## 五、验证：省内客户排名（广东 TOP3）

```sql
SELECT c.customer_name,
       ROUND(SUM(oi.line_amount),2)                              AS 消费额,
       ROW_NUMBER() OVER (ORDER BY SUM(oi.line_amount) DESC)     AS 广东排名
FROM fact_order o
JOIN fact_order_item oi ON o.order_id = oi.order_id
JOIN dim_customer   c  ON o.customer_id = c.customer_id
JOIN dim_region     r  ON o.region_id = r.region_id
WHERE o.status = '已完成' AND r.province_name = '广东'
GROUP BY c.customer_id
ORDER BY 广东排名
LIMIT 3;
```

**预期结果**：吴涛 65,767.42（第 1）/ 黄桂 54,715.65（第 2）/ 赵娟霞 41,340.69（第 3）。

> 全国第 4 的吴涛，在广东却是第 1——说明「分区」改变排名基准。汇报排名时，**必须说清排名范围**（全国 / 省内 / 等级内），否则数字没有意义。

## 六、FDE 现场场景：客户要「我司在你们体系的排名」

客户：「我们公司今年在你们平台排第几？」

你一句 `RANK() OVER (PARTITION BY 行业 ORDER BY 采购额 DESC)` 给出「同行业排名」，再补一句全国排名。客户要的是**相对位置**，不是绝对金额——窗口函数就是干这个的。而且排名**不破坏原行**，你可以把名次、金额、等级并排展示在同一张表里交给客户。

## 七、本章小结

| 你学到了 | 关键点 |
|---|---|
| 窗口 vs GROUP BY | 窗口**不折叠行**，只加一列计算结果 |
| 骨架 | `函数() OVER (PARTITION BY .. ORDER BY ..)` |
| 三函数 | ROW_NUMBER（连续）/ RANK（跳号）/ DENSE_RANK（不跳号） |
| PARTITION BY | 在分组内分别排名（省内 / 等级内） |
| QUALIFY | 过滤窗口函数结果（MySQL 8.0） |
| 锁定数字 | 全国 TOP5 梁诗居首；省份 广东1…陕西10；广东 TOP3 吴涛居首 |

## 八、练习题

### 练习 1：全国 TOP5 排名（考：RANK 基础）

**题目**：跑 4.1，确认全国前 5 名。

**预期结果**：梁诗 1 / 唐宇伟 2 / 马晨博 3 / 吴涛 4 / 彭艳鑫 5，全为钻石。

**解析**：`GROUP BY` 聚合成 500 行，`RANK() OVER(ORDER BY 消费额 DESC)` 打分，行数不变。

---

### 练习 2：三函数差异（考：并列处理，概念题）

**题目**：有 4 个客户消费额分别为 70,022.89 / 70,022.89 / 66,012.90 / 61,699.01，分别用三种函数排名，结果各是？

**预期结果**：

| 函数 | 名次 |
|---|---|
| ROW_NUMBER | 1, 2, 3, 4（前两名被强拆） |
| RANK | 1, 1, 3, 4（并列第 1，第 3 名跳过 2） |
| DENSE_RANK | 1, 1, 2, 3（并列第 1，下一名第 2） |

**解析**：见本章第三节。选哪个取决于业务——比赛名次用 RANK，取每组第 1 行用 ROW_NUMBER。

---

### 练习 3：省份排名（考：单分区）

**题目**：跑 4.2，确认 10 省排名。

**预期结果**：广东 1 / 浙江 2 / 上海 3 / 江苏 4 / 北京 5 / 湖北 6 / 山东 7 / 四川 8 / 辽宁 9 / 陕西 10。

**解析**：分区列省略 = 全量一个窗口，按销售额降序排名。

---

### 练习 4：每等级 TOP3（考：PARTITION BY）

**题目**：用 `PARTITION BY tier` 取出每个等级消费 TOP3 客户。

**预期结果**：普通 胡浩/邓娟桂/陈勇敏；钻石 梁诗/唐宇伟/马晨博（见 4.3）。

**解析**：`PARTITION BY c.tier` 让排名在每个等级内重置为 1。

---

### 练习 5：广东 TOP3（考：多表 + 窗口）

**题目**：跑第五节，取广东客户消费 TOP3。

**预期结果**：吴涛 65,767.42 / 黄桂 54,715.65 / 赵娟霞 41,340.69。

**解析**：多表 JOIN 拿省份维度，窗口函数做省内排名，`LIMIT 3` 取前三。
